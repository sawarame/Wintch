## 1. 前提条件・ビルド・ユニットテスト実行

1. 依存関係なし・Apple 標準フレームワークのみでユニットテストが成功することを確認する：
   ```bash
   DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test
   ```
2. `.app` バンドルをビルドして起動する：
   ```bash
   ./scripts/build-app.sh
   open .build/Wintch.app
   ```
   - ※ ローカル再ビルド時は macOS の `cdhash` 変更により、アクセシビリティ権限／画面収録権限の再登録が必要になる場合がある。

## 2. 機能検証シナリオ

### シナリオ A: デフォルト（リスト型）でのゼロ画面収録権限動作（FR-001, FR-003, SC-003）
1. 新規状態（または設定リセット状態）で Wintch を起動し、メニューバーから「設定...」を開く。
2. 「通常スイッチャー（ホールド式）」の表示形式が初期値「リスト型」になっていること、かつ「画面収録権限」の案内や OS 許可ダイアログが一切表示されないことを確認する。
3. `Option + Tab` を押下し、従来の縦型リストで切り替わることを確認する。

### シナリオ B: キャプチャ表示型への切り替えと権限許可（FR-001, FR-008, FR-010, SC-004）
1. 設定画面で表示形式を「キャプチャ表示型」に変更する。
2. 画面収録権限が未許可の状態で、設定画面内に権限状態の案内と操作導線（「権限をリクエスト」／「システム設定を開く」）が表示されることを確認する。
3. まだ権限を許可しない状態で `Option + Tab` を押下し、クラッシュせずにキャプチャカード（アプリアイコンのプレースホルダー表示）とパネル上部の権限案内が表示され、そのままウィンドウ選択・切り替えができることを確認する。
4. システム設定 ＞ プライバシーとセキュリティ ＞ 画面収録 で Wintch を許可する（必要に応じてアプリを再起動）。

### シナリオ C: キャプチャ表示型での Alt+Tab 風操作と非同期更新（FR-004, FR-005, FR-006, FR-007, SC-001, SC-002）
1. 複数アプリ・複数ウィンドウ（例：ブラウザ複数枚、Finder、ターミナル、最小化ウィンドウ 1 枚）を開いた状態で `Option + Tab` を押下する。
2. パネルが遅延なく即座に表示され、複数行のカードグリッド（画面幅に応じて折り返し）に各ウィンドウのキャプチャサムネイル・アプリアイコン・アプリ名・タイトルが表示されることを確認する。
3. 最小化中のウィンドウや未取得ウィンドウでもアイコンプレースホルダーまたは直前キャッシュでカードが表示され、切り替え可能であることを確認する。
4. `Option` を押したまま `→` / `←` / `↑` / `↓` および `Tab` / `Shift + Tab` でグリッド上の選択カードが循環移動し、`Option` 解放またはクリックで対象ウィンドウへ切り替わることを確認する。
5. `Option` を押したまま `Q` を押し、選択中ウィンドウが閉じられてカードがグリッドから消え、選択位置が安全に補正されることを確認する。

### シナリオ D: 検索ランチャーとの分離およびリスト型への復帰（FR-002, FR-003, FR-012, SC-005）
1. 表示形式が「キャプチャ表示型」のまま `Option + Space`（検索ランチャー）を起動し、従来通りのリスト型（検索欄＋縦型リスト＋アプリ起動候補）で開くことを確認する。
2. 設定画面で表示形式を「リスト型」へ戻すと、設定画面の画面収録権限欄が非表示になり、次回の `Option + Tab` が即座に従来の縦型リストに戻ることを確認する。
