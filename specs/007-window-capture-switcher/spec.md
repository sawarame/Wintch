# 機能仕様書: 通常スイッチャーのウィンドウキャプチャ表示型および表示形式切替設定

**Feature Branch**: `007-window-capture-switcher`

**Created**: 2026-11-15

**Status**: Draft

**Input**: User description: "このアプリのスイッチャーでアプリのキャプチャも表示するようにしたいです。イメージとしてはWindowsのalt+tabで切り替えた時のような感じです。設定画面で既存のリスト型かキャプチャ表示型か選べるようにしたいです。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - キャプチャ表示型でのウィンドウ識別とグリッド切り替え (Priority: P1)

ユーザーは、通常スイッチャー（ホールド式）の表示形式を「キャプチャ表示型」に設定した状態でショートカットを押下した際、Windows の Alt+Tab のように各ウィンドウの実際の見た目（キャプチャプレビュー）とアプリアイコン・アプリ名・ウィンドウタイトルを並べたカードグリッドを即座に確認し、視覚的に目的のウィンドウを見極めて切り替えることができる。

**Why this priority**: 同一アプリで複数のウィンドウ（複数ブラウザウィンドウや複数の文書・エディタ等）を開いている場面では、文字情報だけのリストよりもウィンドウ内容の視覚的なプレビューが直感的な判別に直結するため、本機能の核心価値となる。

**Independent Test**: 画面収録権限を許可し、設定画面で表示形式を「キャプチャ表示型」に切り替えた状態で複数アプリのウィンドウを開き、通常スイッチャーを起動したとき、パネルが遅延なく表示されて各ウィンドウのキャプチャ付きカードが複数行グリッドで並ぶこと、順方向／逆方向トリガーキーおよび上下左右の矢印キーで選択カードが移動すること、修飾キー解放やクリックで対象ウィンドウに切り替わること、`Esc` でキャンセルできること、修飾キー + `Q` で選択カードが閉じられることを確認できる。

**Acceptance Scenarios**:

1. **Given** 通常スイッチャーの表示形式が「キャプチャ表示型」に設定されており、画面収録権限が許可されている状態で複数ウィンドウが開かれている, **When** ユーザーが通常スイッチャーのショートカット（修飾キー保持＋トリガーキー）を押下する, **Then** パネルが体感待ち時間なく画面中央に表示され、各ウィンドウが「キャプチャプレビュー・アプリアイコン・アプリ名・ウィンドウタイトル」を含むカードとして横並びの複数行グリッド（画面幅に応じて折り返し）に配置され、直近アクティブ順の2番目（または先頭）のカードが初期選択される。
2. **Given** キャプチャ表示型のスイッチャーパネルが開いている状態, **When** パネル表示直後に非同期で最新キャプチャの取得が完了する, **Then** 初期表示されていたアイコンプレースホルダーまたは直前キャッシュが最新のウィンドウキャプチャへ滑らかに差し替わり、選択状態やパネル位置は維持される。
3. **Given** キャプチャ表示型のグリッドに複数行のカードが表示されている状態, **When** ユーザーが修飾キーを保持したまま `→` / `←` / `↑` / `↓` 矢印キーまたはトリガーキー（`Shift` 併用で逆順）を押す, **Then** `→` / `←` およびトリガーキーでは直近アクティブ順のインデックスに沿って前後移動（先頭・末尾で循環）し、`↑` / `↓` では上下の行へ移動して選択カーソルが更新され、多数カードでスクロール領域がある場合は選択カードが見える位置へ自動追従する。
4. **Given** キャプチャ表示型で任意のカードが選択されている状態, **When** ユーザーが保持していた修飾キーを離す（または任意のカードをクリックする）, **Then** パネルが閉じ、選択されていたウィンドウが最前面へアクティブ化される（`Esc` キー押下時は切り替わらずパネルを閉じる）。
5. **Given** キャプチャ表示型で任意のカードが選択されている状態, **When** ユーザーがウィンドウ終了操作（スイッチャー修飾キー + `Q`）を入力する, **Then** 該当ウィンドウが閉じられ（同アプリ最後の1枚の場合はアプリを通常終了）、グリッドからそのカードが除外されて選択カーソルが安全に補正される。

### User Story 2 - 設定画面での表示形式切替とオプトイン権限管理 (Priority: P1)

ユーザーは、設定画面から通常スイッチャーの表示形式を「リスト型（デフォルト）」と「キャプチャ表示型」の間でいつでも自由に切り替えられ、プライバシー保護を重視する場合は画面収録権限を一切要求されない従来のリスト型を使い続け、視覚的なプレビューが欲しい場合のみオプトインでキャプチャ表示型を有効化できる。

**Why this priority**: 改定された憲章（最小権限およびオプトインの原則）に基づき、既存ユーザーの無権限運用を完全に守りつつ新機能への明確な切り替え導線と権限管理を提供することが不可欠であるため。

**Independent Test**: 初期状態の設定画面で「リスト型」が選択されており画面収録権限の要求が一切発生しないことを確認した後、「キャプチャ表示型」へ切り替えると即座に次回通常スイッチャーへ反映されること、画面収録権限が未許可なら権限案内とシステム設定への誘導が設定画面上に表示されること、検索ランチャーを起動した際は設定にかかわらず従来のリスト型のままであることを確認できる。

**Acceptance Scenarios**:

1. **Given** 初回起動時（設定未変更状態）で設定画面を開く, **When** 通常スイッチャー設定を確認する, **Then** 表示形式の初期値は「リスト型」が選択されており、画面収録権限の確認・要求ダイアログや権限誘導は一切表示されない。
2. **Given** 設定画面で通常スイッチャーの表示形式を「キャプチャ表示型」に変更した状態, **When** 画面収録権限が未許可である, **Then** 設定画面に「ウィンドウのキャプチャ表示には画面収録権限の許可が必要です」といった案内と権限許可／システム設定を開く導線が表示される（設定は保存され、許可後すぐ利用可能になる）。
3. **Given** 設定画面で「キャプチャ表示型」を選択し、通常スイッチャーが起動された後、再び設定画面で「リスト型」へ戻した状態, **When** 通常スイッチャーを起動する, **Then** 即座に従来の縦型リスト表示へ戻り、以降の動作でキャプチャ取得や画面収録権限の要求は行われず、保持されていた一時キャプチャキャッシュも破棄される。
4. **Given** 通常スイッチャーの表示形式が「キャプチャ表示型」に設定されている状態, **When** ユーザーが検索ランチャー（トグル式）のショートカットを押下する, **Then** 検索ランチャーは従来通りの検索欄付きリスト型（および起動候補リスト）として表示され、キャプチャ表示にはならない。

### User Story 3 - 権限未許可・取得不能ウィンドウに対する安全なフォールバックと安定動作 (Priority: P2)

ユーザーは、画面収録権限が未許可または後から取り消された状態や、最小化中・非表示・別操作スペースにあるウィンドウが含まれる状況であっても、スイッチャーがクラッシュしたり切り替え不能になったりすることなく、フォールバックカードと分かりやすい権限案内によって通常通り目的のウィンドウへ切り替えられる。

**Why this priority**: macOS の権限管理やウィンドウ状態（最小化・別スペース）の制約は実利用環境で日常的に発生するため、どのような状態でもコア機能である「素早いウィンドウ切り替え」が止まらない信頼性が求められるため。

**Independent Test**: 画面収録権限を未許可にしたまま「キャプチャ表示型」で通常スイッチャーを開き、クラッシュせずパネル上部に権限未許可の案内とシステム設定誘導が表示されつつ、すべてのウィンドウカードがアプリアイコンのプレースホルダー付きで選択・切り替え可能であることを確認できる。また最小化中や別スペースのウィンドウが含まれる状態でも、直前キャッシュまたはアイコンプレースホルダーが表示され切り替えに成功することを確認できる。

**Acceptance Scenarios**:

1. **Given** 表示形式が「キャプチャ表示型」で、画面収録権限が未許可またはシステム設定で後からオフにされた状態, **When** ユーザーが通常スイッチャーを起動する, **Then** パネル上部に画面収録権限が未許可である旨のコンパクトな案内（設定を開く導線を含む）が表示されつつ、各ウィンドウカードにはアプリアイコンとアプリ名・タイトルのプレースホルダーが描画され、通常通り選択と切り替え操作が完了できる。
2. **Given** 画面収録権限が許可されている状態で、最小化されているウィンドウまたは別操作スペースにあるウィンドウが存在する, **When** ユーザーがキャプチャ表示型の通常スイッチャーを開く, **Then** リアルタイムのキャプチャが取得できないウィンドウについては、直前の一時キャッシュが存在すればそれを、存在しなければアプリアイコンのプレースホルダーを表示し、ウィンドウ名とタイトルによる判別および切り替え操作を妨げない。
3. **Given** 複数のスペースやモニター構成で多数のウィンドウが開かれている状態, **When** ユーザーがキャプチャ表示型の通常スイッチャーを起動して短時間で開閉を繰り返す, **Then** 前回の非同期キャプチャ取得結果が新しい表示セッションや閉じた後の状態に誤って混入せず、一時キャッシュも上限内に収まって動作が重くならない。

---

### Edge Cases

- **ウィンドウが 1 件しか開かれていない場合**: 従来のリスト型と同様に 1 枚のカードとしてグリッドに表示され、最小幅を維持して見栄え良く中央配置される。
- **ウィンドウ数が非常に多い場合**: 画面幅に対する上限幅内で自動的に折り返して複数行グリッドを形成し、一定の最大高さを超える場合は縦スクロール可能となり、選択カードの移動に合わせて自動スクロール追従する。
- **縦長・横長など極端なアスペクト比のウィンドウ**: 各カードのプレビュー領域は統一された枠サイズに収められ、元のアスペクト比を保ったまま歪みやはみ出しなく表示されるため、グリッド全体の整列が崩れない。
- **グリッド最終行のカード枚数が他の行より少ない場合**: 最終行で `↓` キーを押した際に下の行へ折り返す／循環する挙動、および上の行の右端列から `↓` キーを押した際に最終行の末尾カードへ着地する挙動により、行き止まりなく操作できる。
- **キャプチャ非同期取得中にパネルが閉じられた・または対象ウィンドウが終了操作で閉じられた場合**: 完了した古いキャプチャ取得タスクの結果は現在の表示セッション識別子や有効ウィンドウ一覧と照合され、不要・陳腐化した画像は破棄される。
- **アクセシビリティ権限が未許可の場合**: 表示形式設定にかかわらず、従来通りアクセシビリティ権限が最優先の前提条件としてチェックされ、未許可時は権限誘導画面が表示される。また既存の権限誘導画面にある「画面収録権限は一切使用しない」旨の説明文は、新方針（リスト型では不要／キャプチャ表示型選択時のみ任意で使用）に沿った表現へ改定される。
- **プライバシーとメモリ保護**: 取得したキャプチャ画像はスイッチャー表示用の一時的なメモリキャッシュとしてのみ扱い、ストレージへの書き出し、ログ出力、外部送信は一切行わない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは設定画面に通常スイッチャーの表示形式を選択できる設定項目（「リスト型」／「キャプチャ表示型」）を提供し、選択内容を永続化しなければならない（MUST）。初期値（未設定時の既定値）は「リスト型」としなければならない（MUST）。
- **FR-002**: 検索ランチャーモードの表示形式は、通常スイッチャーの表示形式設定にかかわらず従来のリスト型を維持しなければならない（MUST）。
- **FR-003**: 通常スイッチャーの表示形式が「リスト型」に設定されている間、システムは画面収録権限の確認・許可要求・案内表示およびウィンドウキャプチャの取得処理を一切実行してはならない（MUST NOT）。
- **FR-004**: 通常スイッチャーの表示形式が「キャプチャ表示型」に設定されている場合、通常スイッチャー起動時に各対象ウィンドウを「キャプチャプレビュー表示領域・アプリアイコン・アプリ名・ウィンドウタイトル」で構成されたカードとして、画面幅に応じて自動折り返しする複数行グリッド（多数時は縦スクロール可能）で表示しなければならない（MUST）。
- **FR-005**: キャプチャ表示型の通常スイッチャーは、ショートカット押下から体感待ち時間ゼロで即座にパネルを表示しなければならず（MUST）、表示開始時点で最新のキャプチャが利用できないウィンドウには直前の一時キャッシュまたはアプリアイコンのプレースホルダーを即時表示したうえで、バックグラウンドで非同期取得した最新キャプチャへ順次差し替えなければならない（MUST）。
- **FR-006**: キャプチャ表示型のグリッド操作では、既存の順方向／逆方向トリガー操作および `←` / `→` キーによる直近アクティブ順の前後移動（循環あり）、ならびに `↑` / `↓` キーによる上下行間の移動（循環あり）を行えなければならず（MUST）、修飾キーの解放またはカードのクリックで選択ウィンドウへ切り替え、`Esc` キーで切り替わらずにキャンセルできなければならない（MUST）。
- **FR-007**: キャプチャ表示型でカード選択中にウィンドウ終了操作（スイッチャー修飾キー + `Q`）が実行された場合、リスト型と同様に選択中のウィンドウを閉じる（同アプリ最後の 1 枚ならアプリを通常終了する）処理を行い、グリッド一覧・選択位置・キャッシュを即時更新しなければならない（MUST）。
- **FR-008**: 「キャプチャ表示型」が選択または起動された状態で画面収録権限が未許可または取り消されている場合、システムはクラッシュや操作不能になってはならず（MUST NOT）、設定画面およびスイッチャーパネル上に権限未許可の案内とシステム設定を開く導線を表示しつつ、各カードにはアプリアイコン等のプレースホルダーを表示してウィンドウ切り替え操作を継続可能にしなければならない（MUST）。
- **FR-009**: 最小化中・非表示・別操作スペースに存在するなどリアルタイムの最新キャプチャが取得できないウィンドウについては、メモリ上の直前の一時キャッシュがあればそれを表示し、存在しない場合はアプリアイコンおよびウィンドウ情報によるフォールバックカードを表示しなければならない（MUST）。
- **FR-010**: 設定画面でユーザーが「キャプチャ表示型」を選択した際、画面収録権限が未許可であれば権限許可の手順・状態および権限要求／システム設定を開く操作導線を提示し、設定画面内のシステム権限セクションでも画面収録権限の現在状態を確認・操作できるようにしなければならない（MUST）。
- **FR-011**: 既存の権限誘導画面および関連案内テキストに含まれる「画面収録権限は一切使用しない」旨の記述は、「リスト型では不要であり、キャプチャ表示型を選択した場合のみ任意で使用する」という改定後の仕様と整合する表現へ更新しなければならない（MUST）。
- **FR-012**: 取得したウィンドウキャプチャ画像はメモリ上の一時的な表示キャッシュとしてのみ保持し、保持件数または容量に適切な上限を設けるとともに「リスト型」へ戻された際や閉じられたウィンドウ分は速やかに破棄しなければならず（MUST）、ディスクへの保存や外部送信は一切行ってはならない（MUST NOT）。
- **FR-013**: 非同期キャプチャ取得が完了した時点でパネルがすでに閉じられている、表示セッションが切り替わっている、または該当ウィンドウが一覧から消失している場合、システムはその取得結果を現在の UI へ反映してはならず安全に破棄しなければならない（MUST）。
- **FR-014**: キャプチャ取得および権限確認は OS 標準の公開機能のみを用いて実装し、非公開機能や外部ライブラリを使用してはならない（MUST NOT）。

### Key Entities

- **SwitcherDisplayStyle（スイッチャー表示形式）**: 通常スイッチャーの表示レイアウトを表す設定値。「リスト型（初期値）」と「キャプチャ表示型」の2種類を持ち、設定画面から変更・永続化される。
- **WindowCaptureThumbnail（ウィンドウキャプチャ画像）**: 特定ウィンドウに紐づく一時的な視覚プレビュー情報。対象ウィンドウ識別子、プレビュー画像データ（または未取得／取得不能状態）、および更新世代を保持し、メモリ内のみで管理される。
- **ScreenRecordingPermissionStatus（画面収録権限状態）**: システムにおける画面収録権限の現在状態（許可済み／未許可）。キャプチャ表示型が選択された場合のみ参照・案内対象となる。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 「キャプチャ表示型」で通常スイッチャーを起動した際、ショートカット入力から 100 ミリ秒以内にパネルおよび初期カード（プレースホルダーまたはキャッシュ）が画面に表示され、操作上の遅延を感じさせない。
- **SC-002**: 画面収録権限が許可されている環境において、現在表示中の操作スペース上にある通常ウィンドウの 100% に対し、スイッチャー表示開始から 500 ミリ秒以内に最新のキャプチャ画像がカードへ反映される。
- **SC-003**: 「リスト型」設定時および検索ランチャー利用時において、画面収録権限の確認・要求ダイアログやシステム誘導が発生する回数は 0 回であり、メモリ上のキャプチャキャッシュ保持件数も 0 件である。
- **SC-004**: 画面収録権限が未許可の状態で「キャプチャ表示型」を選択・起動した場合でも、100% のケースでプレースホルダーカードによるウィンドウ選択と切り替え操作が完了でき、クラッシュや操作不能状態が発生しない。
- **SC-005**: 設定画面で表示形式を「リスト型」と「キャプチャ表示型」の間で切り替えた直後、次回の通常スイッチャー起動から 100% 即座に選択した表示形式で起動する。

## Assumptions

- 通常スイッチャーにおける対象ウィンドウの収集・ノイズ除外・直近アクティブ順（MRU）および Z オーダーの並び順ルールは既存仕様（`001-window-switcher-mvp`）をそのまま継承する。
- アクセシビリティ権限が未許可の環境では従来通り通常スイッチャー・検索ランチャーともに起動せず権限誘導画面が表示されるため、画面収録権限はアクセシビリティ権限の前提を満たした上で「キャプチャ表示型」選択時にのみ効力を持つオプトイン権限として扱う。
- 画面収録権限の付与や取り消しは OS のシステム設定により制御され、macOS の仕様上、権限付与後に反映されるまでアプリ再起動が必要になる場合がある（権限案内テキストではその点も考慮して利用者に分かりやすく案内する）。
- 本機能の実現にあたり、[constitution.md](file:///Users/sawarame_yasushi/dev/Wintch/.specify/memory/constitution.md) は v2.0.0 へ改定され、原則1「最小権限およびオプトインの原則」の下で「リスト型での画面収録権限ゼロ」を維持しつつ「キャプチャ表示型でのオプトイン権限使用」が承認されている。
