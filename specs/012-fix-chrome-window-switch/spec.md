# 機能仕様書: 複数ウィンドウを持つブラウザ（Chrome 等）の正確な切り替えと一覧・キャプチャ整合性の確保

**Feature Branch**: `012-fix-chrome-window-switch`

**Created**: 2026-11-17

**Status**: Draft

**Input**: User description: "https://github.com/sawarame/Wintch/issues/13 Chrome で複数ウィンドウを開いたときに、スイッチャーやランチャーに表示されるが想定のウィンドウに移動せず別の Chrome ウィンドウに移動してしまう（キャプチャが取れない状態になっていることがある）原因を修正する。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 複数ウィンドウを開いている状態で、選択した対象ウィンドウへ確実に切り替える (Priority: P1)

ユーザーは、Google Chrome のように複数ウィンドウを同時に開いて使うアプリケーションにおいて、現在の操作スペース上・別の操作スペース上・同一位置／同一サイズ・フルスクリーンなどの配置に関わらず、通常スイッチャー（リスト型・キャプチャ表示型）および検索ランチャーから選択したウィンドウそのものへ確実に切り替わることを期待する。

**Why this priority**: 目的のウィンドウを選択したにもかかわらず別のウィンドウへ移動してしまう不具合は、ウィンドウ切り替えというアプリの中核体験を損なう最優先の修正課題であるため。

**Independent Test**: 複数の操作スペースや同一位置・同一サイズで Chrome の複数ウィンドウを開いた状態で、通常スイッチャーおよび検索ランチャーから各ウィンドウを選択し、すべてのケースで選択したタイトル・内容のウィンドウが最前面に表示されることで検証できる。

**Acceptance Scenarios**:

1. **Given** Chrome で複数のウィンドウが同じ操作スペースまたは別の操作スペースに開かれている状態, **When** ユーザーが通常スイッチャーまたは検索ランチャーから目的のウィンドウを選択して確定する, **Then** アプリケーション全体の直近ウィンドウではなく、選択したそのウィンドウ（必要なら対応する操作スペースへの移動を含む）が最前面にアクティブ化される。
2. **Given** フルスクリーンではない通常サイズで同じ位置・同じサイズの Chrome ウィンドウが複数の操作スペースに開かれている状態, **When** ユーザーが操作スペースを移動した後にスイッチャーまたはランチャーを開いて別スペース側のウィンドウを選択する, **Then** 別スペース側のウィンドウ参照が誤って消去されることなく保持され、選択時にその対象ウィンドウへ切り替わる。
3. **Given** 最小化されているか、または別操作スペースにあるため即座にサムネイルを取得できずプレースホルダー表示になっているウィンドウを選択した場合, **When** ユーザーがその項目を選択して確定する, **Then** キャプチャ有無に関わらず対象ウィンドウが正しく特定され、別のウィンドウへ誤遷移することなく目的のウィンドウへ切り替わる（最小化時は解除される）。

### User Story 2 - 内部補助ウィンドウに実ウィンドウの枠を奪われず、正しいウィンドウ実体とキャプチャを対応付ける (Priority: P1)

ユーザーは、Chrome などが内部的に保持している非表示の補助ウィンドウ（アドレスバー予測変換ポップアップや分離ツールバー等）によって実ウィンドウのタイトルや識別情報が奪われず、スイッチャーの一覧には本物のウィンドウ実体のみが対応付けられ、キャプチャ表示型では可能な限り正確なサムネイルが表示されることを期待する。

**Why this priority**: 実体のない内部補助ウィンドウに実ウィンドウのタイトルが割り当てられると、本物のウィンドウが一覧から弾かれて「キャプチャが取れない項目」が出現するだけでなく、選択時のウィンドウ特定も破綻するため。

**Independent Test**: 予測変換ポップアップ等の内部補助ウィンドウを保持する複数ウィンドウ構成のアプリを別スペースに置いた状態で、通常スイッチャー（キャプチャ表示型を含む）および検索ランチャーを開き、本物のウィンドウのみが対象として認識され、取得可能なウィンドウのサムネイルが正しく表示されることで検証できる。

**Acceptance Scenarios**:

1. **Given** Chrome 等がアドレスバー予測変換などの非表示内部補助ウィンドウを実ウィンドウより手前の重なり順で保持している状態, **When** 別操作スペースにある実ウィンドウを含めてウィンドウ一覧を収集する, **Then** 内部補助ウィンドウが実ウィンドウのタイトルを奪うことなく除外され、本物のウィンドウ実体が一覧に登録される。
2. **Given** 画面収録権限が許可されたキャプチャ表示型スイッチャーで、別スペースを含む複数の Chrome ウィンドウを表示する状態, **When** スイッチャーを起動する, **Then** 内部補助ウィンドウとの誤対応によって本物のウィンドウがキャプチャ不能項目へすり替わることなく、実ウィンドウに紐づくサムネイル（または取得不能時の安全なプレースホルダー）が適切に表示される。

### User Story 3 - タイトルに省略記号が含まれる場合や動的変化がある場合でも正確にウィンドウを識別・遷移する (Priority: P2)

ユーザーは、Web ページのタイトル自体に省略記号（「…」や「...」）が含まれていたり、長文タイトルがメニュー上で省略されていたり、あるいは一覧表示から確定までの間にページタイトルがわずかに変化した場合でも、スイッチャーやランチャーで選択したウィンドウへ確実に移動できることを期待する。

**Why this priority**: Web ブラウザでは長いタイトルや省略記号を含むタイトル、バックグラウンドでのタイトル更新が日常的に発生するため、タイトル文字列の単純一致のみに依存した遷移失敗を防ぐことで切り替え成功率を安定させる必要がある。

**Independent Test**: タイトル内に省略記号を含む長文ページやバックグラウンド更新を伴う複数ウィンドウを開いた状態で、別スペースにあるウィンドウをスイッチャーおよびランチャーから選択し、対象ウィンドウへ遷移できることで検証できる。

**Acceptance Scenarios**:

1. **Given** 元のウィンドウタイトル自体に「…」や「...」が含まれており、さらにアプリのメニュー上でも長文省略されている状態, **When** ウィンドウ一覧の照合や別スペースウィンドウへの切り替えを実行する, **Then** 元のタイトルと省略済みタイトルが正しく同一ウィンドウとして照合され、対象のウィンドウへ切り替えられる。
2. **Given** 一覧取得時から少し時間が経過してウィンドウのメニュー情報が古くなっている状態, **When** 別操作スペースにあるウィンドウを選択して確定する, **Then** 古い無効な参照をそのまま使って失敗するのではなく、最新のメニュー状態や有効な参照を用いて対象ウィンドウへ切り替える。
3. **Given** アプリケーションの「ウィンドウ」メニュー項目による遷移を実行した直後, **When** アプリケーションの前面化およびフォーカス確定を行う, **Then** メニューによる対象ウィンドウ切り替えを妨害・上書きして別のウィンドウを前面に出してしまうことなく、選択した対象ウィンドウにフォーカスが確定する。

---

### Edge Cases

- **同一位置・同一サイズで別スペースに複数ウィンドウがある場合**: 通常サイズ（最大化未満）のウィンドウであっても、別スペースに存在する別ウィンドウを「同一ウィンドウ内のタブ切り替えで消えた旧タブ」と誤認して削除・劣化させないこと。
- **内部補助ウィンドウが本体より手前の重なり順にある、または通常ウィンドウ相当のアスペクト比を持つ場合**: 非表示の予測変換ポップアップ等が通常の最小サイズ条件を満たしていても、本体実ウィンドウを差し置いて優先採用されないこと。
- **同じタイトルのウィンドウが複数開かれている場合**: 同じタイトルを持つ複数のウィンドウが現在スペースと別スペースに混在しても、片方の誤選択や重複消失が起きないこと。
- **タイトルが直前に変化した場合や非アクティブ状態からのメニュー操作が即座に反映されない場合**: メニュー項目参照が無効であれば最新状態を再取得し、別ウィンドウを誤って前面化しない順序・タイミングでフォーカス確定を行うこと。
- **別スペースへの切り替えアニメーションに時間がかかる場合**: 切り替えアニメーション途中で別ウィンドウへフォーカスを戻したり、古い空間情報で上書きしたりしないこと。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、同一アプリケーションで複数ウィンドウが開かれている状態（同一操作スペース・別操作スペース・最小化・フルスクリーンを含む）で選択された特定のウィンドウへ、意図しない別ウィンドウへ移動することなく確実にフォーカスおよび操作スペースを切り替えなければならない（MUST）。
- **FR-002**: システムは、同一位置・同一サイズの別ウィンドウが別の操作スペースに存在する場合に、操作スペースの移動によってそれを「閉じた旧タブ」と誤認して既存のウィンドウ実体参照を破棄してはならない（MUST NOT）。
- **FR-003**: システムは、別操作スペースのウィンドウを補完・対応付ける際、アプリケーションが保持する非表示の内部補助ウィンドウ（予測変換ポップアップや分離ツールバー等）よりも実ウィンドウらしい候補を優先し、内部補助ウィンドウが実ウィンドウの枠やタイトルを奪わないようにしなければならない（MUST）。
- **FR-004**: システムは、別操作スペース等に存在するウィンドウの切り替えにおいてメニュー項目を利用する場合、常に有効性・鮮度を保ったメニュー項目参照を取得して実行し、古い無効な参照のまま実行に失敗してアプリ全体の直近ウィンドウのみを前面化してはならない（MUST）。
- **FR-005**: システムは、個別ウィンドウへの切り替え（メニュー項目による遷移等）とアプリケーションの前面化を組み合わせる際、後続の前面化処理が個別ウィンドウ指定や操作スペース遷移を上書きして別ウィンドウを前面に出さないよう制御しなければならない（MUST）。
- **FR-006**: システムは、ウィンドウタイトル自体に省略記号（「…」や「...」）が含まれる場合や長文が中央／末尾省略される場合であっても、同一ウィンドウのタイトルとして正確に照合できなければならない（MUST）。
- **FR-007**: システムは、選択したウィンドウの切り替え先が存在しない・解決できないなどの異常時を除き、通常スイッチャー（リスト型・キャプチャ表示型）および検索ランチャーの双方で同一の信頼性でウィンドウ切り替えを実行しなければならない（MUST）。
- **FR-008**: システムは、画面収録権限やキャプチャ取得可否に関わらず、キャプチャが取得できない状態（プレースホルダー表示）のウィンドウであっても、正規に一覧表示されている対象であれば正しく切り替え動作を完遂できなければならない（MUST）。

### Key Entities

- **ウィンドウ実体参照（Cached Window Identity）**: 各ウィンドウの固有操作対象および表示用メタデータ（タイトル、位置・サイズ、最小化状態、直近アクティブ日時など）を保持する管理単位。
- **補助ウィンドウ候補（Backing / Auxiliary Window Candidate）**: アプリケーションが描画・入力補助（予測変換ポップアップ等）のために内部生成する非表示ウィンドウ。スイッチャー上の切り替え対象である実ウィンドウと区別される。
- **メニュー項目対応情報（Window Menu Mapping）**: アプリケーションの「ウィンドウ」メニューから取得される個別ウィンドウ切り替え用のタイトル・操作対象情報。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 同一位置・同一サイズや別操作スペースにまたがる複数の Chrome ウィンドウを開いた環境において、通常スイッチャー（リスト型・キャプチャ表示型）および検索ランチャーから選択した目的のウィンドウへ 100% 正確に切り替えられる。
- **SC-002**: Chrome が非表示の内部補助ウィンドウ（予測変換ポップアップ等）を保持している状態でも、別スペースにある実ウィンドウのタイトルが内部補助ウィンドウに奪われる件数が 0 件になる。
- **SC-003**: 元のタイトルに省略記号を含む長文ウィンドウやメニュー情報が更新された後のウィンドウに対しても、別ウィンドウへの誤遷移を発生させずに目的ウィンドウの照合・切り替えに成功する。
- **SC-004**: 既存のウィンドウ収集・フィルタリング・メニュー照合・アクティブ化・キャプチャに関する自動テストに加え、本仕様の再現条件を検証する新規テストがすべて 100% 合格し、パネル表示の体感遅延を発生させない。

## Assumptions

- 本仕様の改善対象は Google Chrome に限定せず、同様の複数ウィンドウ構造・メニュー構造を持つブラウザや一般的なアプリケーションにも汎用的に恩恵を与える設計とする（特定アプリの過剰な個別例外にはしない）。
- 別操作スペースや最小化によってシステム上どうしてもサムネイルが取得できない場合、プレースホルダー表示へフォールバックすること自体は既定仕様通り許容されるが、その状態であっても選択時のウィンドウ切り替え先は常に正確でなければならない。
- リスト型スイッチャーおよび検索ランチャーで画面収録権限を一切使用しない原則、および非公開機能を使用しない原則を完全に維持する。
