# Phase 1 データモデル・状態遷移設計: ランチャー初期フォーカス変更と検索プレースホルダー視認性改善

**Feature**: `008-launcher-ux-refinement` | **Date**: 2026-11-15

本機能では永続化データや新規エンティティの追加は行わず、既存の選択位置算出ルールと検索入力フィールドの視覚状態モデルを以下の通り更新・明確化する。

## 1. モード別初期選択ポリシー（`SwitcherSelection`）

### 状態遷移・算出規則

| 起動対象モード | ウィンドウ件数 `count` | 初期選択インデックス `initialIndex` | 選択される項目 |
|---|---|---|---|
| 通常スイッチャー（リスト型 / キャプチャ型） | `0` | `nil` | パネルを表示しない |
| 通常スイッチャー（リスト型 / キャプチャ型） | `1` | `0` | 1番目（唯一のウィンドウ） |
| 通常スイッチャー（リスト型 / キャプチャ型） | `>= 2` | `1` | 2番目（直前にアクティブだったウィンドウ） |
| 検索ランチャー | `0` | `nil` | パネルを表示しない |
| 検索ランチャー | `1` | `0` | 1番目（唯一のウィンドウ） |
| 検索ランチャー | `>= 2` | `0` | 1番目（最前面 / 最上位のウィンドウ） |

### 起動後操作による選択インデックス遷移（検索ランチャー時）

1. **起動直後**: `selectedIndex = 0`（1番目）
2. **「次へ」操作（`↓` / `Ctrl + N` / 通常順方向ショートカット）**:
   - `count >= 2` の場合: `0` → `1`（2番目）
   - `count == 1` の場合: `0` → `0`（変化なし）
3. **「前へ」操作（`↑` / `Ctrl + P` / 通常逆方向ショートカット）**:
   - `count >= 2` の場合: `0` → `count - 1`（末尾へ循環）
   - `count == 1` の場合: `0` → `0`（変化なし）
4. **検索文字入力 / 変更**:
   - 一致候補が 1 件以上ある場合: `selectedIndex = 0`
   - 全削除して空文字に戻した場合: 全ウィンドウ表示に戻り `selectedIndex = 0`

## 2. 検索入力フィールド視覚状態（`LauncherSearchField`）

| 入力状態 | プレースホルダー表示 | プレースホルダー文字色 | 入力文字色 | 備考 |
|---|---|---|---|---|
| 空文字 かつ IME 未確定文字なし | 表示（`"ウィンドウまたはアプリを検索..."`） | `NSColor.secondaryLabelColor`（15pt Regular） | — | ライト/ダーク・コントラスト設定へ自動追従 |
| 1文字以上入力済み または IME 未確定文字あり | 非表示（AppKit 標準制御） | — | `NSColor.labelColor`（15pt Regular） | IME 変換確定・候補選択の邪魔をしない |
