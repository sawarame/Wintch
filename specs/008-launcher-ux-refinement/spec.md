## User Scenarios & Testing *(mandatory)*

### User Story 1 - 検索ランチャー起動時に先頭項目（1番目）を初期選択する (Priority: P1)

ユーザーは、検索ランチャーを起動した際、一覧の最上部（1番目）のウィンドウに最初からフォーカスが当たっている状態で操作を開始できる。これにより、視覚的に「リストの先頭から順番に並んでいる・移動できる」という直感的な期待と一致し、下に移動して2番目以降を選ぶ操作や検索入力後の先頭フォーカスとも一貫した操作感を得られる。一方、通常スイッチャーでは直前のウィンドウへ素早く切り替える目的のため、従来通り2番目が初期選択される動作を維持する。

**Why this priority**: ランチャー起動直後の初期選択位置は、すべてのキーボードナビゲーション（下移動・上移動・`Enter` 確定）の起点であり、ユーザーの操作直感に直結する最も重要な改善点であるため。

**Independent Test**: 2枚以上のウィンドウを開いた状態で検索ランチャーを起動すると1番目の項目がハイライト選択されていること、そこから「次へ」操作を行うと2番目の項目へ移動すること、および通常スイッチャーを起動した場合は従来通り2番目の項目が初期選択されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 2件以上の通常ウィンドウが開かれている状態, **When** ユーザーが検索ランチャーの起動ショートカットを押してランチャーを開く, **Then** 一覧は直近アクティブ順で表示され、選択カーソルは2番目ではなく1番目（先頭）のウィンドウに置かれる。
2. **Given** 2件以上の通常ウィンドウが開かれており、検索ランチャーを起動した直後の状態（1番目が選択中）, **When** ユーザーが「次へ」移動操作（`↓`、`Ctrl + N`、または通常スイッチャーの順方向ショートカット）を行う, **Then** 選択カーソルは2番目のウィンドウへ移動する。
3. **Given** 2件以上の通常ウィンドウが開かれており、検索ランチャーを起動した直後の状態（1番目が選択中）, **When** ユーザーが「前へ」移動操作（`↑`、`Ctrl + P`、または通常スイッチャーの逆方向ショートカット）を行う, **Then** 選択カーソルは一覧の末尾のウィンドウへ循環移動する。
4. **Given** 2件以上の通常ウィンドウが開かれている状態, **When** ユーザーが通常スイッチャー（リスト型およびキャプチャ表示型のいずれか）を起動する, **Then** 従来通り2番目のウィンドウが初期選択され、通常スイッチャーの操作体験は変化しない。

### User Story 2 - 検索ランチャーのプレースホルダー文字列を明確に視認できる (Priority: P2)

ユーザーは、検索ランチャーを開いた直後の検索入力欄に表示される案内文言（「ウィンドウまたはアプリを検索...」）を、明るい背景・暗い背景のいずれのデスクトップ環境および外観モードでも目を凝らすことなくはっきりと読み取ることができ、入力可能な状態であることを一目で把握できる。

**Why this priority**: プレースホルダー文字は検索入力欄の役割と入力待機状態を伝える重要な手がかりであり、コントラスト不足による視認性低下はランチャー全体の品質と使いやすさを損なうため。

**Independent Test**: ライトモードおよびダークモードの環境で、明るい背景（白いウィンドウなど）および暗い背景の上で検索ランチャーを起動し、検索入力欄の「ウィンドウまたはアプリを検索...」の文字がアイコンや補助テキストと同程度に読みやすいコントラストで表示されること、かつ文字を入力した際は入力文字と明確に区別・非表示になることを確認できる。

**Acceptance Scenarios**:

1. **Given** ライトモードまたはダークモードのデスクトップ上で、背景が明るい・暗い任意のウィンドウ上にいる状態, **When** ユーザーが検索ランチャーを起動する, **Then** 検索入力欄のプレースホルダー「ウィンドウまたはアプリを検索...」が背景に埋もれず、虫眼鏡アイコンやウィンドウタイトルの補助文字と調和しつつ十分に判読できる明度・コントラストで表示される。
2. **Given** 検索ランチャーが開いており、検索入力欄にプレースホルダーが表示されている状態, **When** ユーザーが検索文字列（または日本語 IME の未確定文字列）を入力する, **Then** プレースホルダーは即座に消え、ユーザーが入力した検索文字列がより強いコントラストで明確に表示される。
3. **Given** 検索入力欄に文字列が入力されている状態, **When** ユーザーが入力文字列をすべて削除して空にする, **Then** 視認性が改善されたプレースホルダーが再び表示され、一覧が全件表示に戻り、選択カーソルは1番目（先頭）に位置する。

---

### Edge Cases

- **開いている通常ウィンドウが 1 件のみの場合**: 検索ランチャーを起動した際、従来通り1番目の唯一のウィンドウが初期選択される。通常スイッチャーでも同様に1番目が初期選択される。
- **開いている通常ウィンドウが 0 件の場合**: 検索ランチャーを起動しても、従来通り空のパネルは表示されない。
- **検索文字列を入力したあとにすべて削除して未入力状態へ戻した場合**: 一覧が初期の全件表示へ戻るとともに、選択カーソルは1番目（先頭）に維持され、プレースホルダーも改善後の視認性で再表示される。
- **システムの外観モード（ライト／ダーク）が切り替わった場合**: どちらの外観モードでもプレースホルダーの視認性が保たれ、文字色が背景と同化しない。
- **過去の仕様書との整合性**: `002-window-search-launcher` および `004-launcher-switcher-nav` の仕様書に記載されていた「検索ランチャー起動時の初期選択は2番目」という前提・記述は、本仕様に合わせて「1番目（先頭）」へ改定・整合化される。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、検索ランチャー起動時において、表示可能な通常ウィンドウが1件以上存在する場合、件数にかかわらず常に1番目（先頭）の項目を初期選択状態にしなければならない（MUST）。
- **FR-002**: システムは、通常スイッチャー起動時においては、リスト型・キャプチャ表示型のいずれが選択されているかにかかわらず従来の初期選択規則（1件の場合は1番目、2件以上の場合は2番目）をそのまま維持しなければならない（MUST）。
- **FR-003**: 検索ランチャーの検索入力欄に表示されるプレースホルダー「ウィンドウまたはアプリを検索...」は、半透明パネルおよび背後のウィンドウ輝度の影響を受けやすい環境（ライトモード・ダークモード双方）においてもユーザーが容易に判読できるコントラストを備えなければならない（MUST）。
- **FR-004**: プレースホルダーの視覚的表現は、検索入力欄左側の検索アイコンや一覧行の補助テキスト（ウィンドウタイトル等）と同等の視認性を確保しつつ、ユーザーが実際に入力した検索文字列とは明確に区別できる（未入力状態であることが直感的にわかる）トーンを維持しなければならない（MUST）。
- **FR-005**: 検索入力欄に文字が入力された際（日本語 IME による未確定入力を含む）、プレースホルダーは直ちに表示されなくなり、入力文字列の視認性・入力挙動に干渉してはならない（MUST NOT）。
- **FR-006**: 関連する既存の仕様書（`002-window-search-launcher` および `004-launcher-switcher-nav`）における「検索ランチャー起動時の初期選択は2番目」の記述を本仕様の内容（「常に1番目を初期選択」）へ整合化しなければならない（MUST）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 2件以上のウィンドウが開かれた環境で検索ランチャーを起動した際、100%のケースで1番目（先頭）の項目が初期選択される。
- **SC-002**: 2件以上のウィンドウが開かれた環境で通常スイッチャー（リスト型およびキャプチャ表示型）を起動した際、100%のケースで従来通り2番目の項目が初期選択される。
- **SC-003**: ライトモードおよびダークモード双方において、白い背景・暗い背景のいずれの上に検索ランチャーを表示した場合でも、プレースホルダー文字列「ウィンドウまたはアプリを検索...」の文字色とパネル背景色との間に視認上の十分なコントラスト差が確保され、一見して内容を判読できる。
- **SC-004**: 本変更により、既存の検索ランチャー機能（検索・ハイライト・選択移動・アプリ起動候補表示・ウィンドウ終了・IME 入力保護）および通常スイッチャー機能の動作に一切の退行が発生しない（既存機能テストの合格率 100%）。

## Assumptions

- 検索ランチャー起動時のリスト並び順自体は従来通り「直近アクティブ順（MRU）」であり、1番目の項目は直前まで最前面にあったウィンドウを指す（変更されるのは並び順ではなく初期選択位置のみ）。
- 検索ランチャーで1番目が初期選択された状態でそのまま確定操作（`Enter` 等）を行った場合は、1番目のウィンドウのアクティブ化およびパネル終了として正常に処理される。
- 検索ランチャー表示中の既存ナビゲーション（`↑` / `↓`、`Ctrl + N` / `Ctrl + P`、通常スイッチャーショートカット）および日本語 IME の優先制御はそのまま維持される。
