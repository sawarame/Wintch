# 機能仕様書: ランチャーからのアプリ起動安定化およびローカル開発版の識別名分離

**Feature Branch**: `011-fix-app-launch-dev-name`

**Created**: 2026-11-16

**Status**: Draft

**Input**: User description: "ランチャーから新しいアプリを起動するとアプリ起動直後にWintchが終了してしまう問題の修正。加えてローカル起動版のアプリ名を「Wintch_dev」等として、配布版とは区別できるようにする。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 検索ランチャーから新しいアプリケーションをクラッシュせず安定起動する (Priority: P1)

ユーザーは、Homebrew 等で配布された正式リリース版およびローカルビルド版のいずれの Wintch を使用している場合でも、検索ランチャーから未起動のアプリケーションを検索して起動した際、対象アプリが正常に立ち上がるとともに、Wintch 自身も終了・クラッシュすることなくメニューバー常駐を継続できることを期待する。

**Why this priority**: アプリ起動直後に Wintch 自体が終了してしまうと、その直後からショートカットによるウィンドウ切り替えや再度のランチャー呼び出しが一切不能になり、ランチャー機能の根幹が破綻するため最優先で解決する必要がある。

**Independent Test**: リリース構成でビルド・パッケージ化されたアプリ（およびローカル開発ビルド）を起動した状態で検索ランチャーを開き、未起動のアプリケーションを検索・確定して起動した際、対象アプリが起動して最前面に表示され、かつ数秒以上経過しても Wintch のプロセスおよびメニューバーアイコンが終了せず引き続きホットキー応答することを確認できる。

**Acceptance Scenarios**:

1. **Given** 配布版（リリースビルド）の Wintch が起動し、検索ランチャー上で未起動のアプリ（例: 計算機、テキストエディット等）が起動候補として選択されている状態, **When** ユーザーが確定操作（`Enter` キーまたは行クリック）で対象アプリを起動する, **Then** スイッチャーパネルが閉じて対象アプリが起動・前面表示され、Wintch 自身はクラッシュや予期せぬ終了を起こさず常駐を継続する。
2. **Given** ランチャーから新しいアプリを起動した直後の状態, **When** ユーザーが続けて通常スイッチャーまたは検索ランチャーのショートカットを押す, **Then** Wintch は即座に応答し、先ほど起動したアプリを含めた最新のウィンドウ一覧・検索機能を引き続き利用できる。
3. **Given** ランチャーから起動しようとしたアプリケーションが何らかの理由で起動に失敗した、あるいはすでに起動中だった状態, **When** 起動要求が完了する, **Then** 起動結果にかかわらず Wintch は安全に常駐を維持し、異常終了しない。

---

### User Story 2 - ローカル開発用ビルドを「Wintch_dev」として配布版と明確に区別する (Priority: P2)

開発者兼ユーザーは、ローカル環境でデバッグ・検証用にビルドして起動したアプリについて、アプリケーション名および UI 上の表示名が「Wintch_dev」として扱われ、同じ Mac 上にインストールされている配布版「Wintch」と一目で区別できることを期待する。一方、公式リリース向けにビルドされる配布版は従来通り「Wintch」の名称を維持する。

**Why this priority**: 配布版とローカル開発版がどちらも同じ「Wintch」という名前で表示されると、メニューバー、OS のプライバシー設定一覧、アクティビティモニタ、起動ファイル上でどちらを操作・検証しているのか判別できず、誤って配布版をテストしたり権限設定を取り違えたりするため。

**Independent Test**: ローカル開発用の既定ビルド手順でアプリケーションを生成・起動すると、アプリケーション名およびアプリ内の名称表示（「〜について」画面、設定画面タイトル、メニューバー項目など）が「Wintch_dev」となり、リリース用ビルド手順では従来通り「Wintch」として生成・表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** ローカル開発用のビルド手順（既定の開発ビルド）でアプリを生成した状態, **When** 生成されたアプリケーションバンドルを確認し起動する, **Then** アプリケーション名および表示名が「Wintch_dev」となっており、メニューバー、設定画面のタイトル、「〜について」画面、OS のプロセス一覧／設定一覧上で「Wintch_dev」として識別できる。
2. **Given** 同じ Mac 上に配布版（`Wintch`）とローカル開発版（`Wintch_dev`）の両方が配置されている状態, **When** 開発版を起動して OS のアクセシビリティ権限一覧やプロセス一覧を確認する, **Then** 配布版「Wintch」とは別の「Wintch_dev」として明瞭に区別して表示され、取り違えが発生しない。
3. **Given** 配布版（リリースビルド）をビルドする状態, **When** リリースビルド手順を実行する, **Then** 生成されるアプリケーション名・表示名・成果物名は従来通り「Wintch」のまま維持される。

---

### User Story 3 - 配布版とローカル開発版の共存時における動作と自己除外の整合性を保つ (Priority: P3)

ユーザーは、同じ Mac 上に配布版（`Wintch`）とローカル開発版（`Wintch_dev`）が共存している状態でも、それぞれの権限設定・ユーザー設定・アプリ起動候補の自己除外が破綻せず、開発版を起動している間は開発版自身の操作性が損なわれないことを期待する。

**Why this priority**: 名称やビルドを区別した際に、開発版を起動しているのに設定や権限が配布版と干渉したり、逆に自分自身をランチャーの起動候補として誤提示したりする副作用を防ぐため。

**Independent Test**: 配布版が導入済みの環境でローカル開発版 `Wintch_dev` を起動し、権限状態の確認、ショートカット設定の保存、および検索ランチャーでの自己検索（`"Wintch"` 入力時の候補表示）を行い、動作が競合・破綻しないことを確認できる。

**Acceptance Scenarios**:

1. **Given** ローカル開発版 `Wintch_dev` が起動している状態, **When** ユーザーが開発版の検索ランチャーでアプリ名を検索する, **Then** 実行中の開発版自身は誤って新規起動候補に含まれず、他のアプリケーションのみが起動候補として表示される。
2. **Given** 配布版 `Wintch` にすでにアクセシビリティ権限や設定が登録されている環境で、ローカル開発版 `Wintch_dev` を起動した状態, **When** 開発版の設定変更や権限確認を行う, **Then** 開発版は配布版とは独立した識別情報により、配布版側の登録・設定と干渉せずに運用できる。

---

### Edge Cases

- **アプリ起動完了の応答がメイン処理以外の実行コンテキストで返る場合**: アプリ起動要求の完了応答がどの実行スレッド・キューから通知された場合であっても、メインスレッド前提のアサーション違反による強制終了を一切発生させないこと。
- **すでに起動中（ウィンドウをすべて閉じてバックグラウンド待機中など）のアプリをランチャーから起動した場合**: 新規起動と同様に安全に前面化・起動でき、Wintch 自身が終了しないこと。
- **パッケージ化しない直接実行（開発ツール等からの単体実行）時の表示**: 開発用パッケージ（`.app`）から起動した場合だけでなく、バンドル情報が存在しない状態や開発用バンドルとして起動した場合でも、安全に適切な名称（または開発用表記）で画面表示できること。
- **ローカル環境でリリース相当のビルドを明示的に検証したい場合**: 開発用ビルドでは `Wintch_dev` になる一方、リリースビルド指定時には正規名称 `Wintch` に切り替わり、自動リリースの成果物確認にも支障がないこと。
- **アクセシビリティ権限の再登録について**: ローカル開発版を独立した識別名・識別子とした場合、初回起動時のみ開発版 `Wintch_dev` としての権限許可が必要となるが、一度許可すれば配布版の再インストールや起動によって上書き・失効しにくくなること。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、検索ランチャーからアプリケーションを起動（新規起動またはバックグラウンドアプリの前面化）する際、起動要求および起動完了に伴う内部処理の実行コンテキストの不一致によってアプリ自身が強制終了・クラッシュしてはならない（MUST NOT）。
- **FR-002**: システムは、リリースビルドおよびデバッグビルドを含むすべてのビルド構成・配布環境において、ランチャーからのアプリ起動後にメニューバー常駐およびグローバルショートカット監視を継続しなければならない（MUST）。
- **FR-003**: システムは、ローカル開発用ビルド（既定のデバッグビルド等）としてパッケージ化・起動されたアプリケーションの名称・表示名を、配布版（`Wintch`）と明確に区別できる開発用名称（`Wintch_dev`）として構成・表示しなければならない（MUST）。
- **FR-004**: 開発用ビルドの起動時は、OS が参照するアプリ名・アプリケーションバンドル名だけでなく、アプリ内のユーザー向け表示箇所（メニュー項目、「〜について」画面、設定画面および権限確認画面のウィンドウタイトル等）においても一貫して開発用名称（`Wintch_dev`）が反映されなければならない（MUST）。
- **FR-005**: システムは、ローカル開発用ビルドのアプリ識別子を配布版の正規識別子から分離し、同一端末上で配布版（`Wintch`）と開発版（`Wintch_dev`）を共存させた際に OS の権限登録や設定管理が相互に干渉・上書きされないようにしなければならない（MUST）。
- **FR-006**: システムは、リリースビルド（公式配布および Homebrew 配布向けのビルド）においては、アプリケーション名・表示名・識別子・出力バンドル名を従来通り正規の `Wintch` として維持しなければならない（MUST）。
- **FR-007**: システムは、開発用ビルドでの起動中であっても、画面収録権限を新たに要求したり非公開機能を使用したりしてはならない（MUST NOT）。

### Key Entities

- **アプリケーション実行形態（Release / Development Identity）**: ビルド種別に応じて決まるアプリケーションの名称・表示名・識別情報の組。配布版（`Wintch`）とローカル開発版（`Wintch_dev`）を識別し、OS 表示・UI 表示・権限・設定の境界を規定する。
- **アプリ起動要求（App Launch Request）**: 検索ランチャーでユーザーが起動候補を確定した際に OS へ発行されるアプリケーション起動指示。起動完了のタイミングや実行コンテキストに依存せず常駐プロセスを安全に維持する前提を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: リリースビルド環境でパッケージ化されたアプリから検索ランチャー経由でアプリケーションを起動した際、起動直後の強制終了・クラッシュ発生率が 0% である。
- **SC-002**: ランチャーからのアプリ起動直後、100% のケースで対象アプリケーションが起動すると同時に、Wintch 本体が直後のショートカット入力に対して即座（体感遅延なし）に応答し続ける。
- **SC-003**: ローカル開発用ビルドを起動した際、生成バンドル名、OS のプロセス一覧／プライバシー権限一覧、メニューバー項目、設定画面タイトル、および「〜について」画面のすべてにおいて、100% 一貫して「Wintch_dev」として識別でき、配布版「Wintch」と区別できる。
- **SC-004**: リリースビルドを実行した場合、生成されるアプリケーション成果物およびアプリ内表示の 100% が正規の「Wintch」として生成され、既存の配布フローとの互換性が完全に保たれる。
- **SC-005**: 修正および識別名分離の適用後も、既存の自動ユニットテストが 100% 合格する。

## Assumptions

- ローカル開発用ビルドの識別名は、ご要望の例示通り **`Wintch_dev`** を標準値として採用する。
- 開発版と配布版を確実に区別し、さらに macOS のアクセシビリティ権限やアプリ設定が配布版と衝突・上書きされないようにするため、ローカル開発用ビルドでは表示名・バンドル名だけでなくアプリ識別子（およびそれに伴う設定管理領域）も開発用として分離する前提とする。
- ローカル開発版と配布版の識別切り替えは、既定の開発用ビルド（デバッグビルド）を `Wintch_dev`、リリース用ビルドを `Wintch` とすることを基本とし、既存のリリース自動化フローに影響を与えない。
- 検索ランチャーにおけるアプリ起動機能自体の既存仕様（検索順序、表示形式、起動時のパネルクローズ挙動など）は `006-launcher-app-launch` および `010-launcher-without-windows` の定義をそのまま維持する。
