# 機能仕様書: メニューバーから開く設定画面等の最前面表示修正

**Feature Branch**: `015-fix-settings-frontmost`

**Created**: 2026-11-17

**Status**: Draft

**Related Issue**: [#18](https://github.com/sawarame/Wintch/issues/18)

**Input**: User description: "メニューバーのアイコンから設定画面を表示させても、設定画面のウィンドウが他のウィンドウにかくれて表示されてない。設定画面を開いた際は、設定画面のウィンドウを一番手前に表示させるようにする。（Issue #18）"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 他アプリ作業中でもメニューバーから設定画面を一番手前に開ける (Priority: P1)

ユーザーは、ブラウザやエディタ・ターミナルなど別のアプリケーションを前面で操作している最中に、メニューバーの常駐アイコンから「設定を開く...」を選択した際、設定画面が他のウィンドウの背後に隠れることなく画面の一番手前に表示され、即座に設定内容の確認やショートカット変更・キーボード操作を行えることを期待する。

**Why this priority**: Issue #18 で報告された中心的な不具合であり、メニューバーから設定画面を開いても他ウィンドウの背後に隠れて見えていない状態では、ユーザーがショートカット変更や設定確認を行えず設定機能そのものに到達できないため。

**Independent Test**: 任意の他アプリケーションのウィンドウを画面前面に大きく表示した状態で、メニューバーの Wintch アイコンから「設定を開く...」を選択し、設定画面が他アプリウィンドウより手前に表示され、かつ入力・ショートカット登録・閉じる操作が即座に受け付けられることで検証できる。

**Acceptance Scenarios**:

1. **Given** 他アプリケーションがアクティブで画面上にウィンドウが大きく表示されている状態, **When** メニューバーアイコンから「設定を開く...」を選択する, **Then** 設定画面が他アプリケーションのウィンドウより一番手前に表示され、キーボード入力やショートカット記録が可能なアクティブ状態になる。
2. **Given** 設定画面を一度開いた後、ユーザーが別アプリケーションをクリックして設定画面が他ウィンドウの背後に回った（または設定画面を閉じた）状態, **When** 再度メニューバーアイコンから「設定を開く...」を選択する, **Then** 設定画面が再び現在の画面中央・一番手前に表示される。
3. **Given** 設定画面が最前面に表示された状態, **When** ユーザーが設定画面内のボタンから「システム設定」を開く操作を行う、または別アプリケーションのウィンドウをクリックする, **Then** 「システム設定」やクリックした別アプリケーションが正常に手前へ切り替わり、設定画面がいつまでも他アプリの邪魔をし続けない。

---

### User Story 2 - 「Wintchについて」画面および権限誘導画面も同様に一番手前に表示される (Priority: P2)

ユーザーは、設定画面と同様にメニューバーや起動時案内から開く「Wintchについて」画面や「アクセシビリティ権限誘導」画面についても、他のアプリケーションの背後に隠れることなく確実に一番手前に表示され、内容の確認や権限設定への誘導操作を迷わず行えることを期待する。

**Why this priority**: メニューバーやバックグラウンド状態から開く他の標準ウィンドウも設定画面と同一の仕組みで表示されており、同様に他ウィンドウの裏へ隠れる事象を防ぐことでアプリ全体の案内体験を一貫して担保するため。

**Independent Test**: 他アプリケーションが前面でアクティブな状態で、メニューバーから「Wintchについて」または「アクセシビリティ権限が必要です...」を選択した際、該当ウィンドウが他アプリケーションより手前に表示されることで検証できる。

**Acceptance Scenarios**:

1. **Given** 他アプリケーションがアクティブで画面上にウィンドウが表示されている状態, **When** メニューバーアイコンから「Wintchについて」を選択する, **Then** 「Wintchについて」画面が他アプリケーションのウィンドウより一番手前に表示される。
2. **Given** アクセシビリティ権限が未許可で他アプリケーションがアクティブな状態, **When** 初回起動時の自動表示またはメニューバーの案内項目から権限誘導画面を開く, **Then** 権限誘導画面が他アプリケーションのウィンドウより一番手前に表示され、システム設定への誘導ボタンをすぐに操作できる。

---

### User Story 3 - 常駐アプリとしての非侵襲性（Dock 非表示・既存動作の維持）を保つ (Priority: P2)

ユーザーは、設定画面等を開く際にも Wintch が従来通り Dock アイコンを増やさないメニューバー常駐ユーティリティとして振る舞い、開いた設定画面を閉じた後もバックグラウンドでのウィンドウ切り替え機能が妨げられないことを期待する。

**Why this priority**: 常駐ユーティリティとして Dock や作業スペースを散らかさないことが Wintch の基本設計（シンプルさ・最小限の振る舞い）であり、最前面表示修正によって余計な Dock アイコン点滅等を生じさせないため。

**Independent Test**: 設定画面の開閉前後で Dock にアプリアイコンが追加出現しないこと、および設定画面を閉じた後に通常スイッチャー・検索ランチャーが従来通り動作することで検証できる。

**Acceptance Scenarios**:

1. **Given** Dock に Wintch のアイコンが表示されていない常駐状態, **When** メニューバーから設定画面や「Wintchについて」画面を開閉する, **Then** 開閉の前後を通じて Dock に新たなアプリアイコンは追加されない。

---

### Edge Cases

- **複数の仮想デスクトップ（操作スペース）を跨いで操作する場合**: スペース 1 で設定画面を開いたまま（閉じずに）スペース 2 へ移動し、メニューバーから再度「設定を開く...」を選択した場合でも、現在ユーザーが操作しているスペース上の画面に最前面で表示されること。
- **マルチディスプレイ環境で操作する場合**: 複数ディスプレイ接続時に設定画面を開く際も、他アプリケーションのウィンドウに隠れず手前に表示されること。
- **設定画面を開いた直後の連続操作**: メニューバーから設定画面を開いてすぐ閉じるボタンまたは閉じるショートカットを押した場合でも、正しくアクティブなウィンドウとして閉じた上で元の常駐動作へ戻ること。
- **最小化状態等からの再表示**: ウィンドウが非表示または最小化に準ずる状態にあるときに再度開く操作を行っても、確実に復帰して最前面に表示されること。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、他アプリケーションがアクティブな状態でメニューバーから「設定を開く...」が実行された場合、設定画面を他のすべての通常アプリケーションウィンドウより手前（一番手前）に表示し、即座に入力・操作可能なアクティブ状態にしなければならない（MUST）。
- **FR-002**: システムは、すでに設定画面が開かれて他ウィンドウの背後に回っている状態や閉じられた状態から再度「設定を開く...」が実行された場合でも、設定画面を確実に一番手前へ再表示しフォーカスを与えなければならない（MUST）。
- **FR-003**: システムは、設定画面と同様にメニューバーやバックグラウンド状態から表示される「Wintchについて」画面および「アクセシビリティ権限誘導」画面についても、共通の前面表示振る舞いを適用し他アプリケーションウィンドウより手前に表示しなければならない（MUST）。
- **FR-004**: システムは、設定画面・各種標準ウィンドウを最前面へ表示した後も常時最前面固定（他アプリの上に覆い被さり続ける状態）にはせず、ユーザーが設定画面内の「システム設定を開く」操作や他アプリケーションのクリックを行った場合は通常通り対象アプリを手前へ切り替えられるようにしなければならない（MUST）。
- **FR-005**: システムは、設定画面や各種標準ウィンドウが開かれたまま別の操作スペースへ移動した後に再度メニューバーから開く操作が行われた場合、現在表示中の操作スペース上へウィンドウを呼び出して最前面に表示しなければならない（MUST）。
- **FR-006**: システムは、設定画面等の開閉に際してメニューバー常駐アプリとしての振る舞い（Dock アイコンを増やさない動作、ならびに画面収録権限を要求しない最小権限原則）を維持しなければならない（MUST）。

### Key Entities *(include if feature involves data)*

- **常駐アプリ起点ウィンドウ（Settings / About / PermissionGuide）**: メニューバーや常駐ライフサイクルから呼び出される標準操作ウィンドウ群。呼び出し時には即時アクティブ化・最前面表示・現在スペースへの表示が求められ、表示後は通常ウィンドウとして他アプリと重なり順を共有する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 他アプリケーションが画面前面にある状態でメニューバーから「設定を開く...」を実行した際、100% の試行において設定画面が他アプリケーションのウィンドウより手前に表示され、追加クリックなしでキーボード操作を受け付ける状態になる。
- **SC-002**: 設定画面が背後に回った状態・別操作スペースにある状態・一度閉じた状態のいずれから「設定を開く...」を再実行した場合でも、100% の試行で現在の操作スペース上の最前面へ復帰表示される。
- **SC-003**: 「Wintchについて」画面および「アクセシビリティ権限誘導」画面についても、他アプリケーションが前面にある状態からの呼び出しで 100% 一番手前に表示される。
- **SC-004**: 設定画面から「システム設定」を開いた際または他アプリケーションをクリックした際に、設定画面が「システム設定」や他アプリケーションの表示を妨げて覆い隠し続ける事象が 0 回である。
- **SC-005**: 設定画面等の表示・閉鎖を通じて Dock へのアイコン追加出現が 0 回であり、既存のスイッチャー／ランチャー機能および自動テストに退行が発生しない。

## Assumptions

- 本仕様は Issue #18 の確認コメントで提示した暫定方針（対象 3 ウィンドウへの共通適用、Dock アイコン非表示の常駐ポリシー維持＋開いた瞬間の確実な最前面・アクティブ表示、現在操作スペースへの呼び出し）に基づく。
- スイッチャーパネル自体のフローティング表示制御は既存仕様で完結しているため、本仕様の変更対象はメニューバー／常駐状態から開かれる標準ウィンドウ群（設定画面・「Wintchについて」画面・権限誘導画面）とする。
