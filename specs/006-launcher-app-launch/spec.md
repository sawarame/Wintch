# 機能仕様書: 検索ランチャーでの既存ウィンドウ 0 件時のアプリ新規起動候補表示

**Feature Branch**: `006-launcher-app-launch`

**Created**: 2026-11-15

**Status**: Draft

**Input**: User description: "このアプリのランチャーを立ち上げて、検索で既存のウィンドウがなかった場合は、新しくアプリを立ち上げるためのアプリ候補を出してもらうことはできますか。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 既存ウィンドウが一致しないときにアプリ起動候補から起動する (Priority: P1)

ユーザーは、検索ランチャーを起動して目的のアプリ名を入力した際、そのアプリのウィンドウが 1 枚も開かれていなくても、別のランチャーや Finder へ切り替えることなく、そのまま表示されたアプリ起動候補から選択・確定して目的のアプリケーションを新規起動（またはウィンドウ再表示・前面化）できる。

**Why this priority**: 検索ランチャーでウィンドウ切り替えとアプリ起動の導線が途切れず一気通貫で完結することこそが、本機能の中核的な提供価値であるため。

**Independent Test**: 対象アプリ（例：計算機など）のウィンドウが開かれていない状態で検索ランチャーを起動し、キーワード入力によって既存ウィンドウ一致件数が 0 件となった際にアプリ起動候補リスト（起動目的のセクション案内・アイコン・アプリ名・新規起動バッジ）が表示され、先頭候補が自動選択された状態で `Enter` キーまたはクリックにより該当アプリが起動しパネルが閉じることを確認できる。

**Acceptance Scenarios**:

1. **Given** 検索ランチャーが開いており、検索対象のアプリケーションのウィンドウが 1 枚も開かれていない状態, **When** ユーザーがそのアプリ名または略称（例：`"cal"`）を検索欄に入力して既存ウィンドウの一致件数が 0 件になる, **Then** パネルは閉じずに維持され、「一致するウィンドウがないため、アプリを起動」という案内とともに一致したアプリ起動候補がスコア順に表示され、先頭項目（1番目）が選択状態になる。
2. **Given** 既存ウィンドウが 1 件以上一致する検索キーワードが入力されている状態, **When** ユーザーが検索結果を確認する, **Then** 既存のウィンドウ切り替え候補のみが表示され、アプリ起動候補は混在表示されない。
3. **Given** アプリ起動候補が複数件表示されている状態, **When** ユーザーが `↑` / `↓` 矢印キー、`Ctrl + N` / `Ctrl + P`、または通常スイッチャーのショートカット（順方向および `Shift` 併用の逆方向）を押す, **Then** 選択カーソルがアプリ起動候補リスト内で上下に循環移動し、その際の修飾キー解放によってもパネルは勝手に閉じない。
4. **Given** アプリ起動候補のいずれかが選択されている状態, **When** ユーザーが `Enter` キーを押す（または該当行をクリックする）, **Then** ランチャーパネルが閉じ、選択されていたアプリケーションが起動して最前面に表示される。
5. **Given** 検索文字列によってアプリ起動候補が表示されている状態, **When** ユーザーが検索文字列を編集・削除して既存ウィンドウが再び 1 件以上一致する状態（または空欄）に戻る, **Then** アプリ起動候補表示は解除され、即座に既存ウィンドウ一覧の表示へ戻る。

### User Story 2 - 日本語名・英語名の双方によるアプリ検索とハイライト表示 (Priority: P2)

ユーザーは、日本語環境で英語名とは異なる表示名を持つ標準アプリケーション（例：「メモ」と「Notes」、「システム設定」と「System Settings」）についても、日本語名・英語名どちらの入力でも迷わず見つけ出し、どの文字が一致したかをハイライトで確認して起動できる。

**Why this priority**: macOS の日本語環境ではシステム標準アプリがローカライズ名と英語元の名称の双方で認識されることが多く、どちらの入力習慣でもストレスなく検索できることが実用性を大きく左右するため。

**Independent Test**: ローカライズ名と英語別名の双方を持つアプリケーションが候補に含まれる状態で検索ランチャーを開き、英語表記および日本語表記のキーワードを入力した際、いずれの入力でも対象アプリが候補に現れて一致文字箇所が太字・ハイライト表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** ローカライズされた表示名（例：「メモ」）と英語由来の別名（例：「Notes」）が異なるアプリケーションが端末にインストールされている状態, **When** ユーザーが検索欄に英語キーワード（例：`"note"`）または日本語キーワード（例：`"メモ"`）を入力し既存ウィンドウが 0 件となる, **Then** 双方のキーワードいずれでも対象アプリが起動候補に表示され、別名が併記された上で一致した文字箇所が太字・ハイライト表示される。
2. **Given** 複数語をスペースで区切ったキーワード（例：`"vis code"` や `"sys set"`）が入力された状態, **When** 既存ウィンドウが 0 件となる, **Then** スペース区切り AND 条件のファジー検索により、表示名・別名を横断して一致するアプリのみがスコア順（同点時は名称昇順）で候補表示される。

### User Story 3 - 境界状態・重複除外・パネル安定性および既存操作との安全な共存 (Priority: P2)

ユーザーは、既存ウィンドウも起動可能なアプリもどちらも一致しない場合や、ランチャー起動中にウィンドウを閉じて 0 件になった場合、あるいはアプリ候補表示中に誤って終了ショートカットを押した場合でも、パネルの位置や操作の一貫性が崩れず安全に作業を継続できる。

**Why this priority**: アプリ候補が一切見つからない状態や、ウィンドウクローズ機能・パネルレイアウト制御など既存ランチャー機能との境界で不整合や誤操作が起きないことが、日常的な信頼性に直結するため。

**Independent Test**: 既存ウィンドウにもインストール済みアプリにも一致しない文字列を入力した際に従来の「一致するウィンドウがありません」表示および `Enter` 無操作が維持されること、候補件数変化時にパネル上端位置が固定されたまま下方向のみ伸縮すること、およびアプリ候補表示中に終了操作を行っても何も終了されないことを確認できる。

**Acceptance Scenarios**:

1. **Given** 検索ランチャーが開いている状態, **When** 既存ウィンドウにもインストール済みアプリにも一致しない検索文字列が入力される, **Then** リスト領域に「一致するウィンドウがありません」というメッセージが表示され、`Enter` キーや上下移動を行っても誤動作せずパネルが維持される。
2. **Given** 検索ランチャー上で特定のアプリ名を入力してそのアプリの最後のウィンドウを閉じた結果、一致するウィンドウが 0 件（かつ他アプリのウィンドウは残存）となった状態, **When** クローズ処理が完了する, **Then** 検索キーワードを維持したまま、同一キーワードに一致するアプリ起動候補表示へ切り替わる。
3. **Given** アプリ起動候補が表示されている状態, **When** ユーザーが選択中ウィンドウの終了操作（スイッチャー修飾キー + `Q`）を入力する, **Then** 閉じる対象ウィンドウが存在しないため終了処理は発動せず、入力が安全に消費・無視されてパネルが維持される。
4. **Given** 既存ウィンドウ表示・アプリ起動候補表示・0 件表示の間で候補数や表示モードが切り替わる状態, **When** ユーザーが文字を入力・削除する, **Then** ランチャーパネルの上端位置（検索入力欄の画面上の高さ）は固定されたまま、リスト領域の下端のみが滑らかに伸縮する。

---

### Edge Cases

- **検索入力欄が空欄または空白文字のみの場合**: アプリ起動候補は表示せず、従来通り直近アクティブ順（MRU）の既存ウィンドウ一覧を表示する。
- **通常スイッチャーモード（非ランチャーモード）の表示中**: 通常スイッチャーには検索欄が存在しないため、アプリ起動候補機能は介入せず、従来通りのウィンドウ切り替え専用動作を維持する。
- **アプリは起動済みだが開いているウィンドウが 0 枚のとき**: ウィンドウ一覧には対象アプリが存在しないため、検索時にアプリ起動候補として表示され、選択確定でアプリが前面化／新規ウィンドウが開く。
- **重複配置・エイリアス・非対話ヘルパーアプリ・本アプリ自身**: シンボリックリンク等で複数経路から見える同一アプリは重複表示せず 1 件に統合し、バックグラウンド専用ヘルパーや本アプリ（Wintch）自身、起動不可能な不完全バンドルは起動候補から除外する。
- **ランチャー起動後に新しくインストールされたアプリ**: ランチャー表示中に裏側でアプリ一覧が最新化され、アプリ起動候補表示中に新着アプリが一致した場合は、現在の表示と選択位置の整合性を保ちつつ候補へ反映する。
- **キャンセル操作（`Esc`・ランチャーショートカット再押下・パネル外クリック）**: アプリ起動候補が表示されていても起動は実行せずパネルを閉じ、`Esc` やトグル再押下時は直前アプリへフォーカスを戻す。
- **日本語 IME 未確定入力中のキー操作**: 既存ウィンドウ表示時と同様、IME 変換中の `Enter`・`Esc`・`↑`・`↓` は IME 操作を最優先する。
- **既存仕様書との整合性**: `002-window-search-launcher`・`004-launcher-switcher-nav`・`005-close-selected-window` の各仕様書における「検索結果 0 件時の扱い」の記述は、本仕様のアプリ起動候補フォールバックに合わせて整合・改定される。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 検索ランチャーモードで空欄以外の検索キーワードが入力され、既存ウィンドウの一致結果が 0 件となった場合、システムはインストール済みかつ起動可能なアプリケーションを対象に検索を実行し、一致するアプリ起動候補をリスト表示しなければならない（MUST）。
- **FR-002**: 検索キーワードに一致する既存ウィンドウが 1 件以上存在する場合、または検索キーワードが空欄（空白のみを含む）の場合、システムはアプリ起動候補を表示してはならない（MUST NOT）。
- **FR-003**: システムは、ユーザー向け標準アプリケーション配置領域および標準ユーティリティ／主要システムアプリ（例：Finder 等）から起動可能なアプリケーションを収集し、シンボリックリンクの実体も辿った上で重複を排除しなければならない（MUST）。バックグラウンド専用の非対話プロセス、起動不能な不完全バンドル、および本アプリ自身は候補から除外しなければならない（MUST）。
- **FR-004**: アプリ起動候補の検索では、各アプリケーションの「表示名」および表示名と異なる場合の「別名（原語ファイル名等）」を対象として、空白区切り AND 条件・大文字小文字および発音区別符号・文字幅を区別しないファジー検索を実行しなければならない（MUST）。
- **FR-005**: 一致したアプリ起動候補は一致スコアの高い順に並び替え、同一スコアの場合は表示名の自然な昇順で並べて、先頭項目（1番目）を初期選択状態にしなければならない（MUST）。
- **FR-006**: アプリ起動候補リストを表示する際、システムはウィンドウ切り替え候補ではなく新規起動候補であることを識別できるようセクション案内および「起動」インジケータを表示し、各行にアプリアイコン・一致文字の太字ハイライト付きアプリ名・（異なる場合のみ）ハイライト付き別名を表示しなければならない（MUST）。
- **FR-007**: アプリ起動候補表示中、ユーザーは `↑` / `↓` 矢印キー、`Ctrl + N` / `Ctrl + P`、および通常スイッチャーの順方向・逆方向ショートカットで候補間を循環移動し、`Enter` キーまたは行クリックでパネルを閉じて対象アプリを起動（既存起動中なら前面化）できなければならない（MUST）。通常スイッチャーのショートカットに用いた修飾キーを離してもパネルは閉じてはならない（MUST NOT）。
- **FR-008**: 既存ウィンドウ検索が 0 件かつアプリ起動候補も 0 件の場合、システムはパネルを閉じずに「一致するウィンドウがありません」の案内メッセージを表示し、その状態での `Enter` キーや上下移動を安全に無視しなければならない（MUST）。
- **FR-009**: アプリ起動候補の取得とキャッシュにより、ランチャーの文字入力ごとの検索応答が遅延しないよう設計しなければならず（MUST）、ランチャー起動時にも裏側で最新のインストール済みアプリを反映して、すでに起動候補表示中であれば整合を保ちながら更新しなければならない（MUST）。
- **FR-010**: アプリ起動候補表示中にウィンドウ終了ショートカット（スイッチャー修飾キー + `Q`）が入力された場合、システムは誤操作を行わず入力を消費して安全に無視しなければならない（MUST）。また、既存ウィンドウの終了操作によりランチャー上のウィンドウ一致結果が 0 件（かつ他に有効ウィンドウが残存）となった場合は、検索キーワードを維持したままアプリ起動候補検索を評価し、一致候補があれば表示を切り替えなければならない（MUST）。
- **FR-011**: アプリ起動候補の表示・件数変化・ウィンドウ表示への復帰に際しても、ランチャーパネルの上端位置を固定したまま下方向のみに高さを伸縮させなければならない（MUST）。
- **FR-012**: 本機能においても画面収録権限や追加のプライバシー権限を一切要求・使用してはならず（MUST NOT）、非公開 API も使用してはならない（MUST NOT）。

### Key Entities

- **LaunchableApp（起動可能アプリケーション）**: 端末内にインストールされておりランチャーから起動可能なアプリケーションを表す概念。表示用名称、検索用の英語・元名（表示名と異なる場合）、識別子、および起動先パス情報を持ち、重複なく一意に管理される。
- **AppSearchResult（アプリ検索結果）**: ファジー検索によって評価された個別のアプリ起動候補を表す概念。対象の `LaunchableApp`、算出された一致スコア、および表示名・別名内で一致した文字位置範囲（ハイライト描画用）の属性を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 既存ウィンドウが 0 件となる検索キーワードを入力した際、100% のケースで体感のある引っかかりなく 100 ミリ秒以内にアプリ起動候補リスト（または 0 件案内表示）へ切り替わる。
- **SC-002**: インストール済みの主要アプリケーション（日本語ローカライズ名を持つ標準アプリを含む）について、表示名・英語名・略称による検索で目的のアプリが候補に現れ、選択から起動まで 1 回の確定操作（`Enter` またはクリック）で完了する。
- **SC-003**: 既存ウィンドウが 1 件以上一致する検索時および未入力時に、アプリ起動候補が誤って混入・表示される割合が 0% である。
- **SC-004**: 既存ウィンドウ候補・アプリ起動候補・0 件表示が切り替わる全入力フローを通じて、ランチャーパネル上端座標のズレが 0 ポイントのまま維持される。
- **SC-005**: 既存仕様書（`002-window-search-launcher`・`004-launcher-switcher-nav`・`005-close-selected-window`）において、本仕様と矛盾する「検索 0 件時の挙動」に関する記述が 0 件である。

## Assumptions

- 検索ランチャー自体の起動前提条件（アクセシビリティ権限が許可されており、起動時点で有効な通常ウィンドウが 1 件以上開かれている場合にパネルを開く）は既存仕様（`002-window-search-launcher`）をそのまま継承する。
- 起動対象として探索するアプリケーション配置領域は、macOS の一般的なアプリケーション配置場所（標準のシステムおよびユーザー配下のアプリケーション領域・ユーティリティおよび Finder）を対象とし、ドキュメントフォルダや任意の一時作業フォルダ内のアプリまでは探索しない。
- アプリ起動候補は「既存ウィンドウが見つからなかった場合のフォールバック導線」として提供し、既存ウィンドウが 1 件以上一致する状態で常に全アプリを混ぜて表示する方式はとらない（憲章「過剰機能の排除・シンプルさの徹底」に準拠）。
