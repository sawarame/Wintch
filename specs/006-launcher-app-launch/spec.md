# 機能仕様書: 検索ランチャーでの検索入力時におけるアプリ起動候補の併用表示

**Feature Branch**: `006-launcher-app-launch`

**Created**: 2026-11-15

**Status**: Draft

**Input**: User description: "検索ランチャーでキーワードが検索されたとき、既存ウィンドウが 0 件のときだけでなく、既存ウィンドウ候補の下にも起動できるアプリ候補を表示する（ただし上のウィンドウ候補に既に表示されているアプリは下の起動候補から除外する）。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 検索入力時に既存ウィンドウ候補の下へ未表示アプリ起動候補を併せて表示し起動する (Priority: P1)

ユーザーは、検索ランチャーを起動してキーワードを入力した際、一致する既存ウィンドウがある場合は上部にウィンドウ候補が表示されつつ、その下にも（すでに上部のウィンドウ候補に出ているアプリを除いた）一致するアプリケーションの起動候補が併せて表示されるため、既存のウィンドウへの切り替えと未起動（または未一致）アプリの起動を 1 回の検索フローの中でシームレスに行える。

**Why this priority**: 検索ランチャーから別アプリを立ち上げたい場面において、先頭文字の入力で他アプリのウィンドウがたまたま引っ掛かっていても、わざわざ長いキーワードを打ち切って 0 件にする必要がなく、即座に目的のアプリを起動できることが実用体験の中核であるため。

**Independent Test**: 複数のウィンドウが開かれた状態で検索ランチャーを開き、ウィンドウ候補にも別アプリにも部分一致する検索キーワード（例：`"sa"` で Safari のウィンドウと Slack.app 等が一致）を入力した際、上部に一致したウィンドウ候補・下部に重複アプリを除いたアプリ起動候補が区切り付きで表示されること、上下操作で両セクションを貫通して循環移動できること、`Enter` やクリックで選択種別に応じた動作（ウィンドウ切替またはアプリ起動）が実行されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 検索ランチャーが開いており、「Safari」のウィンドウが開かれていて「Slack」は開かれていない状態, **When** ユーザーが `"s"` のように双方に一致する検索キーワードを入力する, **Then** 上部にウィンドウ候補（「Safari」のウィンドウ）が表示され、その下にセクション区切りとともにアプリ起動候補（「Slack」等、「Safari」は上のウィンドウ候補に既出のため除外）が表示され、選択カーソルは最先頭のウィンドウ候補（1番目）に位置する。
2. **Given** 上部にウィンドウ候補が 1 件以上、下部にアプリ起動候補が 1 件以上表示されている状態, **When** ユーザーが `↓` 矢印キー、`Ctrl + N`、または通常スイッチャーの順方向ショートカットを繰り返し押す, **Then** 選択カーソルはウィンドウ候補の先頭から末尾へ進んだ後、そのまま下部のアプリ起動候補の先頭へシームレスに移動し、アプリ起動候補の末尾の次は再びウィンドウ候補の先頭へ循環する（逆方向操作でも同様に逆順循環し、通常スイッチャーショートカットの修飾キーを離してもパネルは閉じない）。
3. **Given** どの既存ウィンドウにも一致しないがインストール済みアプリに一致する検索キーワード（例：`"cal"`）が入力された状態, **When** 検索結果が更新される, **Then** 上部のウィンドウ候補は表示されず、アプリ起動候補のみが表示され、その先頭項目（1番目）が選択状態になる。
4. **Given** アプリ起動候補側の行に選択カーソルが置かれている状態, **When** ユーザーが `Enter` キーを押す（またはその行をクリックする）, **Then** ランチャーパネルが閉じ、選択されていたアプリケーションが起動して最前面に表示される（ウィンドウ候補側が選択されている場合は従来通りそのウィンドウへ切り替わる）。
5. **Given** 検索キーワードが入力されてウィンドウ候補とアプリ起動候補が表示されている状態, **When** ユーザーが検索文字列をすべて削除して空欄（または空白のみ）に戻す, **Then** アプリ起動候補セクションは消え、直近アクティブ順（MRU）の既存ウィンドウ一覧のみに戻る。

### User Story 2 - 日本語名・英語名の双方によるアプリ検索とハイライト表示 (Priority: P2)

ユーザーは、日本語環境で英語名とは異なる表示名を持つ標準アプリケーション（例：「メモ」と「Notes」、「システム設定」と「System Settings」）についても、日本語名・英語名どちらの入力でも迷わず見つけ出し、どの文字が一致したかをハイライトで確認して起動できる。

**Why this priority**: macOS の日本語環境ではシステム標準アプリがローカライズ名と英語元の名称の双方で認識されることが多く、どちらの入力習慣でもストレスなく検索・識別できることが実用性を大きく左右するため。

**Independent Test**: ローカライズ名と英語別名の双方を持つアプリケーションが候補に含まれる状態で検索ランチャーを開き、英語表記および日本語表記のキーワードを入力した際、いずれの入力でも対象アプリがアプリ起動候補セクションに現れて一致文字箇所が太字・ハイライト表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** ローカライズされた表示名（例：「メモ」）と英語由来の別名（例：「Notes」）が異なるアプリケーションが端末にインストールされており、そのアプリのウィンドウが上のウィンドウ候補に出ていない状態, **When** ユーザーが検索欄に英語キーワード（例：`"note"`）または日本語キーワード（例：`"メモ"`）を入力する, **Then** 双方のキーワードいずれでもアプリ起動候補セクションに表示され、別名が併記された上で一致した文字箇所が太字・ハイライト表示される。
2. **Given** 複数語をスペースで区切ったキーワード（例：`"vis code"` や `"sys set"`）が入力された状態, **When** 検索が実行される, **Then** スペース区切り AND 条件のファジー検索により、表示名・別名を横断して一致する未表示アプリのみがスコア順（同点時は名称昇順）でウィンドウ候補の下に表示される。

### User Story 3 - 境界状態・重複除外・パネル安定性および既存操作との安全な共存 (Priority: P2)

ユーザーは、ウィンドウ候補・アプリ候補のどちらも一致しない場合、ウィンドウを閉じて残余一覧が更新された場合、またはカーソルがアプリ候補側にある状態で誤って終了ショートカットを押した場合でも、パネルの位置や操作の一貫性が崩れず安全に作業を継続できる。

**Why this priority**: 2セクション統合表示において、ウィンドウクローズ・重複除外・0 件状態・レイアウト追従といった既存機能との境界で不整合や誤操作が起きないことが、日常的な信頼性に直結するため。

**Independent Test**: ウィンドウ・アプリ双方に一致しない入力で「一致するウィンドウがありません」と `Enter` 無操作が維持されること、ウィンドウ候補が閉じてアプリがウィンドウ一覧から消えると下の起動候補へ自然に出現すること、アプリ起動候補選択中の終了操作（修飾キー + `Q`）が無視されること、およびセクション増減時にパネル上端位置が固定維持されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 検索ランチャーが開いている状態, **When** 既存ウィンドウにも未表示のインストール済みアプリにも一致しない検索文字列が入力される, **Then** リスト領域に「一致するウィンドウがありません」というメッセージが表示され、`Enter` キーや上下移動を行っても誤動作せずパネルが維持される。
2. **Given** 検索ランチャーでウィンドウ候補とアプリ起動候補が混在表示されている状態（またはアプリ起動候補のみ表示中）, **When** ユーザーがアプリ起動候補側の項目を選択した状態で終了操作（スイッチャー修飾キー + `Q`）を入力する, **Then** 閉じる対象ウィンドウが存在しないため終了処理は発動せず、入力が安全に消費・無視されてパネルが維持される。
3. **Given** 検索キーワードが入力された状態で、あるアプリの最後のウィンドウを終了操作（スイッチャー修飾キー + `Q`）で閉じ（かつ他に別アプリのウィンドウは残存している）状態, **When** クローズ処理が完了する, **Then** 当該アプリが上のウィンドウ候補から除外されると同時に、検索キーワードに一致するアプリ起動候補の再評価が行われ、必要なら下の「アプリを起動」欄へ候補が現れる。
4. **Given** 検索文字列の入力・削除によってウィンドウ候補件数とアプリ起動候補件数がリアルタイムに増減する状態, **When** リスト表示が再描画される, **Then** ランチャーパネルの上端位置（検索入力欄の画面上の高さ）は固定されたまま、リスト領域の下端のみが滑らかに伸縮する。

---

### Edge Cases

- **上のウィンドウ候補に同じアプリが複数ウィンドウ出ている場合**: 同一アプリのウィンドウが上欄に複数枚表示されていても、重複除外によって下のアプリ起動候補に同じアプリは現れない。
- **あるアプリは開いているが、別タイトル条件などで上のウィンドウ候補には一致しなかった場合**: 例として Safari が別タイトルのウィンドウのみで今回の検索語（ウィンドウタイトル条件）に一致しなかった場合など、上のウィンドウ候補に表示されていないアプリに検索語が一致すれば、下のアプリ起動候補の候補対象になり得る（基準は「上のウィンドウ検索結果に表示されているアプリを除外」）。
- **検索入力欄が空欄または空白文字のみの場合**: アプリ起動候補は表示せず、従来通り直近アクティブ順（MRU）の既存ウィンドウ一覧のみを表示する。
- **通常スイッチャーモード（非ランチャーモード）の表示中**: 通常スイッチャーには検索欄が存在しないため、アプリ起動候補機能は介入せず、従来通りのウィンドウ切り替え専用動作を維持する。
- **重複配置・エイリアス・非対話ヘルパーアプリ・本アプリ自身**: シンボリックリンク等で複数経路から見える同一アプリは重複表示せず 1 件に統合し、バックグラウンド専用の非対話プロセスや本アプリ（Wintch）自身、起動不能な不完全バンドルは起動候補から除外する。
- **ランチャー起動後に新しくインストールされたアプリ**: ランチャー表示中に裏側でアプリ一覧が最新化され、検索入力中に新着アプリが一致した場合は、現在の表示や選択位置（ウィンドウ候補選択中の位置を含む）を破綻させずに反映する。
- **キャンセル操作（`Esc`・ランチャーショートカット再押下・パネル外クリック）**: アプリ起動候補が表示・選択されていても起動は実行せずパネルを閉じ、`Esc` やトグル再押下時は直前アプリへフォーカスを戻す。
- **日本語 IME 未確定入力中のキー操作**: 従来通り、IME 変換中の `Enter`・`Esc`・`↑`・`↓` は IME 操作を最優先する。
- **既存仕様書との整合性**: `002-window-search-launcher`・`004-launcher-switcher-nav`・`005-close-selected-window` の各仕様書における「検索結果・選択操作・クローズ時再評価」の記述は、本仕様に合わせて整合・改定される。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 検索ランチャーモードで空欄（空白のみを含む）以外の検索キーワードが入力された場合、システムは既存ウィンドウの検索結果が 0 件か 1 件以上かにかかわらず、インストール済みかつ起動可能なアプリケーションを対象にファジー検索を実行し、一致したアプリをウィンドウ候補の下に「アプリ起動候補」セクションとして表示しなければならない（MUST）。
- **FR-002**: 検索キーワードが空欄（空白のみを含む）の場合、システムはアプリ起動候補を表示してはならず（MUST NOT）、直近アクティブ順の既存ウィンドウ一覧のみを表示しなければならない（MUST）。
- **FR-003**: システムは、上のウィンドウ検索結果にすでに含まれているアプリケーション（プロセス ID やバンドル情報またはアプリケーション名称で一致するアプリ）を下のアプリ起動候補から除外し、重複して表示してはならない（MUST NOT）。
- **FR-004**: システムは、標準のシステムおよびユーザーのアプリケーション配置領域や標準ユーティリティ・主要システムアプリ（Finder 等）から起動可能なアプリケーションを収集し、シンボリックリンクの実体も辿った上で重複を排除しなければならない（MUST）。バックグラウンド専用の非対話プロセス、起動不能な不完全バンドル、および本アプリ自身は候補から除外しなければならない（MUST）。
- **FR-005**: アプリ起動候補の検索では、各アプリケーションの「表示名」および表示名と異なる場合の「別名（原語ファイル名等）」を対象として、空白区切り AND 条件・大文字小文字および発音区別符号・文字幅を区別しないファジー検索を実行しなければならない（MUST）。
- **FR-006**: 一致したアプリ起動候補は一致スコアの高い順に並び替え、同一スコアの場合は表示名の自然な昇順で並べなければならない（MUST）。検索入力直後の初期選択カーソルは、ウィンドウ候補が 1 件以上あればウィンドウ候補の先頭（全体インデックス `0`）、ウィンドウ候補が 0 件でアプリ起動候補のみがある場合はアプリ起動候補の先頭（全体インデックス `0`）に設定しなければならない（MUST）。
- **FR-007**: パネル上の統合リストでは、ウィンドウ候補がある場合は上部にウィンドウ候補一覧を表示し、アプリ起動候補が 1 件以上ある場合は下部に区切りとセクション案内（「アプリを起動」等）を設けて各アプリ行（アプリアイコン・太字ハイライト付き表示名・異なる場合のみハイライト付き別名・「起動」インジケータ）を表示しなければならない（MUST）。
- **FR-008**: 検索入力中の候補選択カーソルは、上部のウィンドウ候補と下部のアプリ起動候補を1つの連続した選択順序として扱い、`↑` / `↓` 矢印キー、`Ctrl + N` / `Ctrl + P`、および通常スイッチャーの順方向・逆方向ショートカットで両セクション間をシームレスかつ循環移動できなければならない（MUST）。通常スイッチャーのショートカットに用いた修飾キーを離してもパネルは閉じてはならない（MUST NOT）。
- **FR-009**: 確定操作（`Enter` キーまたは行クリック）が行われたとき、選択位置がウィンドウ候補を指していれば該当ウィンドウを最前面へアクティブ化し、アプリ起動候補を指していれば該当アプリを起動（既存起動中なら前面化）して、いずれの場合もパネルを閉じなければならない（MUST）。
- **FR-010**: 既存ウィンドウ候補が 0 件かつアプリ起動候補も 0 件の場合、システムはパネルを閉じずに「一致するウィンドウがありません」の案内メッセージを表示し、その状態での `Enter` キーや上下移動を安全に無視しなければならない（MUST）。
- **FR-011**: アプリ起動候補の取得とキャッシュにより、ランチャーの文字入力ごとの検索応答が遅延しないよう設計しなければならず（MUST）、ランチャー起動時にも裏側で最新のインストール済みアプリを反映して、検索キーワード入力中であれば選択カーソルの整合を保ちながら更新しなければならない（MUST）。
- **FR-012**: 選択カーソルがアプリ起動候補側にある状態（または候補 0 件状態）でウィンドウ終了ショートカット（スイッチャー修飾キー + `Q`）が入力された場合、システムは誤操作を行わず入力を消費して安全に無視しなければならない（MUST）。また、ウィンドウ候補側を選択して終了操作を行った結果、対象アプリがウィンドウ一覧から除外された（かつ他に有効ウィンドウが残存している）場合は、検索キーワードを維持したままウィンドウ候補とアプリ起動候補の双方を再評価し、選択インデックスを安全に補正しなければならない（MUST）。
- **FR-013**: ウィンドウ候補とアプリ起動候補の表示・件数変化・空状態への遷移に際しても、ランチャーパネルの上端位置を固定したまま下方向のみに高さを伸縮させなければならない（MUST）。
- **FR-014**: 本機能においても画面収録権限や追加のプライバシー権限を一切要求・使用してはならず（MUST NOT）、非公開 API も使用してはならない（MUST NOT）。

### Key Entities

- **LaunchableApp（起動可能アプリケーション）**: 端末内にインストールされておりランチャーから起動可能なアプリケーションを表す概念。表示用名称、検索用の英語・元名（表示名と異なる場合）、識別子、および起動先パス情報を持ち、重複なく一意に管理される。
- **AppSearchResult（アプリ検索結果）**: ファジー検索によって評価された個別のアプリ起動候補を表す概念。対象の `LaunchableApp`、算出された一致スコア、および表示名・別名内で一致した文字位置範囲（ハイライト描画用）の属性を持つ。
- **Unified Launcher Selection（統合ランチャー選択位置）**: 検索中のウィンドウ候補一覧（インデックス `0 ..< windowCount`）と、その直後に続くアプリ起動候補一覧（インデックス `windowCount ..< windowCount + appCount`）を単一の連続インデックスとして扱う選択状態。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 検索キーワードを 1 文字入力または削除するたびに、ウィンドウ検索およびアプリ検索・重複除外・一覧再描画が 100 ミリ秒以内に完了し、体感のある入力遅延が発生しない。
- **SC-002**: ウィンドウ候補が 1 件以上一致する検索時でも、上のウィンドウ候補に出ていない未起動・未一致アプリが下の「アプリを起動」セクションに表示され、キーボード移動またはクリックから 1 回の確定操作で起動できる。
- **SC-003**: 上のウィンドウ候補に表示中の同一アプリケーションが下のアプリ起動候補に重複出現する割合が 0% であり、検索欄が空欄のときにアプリ起動候補が誤表示される割合も 0% である。
- **SC-004**: ウィンドウ候補のみ・混在表示・アプリ起動候補のみ・0 件表示の間で候補が切り替わる全入力フローを通じて、ランチャーパネル上端座標のズレが 0 ポイントのまま維持される。
- **SC-005**: 既存仕様書（`002-window-search-launcher`・`004-launcher-switcher-nav`・`005-close-selected-window`）において、本仕様と矛盾する記述が 0 件である。

## Assumptions

- 検索ランチャー自体の起動前提条件はアクセシビリティ権限が許可されていることであり、有効な通常ウィンドウが 0 件の状態でも検索ランチャーパネルを開いてアプリ検索・起動を行える（※ `010-launcher-without-windows` にて改定）。
- 起動対象として探索するアプリケーション配置領域は、macOS の一般的なアプリケーション配置場所（標準のシステムおよびユーザー配下のアプリケーション領域・ユーティリティおよび Finder）を対象とし、ドキュメントフォルダや任意の一時作業フォルダ内のアプリまでは探索しない。
- 上のウィンドウ候補と下のアプリ起動候補の同一性判定は、実行中アプリのバンドル識別子（またはバンドル URL）が取得できる場合はそれを最優先に照合し、取得できない場合はアプリケーション名の大小文字を無視した比較で安全にフォールバック照合する。
