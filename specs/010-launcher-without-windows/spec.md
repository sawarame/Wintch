# 機能仕様書: ウィンドウ 0 件時の検索ランチャー起動対応

**Feature Branch**: `010-launcher-without-windows`

**Created**: 2026-11-16

**Status**: Draft

**Input**: User description: "現在ランチャーはウィンドウが一つもないと起動しませんが、ウィンドウが一つもないときも起動するようにしてもらえますか。アプリ起動ランチャーとしてしようしたいので。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ウィンドウが 0 件の状態でも検索ランチャーを起動してアプリを起動する (Priority: P1)

ユーザーは、デスクトップ上に操作可能な通常ウィンドウが 1 つも開かれていない状態（アプリをすべて閉じた直後、ログイン直後、別アプリをすべて終了した状態など）であっても、検索ランチャーのショートカットを押すことで検索ランチャーパネルを開き、インストール済みアプリケーションを検索してそのまま起動できる。これにより、開いているウィンドウの有無にかかわらず、常に同じショートカットと操作感でアプリ起動ランチャーとして利用できる。

**Why this priority**: 「開いているウィンドウが 0 件のときでもアプリ起動ランチャーとして使えること」が本変更の中核であり、この導線なしではウィンドウをすべて閉じた瞬間に検索ランチャー自体が利用不能になってしまうため。

**Independent Test**: 有効な通常ウィンドウが 0 件の状態で検索ランチャーのショートカット（デフォルト `Option + Space`）を押してパネルが表示され、検索入力欄に自動フォーカスが当たるとともにウィンドウ 0 件時の案内メッセージが表示されること、アプリ名や別名（英語名・日本語名）を入力して一致するアプリケーションの起動候補が選択可能になること、および確定操作（`Enter` キーまたはクリック）で対象アプリが起動してパネルが閉じることを確認できる。

**Acceptance Scenarios**:

1. **Given** 操作可能な通常ウィンドウが 0 件であり、アクセシビリティ権限が許可されている状態, **When** ユーザーが検索ランチャーのショートカットを押す, **Then** 検索ランチャーパネルが画面に表示され、検索入力欄に自動フォーカスが当たった状態で、リスト領域に「開いているウィンドウがありません（アプリ名を入力して起動）」等の案内メッセージが表示される（未入力状態ではアプリ一覧は表示されない）。
2. **Given** ウィンドウ 0 件の状態で検索ランチャーが開いている状態, **When** ユーザーが起動したいアプリ名や別名（例：`"safari"` や `"メモ"`）を入力する, **Then** 案内メッセージが消え、一致するインストール済みアプリケーションが「アプリ起動候補」としてスコア順に表示されて先頭項目が初期選択され、確定操作（`Enter` またはクリック）で対象アプリが起動してパネルが閉じる。
3. **Given** ウィンドウ 0 件の状態で検索ランチャーが開いている状態, **When** ユーザーがキャンセル操作（`Esc` キー、検索ランチャーショートカットの再押下、またはパネル外クリック）を行う, **Then** アプリは起動されず、即座にパネルが閉じる。

### User Story 2 - 通常スイッチャーとの役割分離およびウィンドウ 0 件状態へのシームレスな遷移維持 (Priority: P2)

ユーザーは、通常スイッチャーがウィンドウ 0 件のときに誤って空表示されない従来の安全性を維持しつつ、検索ランチャーではウィンドウ 0 件時・検索文字列削除時・最後のウィンドウ終了時のいずれにおいてもパネルが途切れず、アプリ起動ランチャーとしての一貫した体験を得られる。

**Why this priority**: 通常スイッチャー（ウィンドウ切り替え専用）と検索ランチャー（ウィンドウ検索＋アプリ起動）の境界および 0 件状態における各種操作の安全性を明確にし、誤操作や意図しないパネル閉鎖を防ぐため。

**Independent Test**: 通常ウィンドウ 0 件の状態で通常スイッチャーショートカット（デフォルト `Option + Tab`）を押してもパネルが開かないこと、検索ランチャー表示中に最後のウィンドウを閉じた場合もパネルが開いたまま維持されてそのままアプリ検索・起動を続けられること、アプリ起動候補表示後に検索語を削除すると 0 件時の案内メッセージへ戻ること、および一致するアプリも存在しない入力で `Enter` 等を押してもエラーや誤動作が起きないことを確認できる。

**Acceptance Scenarios**:

1. **Given** 操作可能な通常ウィンドウが 0 件の状態, **When** ユーザーが通常スイッチャーのショートカット（順方向または逆方向）を押す, **Then** 切り替える対象ウィンドウが存在しないため通常スイッチャーパネルは表示されない。
2. **Given** 残り 1 枚の通常ウィンドウがある状態で検索ランチャーが開いている状態, **When** ユーザーがその最後のウィンドウを選択してウィンドウ終了操作（スイッチャー修飾キー + `Q`）で閉じる, **Then** ウィンドウが 0 件になっても検索ランチャーは閉じずに開いたまま維持され、検索語が未入力なら「開いているウィンドウがありません」等の案内表示へ遷移し、検索語が入力中であれば一致するアプリ起動候補を再評価して表示を継続する。
3. **Given** ウィンドウ 0 件の状態で検索ランチャーが開いており、検索文字列を入力してアプリ起動候補が表示されている状態, **When** ユーザーが検索文字列をすべて削除して空欄（または空白のみ）に戻す, **Then** アプリ起動候補は消え、パネルは開いたまま上端位置をずらさずに「開いているウィンドウがありません（アプリ名を入力して起動）」等の案内表示へ切り替わる。
4. **Given** ウィンドウ 0 件の状態で検索ランチャーが開いており、一致するアプリも存在しない検索文字列が入力されている状態, **When** ユーザーが `Enter` キー・上下移動操作・ウィンドウ終了ショートカット（スイッチャー修飾キー + `Q`）を入力する, **Then** 誤起動やクラッシュは発生せず、入力が安全に無視されてパネルが維持される。

---

### Edge Cases

- **ウィンドウ 0 件・検索欄未入力で検索ランチャーを起動した直後の表示**: 検索文字列が空（空白のみを含む）の状態ではアプリ起動候補一覧を出さず、「開いているウィンドウがありません（アプリ名を入力して起動）」等の案内メッセージのみを表示し、1文字以上入力されたタイミングでアプリ検索・表示へ切り替える。
- **検索ランチャー表示中に最後のウィンドウを閉じた場合の挙動**: 検索ランチャー表示中に残っていた最後の 1 枚のウィンドウを終了操作（スイッチャー修飾キー + `Q`）で閉じて 0 件になった場合でも、ランチャーは閉じずに開いたまま維持する（未入力時は 0 件案内表示へ遷移、検索語入力中はアプリ起動候補の再評価結果を維持）。なお、通常スイッチャー表示中に最後のウィンドウを閉じた場合は、従来通り自動でパネルを閉じる。
- **検索キーワード入力後にウィンドウもアプリ起動候補も一致しない場合**: ウィンドウが存在しない環境で一致するアプリも見つからない場合でもパネルは閉じず、未入力時の「開いているウィンドウがありません」とは区別して、入力語に一致する候補がないことが分かる案内表示を維持し、`Enter` キーや選択移動を安全に消費する。
- **ランチャー表示中にバックグラウンドでアプリが新規インストール・更新された場合**: ウィンドウ 0 件の状態で検索ランチャーを開いた直後に裏側でアプリ一覧が最新化された場合でも、検索入力中の結果や選択位置が破綻せずに更新される。
- **アクセシビリティ権限が未許可の状態でウィンドウ 0 件時に検索ランチャーを起動しようとした場合**: 従来通りパネルは開かず、既存のアクセシビリティ権限誘導画面へ安全に案内する。
- **日本語 IME 未確定入力中の操作**: ウィンドウ 0 件の状態で検索ランチャーを開き日本語 IME で入力している間も、従来通り IME の確定・キャンセル・候補選択操作を最優先する。
- **既存仕様書との整合性**: `002-window-search-launcher`・`005-close-selected-window`・`006-launcher-app-launch`・`008-launcher-ux-refinement` に記載されている「開いている通常ウィンドウが 0 件のときは検索ランチャーを起動しない／最後のウィンドウを閉じたらランチャーも閉じる」前提は、本仕様に合わせて改定・整合化される。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、操作可能な通常ウィンドウが 0 件の状態であっても、アクセシビリティ権限が許可されている場合は検索ランチャーの起動ショートカットによって検索ランチャーパネルを開き、検索入力欄へ自動的にキーボードフォーカスを与えなければならない（MUST）。
- **FR-002**: システムは、ウィンドウ 0 件の状態で起動した検索ランチャーにおいて検索文字列が空（または空白のみ）の場合、アプリ起動候補は表示せず、検索欄の下にウィンドウが存在しないこととアプリ検索を促す案内メッセージ（「開いているウィンドウがありません（アプリ名を入力して起動）」等）を表示しなければならない（MUST）。
- **FR-003**: ウィンドウ 0 件の状態で開かれた検索ランチャーに有効な検索キーワード（空白のみ以外）が入力された場合、システムはインストール済みかつ起動可能なアプリケーションを対象にファジー検索を実行し、一致したアプリを起動候補として表示し、先頭項目を初期選択しなければならない（MUST）。
- **FR-004**: ユーザーは、ウィンドウ 0 件の状態で起動した検索ランチャーに表示されたアプリ起動候補を、既存のキーボード操作（`↑` / `↓`、`Ctrl + N` / `Ctrl + P`、通常スイッチャーの順方向・逆方向ショートカット）またはクリックで選択し、`Enter` キーまたは行クリックで対象アプリを起動してパネルを閉じることができなければならない（MUST）。
- **FR-005**: システムは、ウィンドウ 0 件の状態で検索ランチャーを開いている間にキャンセル操作（`Esc` キー、検索ランチャーショートカットの再押下、パネル外クリック）が行われた場合、アプリを起動せずに即座にパネルを閉じなければならない（MUST）。
- **FR-006**: 検索ランチャー表示中に開いていた最後の 1 枚のウィンドウを終了操作（スイッチャー修飾キー + `Q`）で閉じてウィンドウが 0 件になった場合、システムはパネルを閉じずに開いたまま維持し、検索キーワードが空なら 0 件時の案内メッセージ表示へ遷移し、検索キーワードが入力中ならアプリ起動候補を再評価して表示・操作を継続できなければならない（MUST）。一方、通常スイッチャー表示中に最後のウィンドウを閉じた場合は、従来通り自動的にパネルを閉じなければならない（MUST）。
- **FR-007**: システムは、操作可能な通常ウィンドウが 0 件の状態で通常スイッチャーの起動ショートカットが押された場合は、従来通りパネルを表示しない挙動を維持しなければならない（MUST）。
- **FR-008**: ウィンドウ 0 件状態からの起動・検索・候補件数変化・検索結果 0 件状態への切り替えに際しても、検索ランチャーパネルの上端位置（検索入力欄の位置）を固定維持し、画面収録権限の要求や非公開機能の使用を行ってはならない（MUST NOT）。
- **FR-009**: 関連する既存仕様書（`002-window-search-launcher`・`005-close-selected-window`・`006-launcher-app-launch`・`008-launcher-ux-refinement`）における「ウィンドウ 0 件時は検索ランチャーを開かない」「ランチャーで最後のウィンドウを閉じたらパネルを閉じる」旨の記述を本仕様に合わせて整合化しなければならない（MUST）。

### Key Entities

- **検索ランチャー起動対象状態（ウィンドウ 0 件モード）**: 有効な通常ウィンドウが存在しない環境で開かれた検索ランチャーの稼働状態。ウィンドウ候補は空であり、未入力時の案内表示と、キーワード入力によるアプリ起動候補の提示・選択・確定のサイクルを単独で完結できる。
- **アプリ起動候補**: インストール済みかつ起動可能なアプリケーションと、その検索一致情報。ウィンドウ 0 件時はウィンドウ候補が存在しないため、起動候補のみが直接選択対象となる。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 有効な通常ウィンドウが 0 件の状態で検索ランチャーショートカットを押した際、100% のケースで 100 ミリ秒以内に検索入力可能な状態でランチャーパネルが表示される。
- **SC-002**: ウィンドウ 0 件の状態からアプリ名を検索して確定する操作により、目的のインストール済みアプリケーションを 1 回の検索フローで起動できる。
- **SC-003**: ウィンドウ 0 件の状態で通常スイッチャーのショートカットを押した際、誤って空のスイッチャーパネルが表示される割合が 0% である。
- **SC-004**: 検索ランチャー上で最後のウィンドウを閉じた場合、100% のケースでパネルが閉じずに維持され、そのまま別のアプリを起動できる。
- **SC-005**: ウィンドウ 0 件状態における未入力時・検索一致時・一致 0 件時の切り替えを通じて、ランチャーパネル上端座標のズレおよび不正終了・クラッシュの発生率が 0% である。

## Assumptions

- 検索ランチャー起動時のアクセシビリティ権限チェックは従来通り維持され、権限未許可時には権限誘導画面へ案内する。
- 通常スイッチャー（`Option + Tab` 等）はウィンドウ切り替え専用機能であるため、ウィンドウ 0 件時に開かない既存仕様および最後のウィンドウを閉じた際に自動で閉じる仕様をそのまま維持する。
- 検索対象のアプリケーション収集範囲、重複排除、日本語名・英語別名検索、およびハイライト表示規則は既存のアプリ起動候補仕様（`006-launcher-app-launch`）をそのまま継承する。
- 検索キーワードが入力されているにもかかわらずウィンドウもアプリ起動候補も一致しない状態では、未入力時の「開いているウィンドウがありません」とは区別して、入力した条件に一致する候補がない旨（「一致する候補がありません」等）の案内表示を行う前提とする。
