# 機能仕様書: スイッチャーおよび検索ランチャーからの選択中ウィンドウ終了

**Feature Branch**: `005-close-selected-window`

**Created**: 2026-11-15

**Status**: Draft

**Input**: User description: "スイッチャーや検索ランチャーを立ち上げ、「Q」を押すと現在選択しているウィンドウを閉じるようにしてもらえますか。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 通常スイッチャーから現在選択中のウィンドウを閉じる (Priority: P1)

ユーザーは、通常スイッチャー（ホールド式、デフォルト `Option + Tab`）を起動してウィンドウ一覧から不要なウィンドウに選択カーソルを合わせた状態で、ホールド中のスイッチャー修飾キーを押したまま `Q` キー（デフォルト `Option + Q`）を押すだけで、該当ウィンドウへ切り替える手間なくそのウィンドウ1枚だけを即座に閉じ、パネルを開いたまま連続して他のウィンドウを整理または選択できる。

**Why this priority**: 一旦対象ウィンドウへ切り替えてから `Command + W` で閉じるという2段階の手間を省き、スイッチャー上の閲覧・整理フローの中で直接ウィンドウを連続整理できることが本機能の中核価値であるため。

**Independent Test**: 複数のウィンドウを開いた状態で通常スイッチャーを起動し、選択中のウィンドウに対してホールド中の修飾キー + `Q` を押した際に、そのウィンドウ1枚のみが閉じられ（同一アプリの他ウィンドウやアプリ自体は終了しない）、一覧から除外されてパネルが表示され続けること、および修飾キーを離すと残りの選択ウィンドウへ切り替えられることを確認できる。

**Acceptance Scenarios**:

1. **Given** 複数の通常ウィンドウ（同一アプリ内の複数ウィンドウを含む）が開いており、通常スイッチャーが起動して特定のウィンドウが選択されている状態, **When** ユーザーがスイッチャーの修飾キーを押したまま `Q` キーを押す（デフォルト `Option + Q`）, **Then** 現在選択されているウィンドウ1枚のみが閉じられ、同一アプリケーションの他のウィンドウおよびアプリケーション自体は終了せず維持される。
2. **Given** 通常スイッチャー起動中に3件以上のウィンドウが表示され、2番目のウィンドウを選択して `修飾キー + Q` を押した状態, **When** 当該ウィンドウが閉じられる, **Then** スイッチャーパネルは閉じずに表示されたまま維持され、閉じられたウィンドウが一覧から除外され、次のウィンドウ（新しい2番目）が選択状態になる（末尾の項目を閉じた場合は新しい末尾項目が選択状態になる）。
3. **Given** 通常スイッチャーで `修飾キー + Q` により連続して複数のウィンドウを閉じた後、まだ1件以上のウィンドウが残っている状態, **When** ユーザーが別のウィンドウを選択して修飾キーを離す（または `Esc` を押す）, **Then** 選択中のウィンドウへフォーカスが切り替わりパネルが閉じる（`Esc` の場合は切り替えずにパネルが閉じる）。

### User Story 2 - 検索ランチャーから現在選択中のウィンドウを閉じる (Priority: P1)

ユーザーは、検索ランチャー（トグル式、デフォルト `Option + Space`）を起動してウィンドウ一覧を表示またはキーワードで絞り込み、目的のウィンドウを選択した状態で通常スイッチャーと共通の「スイッチャー修飾キー + `Q`」（デフォルト `Option + Q`）を入力することで、検索欄への文字 `"q"` の入力と競合することなくそのウィンドウ1枚だけを直接閉じ、そのまま検索ランチャー上で続けて整理や切り替えを行える。

**Why this priority**: 検索ランチャーは開いているウィンドウが多い環境で不要なウィンドウを素早く検索・特定する場面が多いため、通常スイッチャーと完全に一貫した操作体系（スイッチャー修飾キー + `Q`）で、文字入力を妨げずにウィンドウを閉じられることが不可欠であるため。

**Independent Test**: 複数のウィンドウを開いた状態で検索ランチャーを起動し、キーワード入力中および未入力中の双方において、単体 `Q` は検索文字入力として扱われる一方、スイッチャー修飾キー + `Q`（デフォルト `Option + Q`）を押したときのみ選択中ウィンドウ1枚が閉じられ、特殊文字が検索欄に入力されずパネルと検索語が維持されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 検索ランチャーが起動し、ウィンドウ候補が1件以上表示されて特定のウィンドウが選択されている状態, **When** ユーザーが現在設定されている通常スイッチャーの修飾キーと `Q` を同時に押す（デフォルト `Option + Q`）, **Then** 選択されているウィンドウ1枚のみが閉じられ、検索入力欄には文字や記号が一切入力されず、検索ランチャーは開いたまま維持されて閉じられたウィンドウが一覧から除外される。
2. **Given** 検索ランチャーで検索キーワード（例：`"chr"`）を入力して候補が絞り込まれている状態, **When** ユーザーがスイッチャー修飾キー + `Q` を押す, **Then** 検索キーワードを維持したまま選択中ウィンドウ1枚が閉じられ、絞り込み結果からそのウィンドウが除外される（選択位置は同インデックス、末尾を閉じた場合は新しい末尾へ移動し、一致候補が0件になった場合は0件案内表示になる）。
3. **Given** 検索ランチャーの検索入力欄にフォーカスがある状態, **When** ユーザーが修飾キーなしで単体の `Q` キー（または `Shift + Q`）を入力する, **Then** ウィンドウを閉じる操作は発動せず、通常通り検索文字 `"q"`（または `"Q"`）が検索入力欄に入力される。
4. **Given** 設定画面で通常スイッチャーの修飾キーがデフォルトの `Option` から別の修飾キー（例：`Control`）に変更されている状態, **When** ユーザーが通常スイッチャーまたは検索ランチャーを起動する, **Then** 双方のモードにおいて新しい修飾キー + `Q`（例：`Control + Q`）で選択中のウィンドウを閉じることができる。

### User Story 3 - 閉じられないウィンドウ・確認ダイアログ・残余0件時の安全な振る舞い (Priority: P2)

未保存の変更があるドキュメントウィンドウや閉じる操作を受け付けないウィンドウに対してクローズ操作を実行した場合でも、アプリがクラッシュしたり変更を強制破棄してデータを失ったりすることなく、対象アプリの標準的な確認動作が尊重される。また、候補が0件になった場合も安全に状態が遷移する。

**Why this priority**: ウィンドウを閉じる操作はユーザーの作業中の状態を変更する操作であるため、未保存データの保護と境界状態での安定性が日常利用の信頼性に直結するため。

**Independent Test**: 未保存の変更を含むテキストエディタ等のウィンドウを選択してクローズ操作を実行した際にデータが強制破棄されないこと、閉じる操作非対応のウィンドウでクラッシュしないこと、および最後の1件を閉じた後や候補0件状態で安全に動作することを確認できる。

**Acceptance Scenarios**:

1. **Given** 未保存の変更があり閉じる前に保存確認を求めるウィンドウが選択されている状態, **When** ユーザーがスイッチャー修飾キー + `Q` を押す, **Then** 未保存の変更は強制破棄されず、対象アプリケーション標準の確認手順（保存確認ダイアログ等）が尊重される。
2. **Given** 一覧に残っているウィンドウが最後の1件のみであり、それが選択されている状態, **When** ユーザーがスイッチャー修飾キー + `Q` を押してそのウィンドウが閉じられたとき, **Then** 閉じられるべき残余ウィンドウが存在しないためパネルは自動的に閉じる。
3. **Given** 検索ランチャーで検索結果が0件になっている状態, **When** ユーザーがスイッチャー修飾キー + `Q` を押す, **Then** 誤って他のウィンドウやアプリ自身を閉じることなく入力が安全に消費・無視され、パネルと0件案内表示が維持される。

---

### Edge Cases

- **閉じる操作に対応していないウィンドウ**: 閉じる手段を持たない特殊な通常ウィンドウを選択してスイッチャー修飾キー + `Q` を押した場合でも、アプリが異常終了せず、そのウィンドウは一覧に残ったまま安全に状態を保つ。
- **未保存確認ダイアログ等でウィンドウが閉じずに残った場合**: ユーザーが確認ダイアログでキャンセルする等でウィンドウが閉じられなかった場合、そのウィンドウは一覧から消滅せず安全に状態が維持される。
- **検索ランチャーで検索結果が0件になった場合と全ウィンドウが0件になった場合の区別**: 検索絞り込みの結果として一時的に一致件数が0件になっただけの場合はパネルを閉じず「一致するウィンドウがありません」を表示し続ける（検索語を消せば他ウィンドウに戻れるため）。一方、開いている通常ウィンドウ自体が全件0件になった場合はパネルを自動的に閉じる。
- **通常スイッチャーで修飾キーとして `Command` を設定している場合**: `Command + Q` が macOS 標準の「アプリケーション終了」として解釈され本アプリや背面の別アプリを誤終了させることがないよう、スイッチャーまたは検索ランチャー表示中の `Command + Q` は「選択中ウィンドウ1枚を閉じる」操作として優先処理・消費されなければならない。
- **日本語配列・英語配列で `Option + Q` 等を入力したときの文字入力防止**: 検索ランチャー表示中に `Option + Q` 等が押された場合、macOS の入力システムによって特殊文字（例：`œ` 等）が検索入力欄に挿入されないよう、キーイベントをクローズ操作として確実に消費する。
- **日本語 IME で未確定文字列を入力中に検索ランチャーで操作した場合**: 修飾キーを伴わない文字・変換操作は IME 入力として妨げられず、スイッチャー修飾キー + `Q` が押された場合のみウィンドウを閉じる操作として処理される。
- **背面アプリケーションへのキーイベント漏洩防止**: パネル表示中にスイッチャー修飾キー + `Q` が入力された際、そのキーイベントが背面の別アプリケーションへ漏れて意図しないショートカットを発火させてはならない。
- **過去の仕様書における MVP スコープ記載との関係**: `001-window-switcher-mvp` の FR-017 で MVP 当時はスコープ外としていた「スイッチャー上からのウィンドウを閉じる操作」を、本仕様により後続の機能拡張として新たに追加する。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 通常スイッチャー表示中および検索ランチャー表示中の双方において、現在設定されている通常スイッチャーの必須修飾キーと `Q` キーの組み合わせ（デフォルト `Option + Q`）が押されたとき、システムは現在選択中のウィンドウを閉じる操作を実行しなければならない（MUST）。
- **FR-002**: 閉じる操作の対象は現在選択中のウィンドウ1枚のみ（ウィンドウのクローズボタン / `Command + W` 相当）とし、同一アプリケーションの他のウィンドウやアプリケーション全体の終了（Quit）を行ってはならない（MUST NOT）。
- **FR-003**: 検索ランチャー表示中において、修飾キーを伴わない単体の `Q` キー（および `Shift + Q`）は検索キーワードの文字入力としてそのまま検索入力欄へ通さなければならず、ウィンドウを閉じる操作を発動してはならない（MUST NOT）。
- **FR-004**: ウィンドウを閉じる操作の修飾キー判定は、設定画面でユーザーが保存した最新の通常スイッチャーの必須修飾キー設定に常に追従しなければならない（MUST）。
- **FR-005**: 選択中のウィンドウが閉じられた後、開いている通常ウィンドウが1件以上残っている場合、システムはパネルを閉じずに表示を維持し、閉じられたウィンドウを一覧から除外して残りの候補を表示し続けなければならない（MUST）。
- **FR-006**: ウィンドウが一覧から除外された後の選択カーソルは、除外前の同じ位置（インデックス）を維持しなければならない（MUST）。末尾の項目が閉じられてリストが短くなった場合は、新しい末尾項目を選択状態にしなければならない（MUST）。
- **FR-007**: 検索ランチャーで検索キーワードが入力されている状態でウィンドウを閉じた場合、システムは検索キーワードを維持したまま絞り込み後の候補リストから該当ウィンドウを除外しなければならない（MUST）。絞り込み結果が0件になった場合は既存の0件案内表示へ遷移し、開いている通常ウィンドウ自体が全件0件になった場合はパネルを閉じなければならない（MUST）。
- **FR-008**: 通常スイッチャー表示中に最後の1件のウィンドウを閉じて残余通常ウィンドウが0件になった場合、システムは即座にスイッチャーパネルを閉じなければならない（MUST）。
- **FR-009**: ウィンドウを閉じる操作は、未保存変更の確認ダイアログ等を強制バイパスしてデータ損失を引き起こしてはならず、対象ウィンドウ側の標準的なクローズ応答を尊重しなければならない（MUST）。また、閉じる手段を持たないウィンドウに対して操作が行われた場合もエラーやクラッシュを起こしてはならない（MUST NOT）。
- **FR-010**: パネル表示中に「スイッチャー修飾キー + `Q`」が入力された場合、システムはそのキー入力を消費し、背面の他アプリケーションへのキーイベント伝播や検索入力欄への文字・特殊文字の入力を行ってはならない（MUST NOT）。設定された修飾キーが `Command` の場合でも、`Command + Q` による本アプリ自身の誤終了を引き起こしてはならない（MUST NOT）。
- **FR-011**: 検索結果が0件の状態など選択対象ウィンドウが存在しない状態で「スイッチャー修飾キー + `Q`」が押された場合、システムは誤操作を起こさず入力のみを消費して安全に無視しなければならない（MUST）。
- **FR-012**: 本機能においても画面収録権限を一切要求・使用してはならず（MUST NOT）、アクセシビリティ権限が未許可の状態ではクラッシュせずに既存の権限誘導画面へ安全に誘導しなければならない（MUST）。

### Key Entities

- **Window Close Action（ウィンドウ終了アクション）**: スイッチャーまたは検索ランチャー上で現在選択されている1つのウィンドウ項目に対して発行される単一ウィンドウのクローズ要求。同一アプリの他ウィンドウやアプリ終了には波及せず、未保存確認やクローズ不可ウィンドウに対する安全なフォールバックを含む。
- **Active Panel Context（アクティブパネル状態）**: 現在表示されているパネル種別（通常スイッチャーまたは検索ランチャー）、現在適用中の検索キーワード（ランチャー時）、表示中のウィンドウ候補リスト、および現在の選択インデックスを表す状態。クローズ実行後のリスト再評価、選択インデックス補正、およびパネル継続／自動終了の判定基準となる。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーがスイッチャーまたは検索ランチャーでウィンドウを選択し、スイッチャー修飾キー + `Q` を押してから、対象ウィンドウへクローズ指示が送られパネル上の候補リストが更新（または最後の1件の場合はパネル終了）されるまで、100% の通常ウィンドウにおいて 200ミリ秒以内の即時応答で完了する。
- **SC-002**: 検索ランチャーで文字 `q` / `Q` を含む検索キーワードを入力した際、100% のケースで意図通り検索文字として入力でき、誤ってウィンドウが閉じられる割合が 0% である。また、スイッチャー修飾キー + `Q` を押した際に検索入力欄へ特殊文字や不要な文字が混入する割合が 0% である。
- **SC-003**: 同一アプリの複数ウィンドウのうち1枚を閉じた際、他のウィンドウおよびアプリケーション自体が維持される割合が 100% であり、未保存データの強制破棄および本アプリのクラッシュ発生率が 0% である。
- **SC-004**: パネル表示中の閉じる操作において、背面アプリケーションへの誤ったキーイベント漏洩および（`Command` 修飾キー設定時の）本アプリ誤終了の発生率が 0% である。
- **SC-005**: 既存の通常スイッチャー（起動・選択移動・確定・キャンセル）および検索ランチャー（起動・ファジー検索・候補移動・確定・キャンセル）の全操作の成功率が 100% 維持される。

## Assumptions

- **固定のショートカットキー割り当て**: 憲章の「過剰機能の排除（シンプルさの徹底）」に基づき、閉じる操作のトリガーキー `Q` は設定画面でのカスタマイズ項目としては追加せず、現在設定されている通常スイッチャーの必須修飾キーと `Q` の組み合わせとして一貫して提供する。
- **アクセシビリティ権限の利用**: ウィンドウを閉じる操作には追加の権限（画面収録権限等）は要求せず、既存のアクセシビリティ権限の範囲内で完結する。
- **過去仕様との位置づけ**: `001-window-switcher-mvp` で MVP スコープ外とされていた機能の後続拡張であるため、MVP 仕様自体の不備ではなく新機能追加として扱う。
- **クローズ処理の即時反映とアプリ側遅延**: 対象アプリケーションが未保存確認ダイアログを表示したり終了アニメーション等で即座に消滅しなかったりする場合は、対象アプリ側の標準挙動に委ねられ、本アプリは強制終了手段をとらない。
