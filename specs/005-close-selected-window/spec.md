# 機能仕様書: スイッチャーおよび検索ランチャーからの選択中ウィンドウ／アプリ終了

**Feature Branch**: `005-close-selected-window`

**Created**: 2026-11-15

**Status**: Draft

**Input**: User description: "スイッチャーや検索ランチャーを立ち上げ、「Q」を押すと現在選択しているウィンドウを閉じるようにしてもらえますか。（追加要望：同じアプリで複数ウィンドウがある場合はそのウィンドウを閉じ、一つしかウィンドウがない場合はアプリごと終了する。また、複数ウィンドウのうち未訪問の別スペースにあるウィンドウは対象スペースへ自動移動して閉じる）"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 通常スイッチャーから選択中ウィンドウを閉じる／単一ウィンドウのアプリを終了する (Priority: P1)

ユーザーは、通常スイッチャー（ホールド式、デフォルト `Option + Tab`）を起動してウィンドウ一覧から不要なウィンドウに選択カーソルを合わせた状態で、ホールド中のスイッチャー修飾キーを押したまま `Q` キー（デフォルト `Option + Q`）を押すだけで、同じアプリに複数ウィンドウがあるときは選択中のウィンドウ 1 枚だけを閉じ、ウィンドウが 1 つしかないアプリであればアプリケーション自体を終了することで、ウィンドウを閉じた後にアプリが候補へ再出現することなく作業環境を素早く整理できる。

**Why this priority**: 一旦対象ウィンドウへ切り替えてから閉じる／終了する手間を省くと同時に、最後のウィンドウを閉じたあとにバックグラウンド残存アプリが再びスイッチャー候補に現れてしまう煩わしさを解消することが、本機能の中核価値であるため。

**Independent Test**: 複数ウィンドウを持つアプリと単一ウィンドウのみのアプリを開いた状態で通常スイッチャーを起動し、前者に対して修飾キー + `Q` を押すとそのウィンドウ 1 枚のみが閉じられ（残り 1 枚になれば次の `Q` でアプリ終了）、後者に対して押すとアプリ全体が終了し、いずれの場合もパネルを開いたまま連続操作や修飾キー解放確定ができることを確認できる。

**Acceptance Scenarios**:

1. **Given** 同一アプリケーションで 2 枚以上の通常ウィンドウが開かれており、通常スイッチャーでそのうち 1 枚が選択されている状態, **When** ユーザーがスイッチャーの修飾キーを押したまま `Q` キーを押す（デフォルト `Option + Q`）, **Then** 現在選択されているウィンドウ 1 枚のみが閉じられ、同一アプリケーションの他のウィンドウおよびアプリケーション自体は終了せず維持される。
2. **Given** 同一アプリケーションで開かれている通常ウィンドウが 1 枚のみであり、通常スイッチャーでそのウィンドウが選択されている状態, **When** ユーザーがスイッチャーの修飾キーを押したまま `Q` キーを押す, **Then** 当該アプリケーション全体が通常終了（Quit 相当）され、一覧から除外される。
3. **Given** 通常スイッチャー起動中に 3 件以上のウィンドウが表示され、2 番目の項目を選択して `修飾キー + Q` を押した状態, **When** 当該ウィンドウのクローズまたはアプリ終了が完了する, **Then** スイッチャーパネルは閉じずに表示されたまま維持され、対象が一覧から除外され、次の項目（新しい 2 番目、末尾だった場合は新しい末尾）が選択状態になる。
4. **Given** 通常スイッチャーで `修飾キー + Q` により連続して整理を行った後、まだ 1 件以上のウィンドウが残っている状態, **When** ユーザーが別のウィンドウを選択して修飾キーを離す（または `Esc` を押す）, **Then** 選択中のウィンドウへフォーカスが切り替わりパネルが閉じる（`Esc` の場合は切り替えずにパネルが閉じる）。

### User Story 2 - 検索ランチャーから文字入力と競合せず選択中ウィンドウを閉じる／単一ウィンドウアプリを終了する (Priority: P1)

ユーザーは、検索ランチャー（トグル式、デフォルト `Option + Space`）を起動してウィンドウ一覧を表示またはキーワードで絞り込み、目的のウィンドウを選択した状態で通常スイッチャーと共通の「スイッチャー修飾キー + `Q`」（デフォルト `Option + Q`）を入力することで、検索欄への文字 `"q"` 入力と競合することなく単一ウィンドウクローズ／単一ウィンドウ時のアプリ終了を直接実行できる。

**Why this priority**: 検索ランチャーでは多数・複数のウィンドウやアプリから不要なものを素早く絞り込んで片付ける場面が多く、通常スイッチャーと完全に一貫した操作体系（スイッチャー修飾キー + `Q`）で、文字入力を妨げずに整理を完結できることが不可欠であるため。

**Independent Test**: 検索ランチャー起動中に単体 `Q` が検索文字入力として機能する一方、スイッチャー修飾キー + `Q` で複数ウィンドウアプリは 1 枚のみ閉じ（検索絞り込みで見えていない別ウィンドウがある場合も誤ってアプリ終了しない）、1 枚のみアプリはアプリごと終了し、検索語とパネルが維持されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 検索ランチャーが起動し、ウィンドウ候補が 1 件以上表示されて特定のウィンドウが選択されている状態, **When** ユーザーが現在設定されている通常スイッチャーの修飾キーと `Q` を同時に押す（デフォルト `Option + Q`）, **Then** 同一アプリの有効ウィンドウ数に応じて「1 枚のみクローズ」または「アプリ通常終了」が実行され、検索入力欄には文字や特殊記号が入力されず、検索ランチャーは開いたまま維持されて対象が一覧から除外される。
2. **Given** 検索ランチャーで検索キーワードを入力し、同一アプリに複数ウィンドウが開いているにもかかわらず絞り込み結果上はそのアプリが 1 件だけ表示されている状態, **When** ユーザーがスイッチャー修飾キー + `Q` を押す, **Then** 絞り込み前の全有効ウィンドウ数に基づき「複数ウィンドウあり」と判定され、アプリケーション全体は終了せず選択中のウィンドウ 1 枚のみが閉じられる。
3. **Given** 検索ランチャーで検索キーワード（例：`"chr"`）を入力して候補が絞り込まれている状態, **When** ユーザーがスイッチャー修飾キー + `Q` を押して対象が閉じられた／終了したとき, **Then** 検索キーワードを維持したまま絞り込み結果から対象が除外される（ウィンドウの一致候補が 0 件になっても他ウィンドウが残っていれば、一致するアプリ起動候補がある場合はアプリ起動候補表示、ない場合は 0 件案内表示でパネルを維持する）（※ `006-launcher-app-launch` にて改定）。
4. **Given** 検索ランチャーの検索入力欄にフォーカスがある状態, **When** ユーザーが修飾キーなしで単体の `Q` キー（または `Shift + Q`）を入力する, **Then** クローズ／終了操作は発動せず、通常通り検索文字 `"q"`（または `"Q"`）が検索入力欄に入力される。
5. **Given** 設定画面で通常スイッチャーの修飾キーがデフォルトの `Option` から別の修飾キー（例：`Control`）に変更されている状態, **When** ユーザーが通常スイッチャーまたは検索ランチャーを起動する, **Then** 双方のモードにおいて新しい修飾キー + `Q`（例：`Control + Q`）で操作を実行できる。

### User Story 3 - 別スペース自動移動・未保存確認・クローズ不可・残余0件時の安全な振る舞い (Priority: P2)

別スペースにある未取得ウィンドウに対して操作した場合も対象スペースへ切り替えて確実にクローズを実行し、かつパネルの表示状態を維持する。また、未保存の変更があるウィンドウや終了確認を求めるアプリに対して操作した場合も変更を強制破棄せず標準の確認動作を尊重し、候補が 0 件になった場合も安全に終了する。

**Why this priority**: 別スペースにあるウィンドウが閉じられないもどかしさを解消しつつ、破壊的なデータ損失や境界状態での誤終了を防ぐことが日常利用の信頼性に直結するため。

**Independent Test**: 未訪問の別スペースにある複数ウィンドウアプリの 1 枚を選択してクローズした際に自動で対象スペースへ切り替わって該当ウィンドウが閉じられパネルが維持されること、未保存変更があるアプリ・ウィンドウでデータが強制破棄されないこと、および最後の 1 件を閉じた後や候補 0 件状態で安全に動作することを確認できる。

**Acceptance Scenarios**:

1. **Given** 複数ウィンドウを持つアプリケーションの選択中ウィンドウが未訪問の別操作スペースにある状態, **When** ユーザーがスイッチャー修飾キー + `Q` を押す, **Then** システムは対象ウィンドウがある操作スペースへ一時的に切り替えてウィンドウ情報を認識した上でそのウィンドウ 1 枚を閉じ、処理完了後もスイッチャー／検索ランチャーのパネルを維持する。
2. **Given** 未保存の変更があり閉じる前または終了前に確認を求めるウィンドウ・アプリケーションが選択されている状態, **When** ユーザーがスイッチャー修飾キー + `Q` を押す, **Then** 強制終了や変更の強制破棄は行われず、対象アプリケーション標準の確認手順（保存確認ダイアログ等）が尊重される。
3. **Given** 一覧に残っているウィンドウが最後の 1 件のみであり、それが選択されている状態, **When** ユーザーがスイッチャー修飾キー + `Q` を押してそのウィンドウ（またはアプリ）の終了が完了したとき, **Then** 通常スイッチャー表示中は残余ウィンドウが 0 件となるためパネルが自動的に閉じ、検索ランチャー表示中はパネルを閉じずに維持してウィンドウ 0 件時の状態（未入力時は案内表示、検索語入力中はアプリ起動候補の再評価結果）へ遷移する（※ `010-launcher-without-windows` にて改定）。
4. **Given** 検索ランチャーで選択カーソルがアプリ起動候補上にある状態、またはウィンドウ・アプリ双方の検索結果が 0 件になっている状態, **When** ユーザーがスイッチャー修飾キー + `Q` を押す, **Then** 誤って他のウィンドウやアプリ自身を終了することなく入力が安全に消費・無視され、パネルと現在の表示状態が維持される（※ `006-launcher-app-launch` にて改定）。

---

### Edge Cases

- **同じアプリのウィンドウを 2 枚から 1 枚へ減らし、続けて残りの 1 枚へ操作した場合**: 1 回目は複数ウィンドウがあるため 1 枚のみが閉じられ、2 回目の時点ではそのアプリの有効ウィンドウが 1 枚のみとなっているためアプリケーション全体が通常終了する。
- **検索絞り込みにより表示上の件数だけ 1 件に見えている場合**: 判定基準は表示中の絞り込みリストではなく「絞り込み前のそのアプリの有効ウィンドウ総数」とし、絞り込み外のウィンドウを巻き添えにしてアプリ終了しない。
- **別スペース移動を伴うクローズ中に一時的なフォーカス移動が起きた場合**: 対象スペースへの切り替え処理に伴ってパネルが一時的にキーフォーカスを失っても、処理完了までパネルを勝手にキャンセル終了させず、クローズ完了後にパネルの前面表示・操作フォーカスを回復する。
- **閉じる操作・終了操作に対応していない、または確認ダイアログでキャンセルされた場合**: 強制終了手段は使わず、ウィンドウ／アプリが残存している場合は一覧から消滅させずに状態を保つ。
- **通常スイッチャーで修飾キーとして `Command` を設定している場合**: スイッチャーまたは検索ランチャー表示中の `Command + Q` は本アプリ（Wintch）自身を誤終了させることなく選択対象へのクローズ／終了操作として優先処理・消費される。
- **日本語配列・英語配列で `Option + Q` 等を入力したときの文字入力防止**: 検索ランチャー表示中に `Option + Q` 等が押された場合、検索入力欄へ特殊文字（例：`œ` 等）が挿入されないようキーイベントを消費する。
- **日本語 IME で未確定文字列を入力中に検索ランチャーで操作した場合**: 修飾キーを伴わない文字・変換操作は妨げず、スイッチャー修飾キー + `Q` が押された場合のみ動作する。
- **過去の仕様書における MVP スコープ記載との関係**: `001-window-switcher-mvp` の FR-017 で MVP 当時はスコープ外とされていた「スイッチャー上からのウィンドウを閉じる・アプリ終了操作」を、本仕様により後続の機能拡張として新たに追加する。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 通常スイッチャー表示中および検索ランチャー表示中の双方において、現在設定されている通常スイッチャーの必須修飾キーと `Q` キーの組み合わせ（デフォルト `Option + Q`）が押されたとき、システムは現在選択中の対象に対する終了処理を実行しなければならない（MUST）。
- **FR-002**: 選択中のウィンドウが所属するアプリケーションに、ノイズ除外後の有効な通常ウィンドウが **2 枚以上** 開かれている場合、システムは現在選択中のウィンドウ 1 枚のみを閉じ、同一アプリケーションの他ウィンドウやアプリケーション本体を終了してはならない（MUST NOT）。この判定には検索ランチャーの絞り込み結果ではなく、パネル起動時点（および直前クローズ反映後）の有効ウィンドウ一覧全体を使用しなければならない（MUST）。
- **FR-003**: 選択中のウィンドウが所属するアプリケーションで開かれている有効な通常ウィンドウが **1 枚のみ** の場合、システムはそのアプリケーション全体を通常終了（Quit 相当、強制終了ではない）しなければならない（MUST）。
- **FR-004**: 複数ウィンドウを持つアプリケーションの選択中ウィンドウが別操作スペースにあり直接情報へアクセスできない場合、システムは対象ウィンドウの操作スペースへ自動的に切り替えてウィンドウを特定した上でクローズを実行しなければならない（MUST）。その際の一時的なフォーカス移動でパネルをキャンセル終了してはならず、クローズ完了後にパネルの表示と操作状態を維持・回復しなければならない（MUST）。
- **FR-005**: 検索ランチャー表示中において、修飾キーを伴わない単体の `Q` キー（および `Shift + Q`）は検索キーワードの文字入力としてそのまま検索入力欄へ通さなければならず、クローズ／終了操作を発動してはならない（MUST NOT）。
- **FR-006**: 操作に用いる修飾キー判定は、設定画面でユーザーが保存した最新の通常スイッチャーの必須修飾キー設定に常に追従しなければならない（MUST）。
- **FR-007**: ウィンドウのクローズまたはアプリケーションの終了が完了した後、開いている有効ウィンドウが 1 件以上残っている場合、システムはパネルを閉じずに表示を維持し、対象を一覧から除外して残りの候補を表示し続けなければならない（MUST）。
- **FR-008**: 項目が一覧から除外された後の選択カーソルは、除外前の同じ位置（インデックス）を維持しなければならない（MUST）。末尾の項目が除外されてリストが短くなった場合は、新しい末尾項目を選択状態にしなければならない（MUST）。
- **FR-009**: 検索ランチャーで検索キーワードが入力されている状態で対象が除外された場合、システムは検索キーワードを維持したまま絞り込み後のウィンドウ候補および未表示のアプリ起動候補を再評価しなければならない（MUST）。最後の 1 件のウィンドウを閉じて有効ウィンドウ自体が 0 件になった場合でも、検索ランチャーはパネルを閉じずに維持し、未入力時は 0 件案内表示へ、検索語入力中はアプリ起動候補の再評価結果（または一致 0 件案内表示）へ遷移しなければならない（MUST）（※ `006-launcher-app-launch` および `010-launcher-without-windows` にて改定）。
- **FR-010**: 通常スイッチャー表示中に最後の 1 件が閉じられて残余有効ウィンドウが 0 件になった場合、システムは即座にスイッチャーパネルを閉じなければならない（MUST）。
- **FR-011**: ウィンドウのクローズおよびアプリケーションの終了は、強制終了や確認ダイアログの強制スキップによって未保存データを損失させてはならず（MUST NOT）、対象アプリケーション標準の確認応答を尊重しなければならない（MUST）。確認ダイアログ等で終了しなかった場合は一覧から除外しない。
- **FR-012**: パネル表示中に「スイッチャー修飾キー + `Q`」が入力された場合、システムはそのキー入力を消費し、背面の他アプリケーションへのキーイベント伝播や検索入力欄への文字・特殊文字の入力を行ってはならない（MUST NOT）。設定された修飾キーが `Command` の場合でも、`Command + Q` による本アプリ（Wintch）自身の誤終了を引き起こしてはならない（MUST NOT）。
- **FR-013**: 検索結果が 0 件の状態やアプリ起動候補の表示中など、閉じられるべきウィンドウ選択対象が存在しない状態で「スイッチャー修飾キー + `Q`」が押された場合、システムは誤操作を起こさず入力のみを消費して安全に無視しなければならない（MUST）（※ `006-launcher-app-launch` にて改定）。
- **FR-014**: 本機能においても画面収録権限を一切要求・使用してはならず（MUST NOT）、アクセシビリティ権限が未許可の状態ではクラッシュせずに既存の権限誘導画面へ安全に誘導しなければならない（MUST）。

### Key Entities

- **Window Close or Quit Action（ウィンドウ／アプリ終了アクション）**: スイッチャーまたは検索ランチャー上で現在選択されている項目に対して発行される終了要求。同一アプリの有効ウィンドウ数に基づき「単一ウィンドウクローズ」または「アプリケーション通常終了」のいずれかに分岐し、未訪問スペースへの自動切り替えフォールバックや未保存確認への安全配慮を含む。
- **Active Panel Context（アクティブパネル状態）**: 現在表示されているパネル種別（通常スイッチャーまたは検索ランチャー）、絞り込み前の有効ウィンドウ全件（同一アプリ件数判定の基準）、検索キーワード、表示中候補リスト、および現在の選択インデックスを表す状態。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 同一スペース上の通常ウィンドウを 1 枚閉じる操作および単一ウィンドウアプリの終了要求において、操作入力から一覧更新（または最後の 1 件終了時のパネルクローズ）まで、通常の即応ケースで 500 ミリ秒以内（単一ウィンドウクローズは 200 ミリ秒以内）に完了する。
- **SC-002**: 1 枚しかウィンドウを持たないアプリに対して操作した場合、100% の通常アプリでプロセス自体が終了し、アプリ終了後に隠しウィンドウ等がスイッチャー候補へ再出現する割合が 0% である。
- **SC-003**: 検索ランチャーで文字 `q` / `Q` を含む検索キーワードを入力した際、100% のケースで検索文字として入力でき、検索絞り込みによって見かけ上 1 件に絞られた複数ウィンドウアプリが誤ってアプリごと終了される割合が 0% である。
- **SC-004**: 複数ウィンドウアプリの未訪問別スペースにあるウィンドウに対しても、スペース自動切り替えにより操作対象を捕捉してクローズし、パネルが維持される。
- **SC-005**: 確認ダイアログを伴う未保存変更の強制破棄、背面アプリへのキーイベント漏洩、および本アプリ（Wintch）自身の誤終了の発生率が 0% である。

## Assumptions

- **固定のショートカットキー割り当て**: 憲章の「過剰機能の排除（シンプルさの徹底）」に基づき、終了操作のキーは設定画面へ追加せず、現在設定されている通常スイッチャーの必須修飾キーと `Q` の組み合わせとして一貫して提供する。
- **アクセシビリティ権限の利用**: 画面収録権限等は追加要求せず、既存のアクセシビリティ権限および標準 OS プロセス管理の範囲内で完結する。
- **別スペースへの一時移動の許容**: 別スペースの未取得ウィンドウを単体で閉じる場合、macOS の公開 API 制約上その操作スペースへの切り替えが発生し、処理後も元のスペースへ自動では戻らずそのスペース上でパネルが維持される（1 ウィンドウのみのアプリ終了時はスペース移動なしで終了する）。
- **終了処理の遅延と確認ダイアログ**: 終了確認ダイアログが表示されたり終了処理に長い時間を要したりするアプリについては、本アプリは強制終了手段をとらず対象アプリ側の標準挙動に委ねる。
