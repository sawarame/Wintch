# 機能仕様書: メモ等の非表示内部補助ウィンドウによる重複・ゴースト表示の除外

**Feature Branch**: `009-filter-hidden-ghost-windows`

**Created**: 2026-11-15

**Status**: Draft

**Input**: User description: "Mac標準のメモアプリが一つしかウィンドウを開いていなくても複数表示されていまいます。スイッチャーとランチャー両方です。原因を調べて修正方針をまとめてください。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 単一ウィンドウのみ開いているアプリで実ウィンドウ1件だけを表示する (Priority: P1)

ユーザーは、Mac 標準の「メモ」アプリなどで実際に1枚しかウィンドウを開いていない状態で通常スイッチャーまたは検索ランチャーを開いたとき、その開いているウィンドウ1件のみが一覧に表示され、実体のない「(タイトルなし)」エントリが複数並んで表示されないことを期待する。これにより、目的のウィンドウへの切り替えや「選択中のウィンドウを閉じる」操作が直感的かつ正確に動作する。

**Why this priority**: ユーザーが開いた覚えのない複数の「(タイトルなし)」ウィンドウが一覧を圧迫し、誤選択や「最後の1枚を閉じたのにアプリ終了にならない」といった操作破綻を引き起こすため、最優先で解消すべき問題である。

**Independent Test**: メモアプリのウィンドウを1枚だけ開いた状態（現在の操作スペースにある場合、および別の操作スペースにある場合の双方）で、通常スイッチャー（リスト型・キャプチャ表示型）および検索ランチャーを起動し、メモアプリのエントリが実ウィンドウの1件のみ表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** Mac 標準のメモアプリで1つのウィンドウ（例: `eco検定 – 14件のメモ`）のみが開かれている状態（現在の操作スペースまたは別の操作スペース上）, **When** ユーザーが通常スイッチャーを起動する, **Then** メモアプリのエントリは実際に開いている1件のみが表示され、「メモ (タイトルなし)」の重複エントリは一切表示されない。
2. **Given** Mac 標準のメモアプリで1つのウィンドウのみが開かれている状態, **When** ユーザーが検索ランチャーを起動する, **Then** 一覧および「メモ」での検索結果において、実際に開いている1件のみが表示され、「メモ (タイトルなし)」の重複エントリは表示されない。
3. **Given** メモアプリの実ウィンドウが1件のみ表示されている状態, **When** ユーザーが通常スイッチャーまたは検索ランチャー上でその項目に対してウィンドウ終了操作を実行する, **Then** 同アプリのウィンドウは1枚のみと正しく判定され、アプリが通常終了する。

---

### User Story 2 - ウィンドウをすべて閉じている待機中アプリの非表示補助ウィンドウを表示しない (Priority: P2)

ユーザーは、ウィンドウを1枚も開いていないにもかかわらずバックグラウンドで待機しているアプリケーション（例: Gemini、メモ、システム設定など）について、内部で保持されている画面外の未表示補助ウィンドウが「(タイトルなし)」ウィンドウとしてスイッチャーやランチャーに紛れ込まないことを期待する。

**Why this priority**: 開いているウィンドウが存在しないアプリが「(タイトルなし)」として一覧に現れると、切り替え先として機能しない空エントリが増えるだけでなく、検索ランチャーでのアプリ起動候補との区別も曖昧になるため。

**Independent Test**: ウィンドウをすべて閉じた状態で常駐起動中のアプリ（Gemini やメモなど）がある環境で通常スイッチャーおよび検索ランチャーを起動し、そのアプリの「(タイトルなし)」ウィンドウが表示されないこと、かつ検索ランチャーでは既存ウィンドウではなくアプリ起動候補として扱われることを確認できる。

**Acceptance Scenarios**:

1. **Given** 起動中だが表示中のウィンドウを1枚も持たないアプリ（Gemini やウィンドウを閉じた後のメモ等）が存在する状態, **When** ユーザーが通常スイッチャーまたは検索ランチャーを起動する, **Then** 当該アプリの「(タイトルなし)」ウィンドウエントリは一覧に表示されない。
2. **Given** 起動中だが表示中のウィンドウを1枚も持たないアプリが存在する状態, **When** ユーザーが検索ランチャーでそのアプリ名を入力して検索する, **Then** 実体のない「(タイトルなし)」ウィンドウではなく、アプリ起動候補（または開かれたウィンドウが存在しない状態）として適切に扱われる。

---

### User Story 3 - 実在する複数ウィンドウや別操作スペースのウィンドウ表示を維持する (Priority: P2)

ユーザーは、不要なゴーストウィンドウが除外される一方で、実際に自分で複数開いているウィンドウ（メモアプリで別メモを独立ウィンドウとして開いた場合や、Chrome・VS Code・Finder などで別操作スペースに複数ウィンドウを開いている場合）や、本当にタイトルが空の通常ウィンドウについては、従来通りすべて切り替え対象として表示されることを期待する。

**Why this priority**: ノイズ除外を強めすぎると別スペースの実ウィンドウが一覧から消える退行（リグレッション）を起こす恐れがあるため、実ウィンドウの捕捉精度を損なわないことを同時に保証する必要がある。

**Independent Test**: メモアプリで複数ウィンドウを明示的に開いた場合、および別操作スペースに複数ウィンドウを持つ他アプリが存在する場合に、通常スイッチャーと検索ランチャーの両方で開いている実ウィンドウの枚数と一致する件数が表示され、選択して切り替えられることを確認できる。

**Acceptance Scenarios**:

1. **Given** メモアプリでメインウィンドウに加えて別のメモを独立ウィンドウとして開き、合計2枚以上の実ウィンドウが存在する状態, **When** ユーザーが通常スイッチャーまたは検索ランチャーを起動する, **Then** 実際に開かれている実ウィンドウの枚数分のエントリのみが表示され、それ以上の「(タイトルなし)」ゴーストは表示されない。
2. **Given** 別の操作スペースに実ウィンドウを開いている他アプリ（Google Chrome、VS Code、Finder など）が存在する状態, **When** ユーザーが通常スイッチャーまたは検索ランチャーを起動する, **Then** 別操作スペース上の実ウィンドウは従来通り欠落なく一覧に表示され、選択して切り替えることができる。

---

### Edge Cases

- **対象アプリが現在の操作スペースではなく別操作スペースにある場合**: 別スペースにある1枚の実ウィンドウが正しく1件として維持され、画面外の内部補助ウィンドウ（既定サイズ500×500の初期裏方ウィンドウやアプリ固有の非表示パネル等）が増殖しないこと。
- **対象アプリが起動直後またはウィンドウ全閉後の状態**: 開かれている実ウィンドウが0枚になった際に、裏方の非表示ウィンドウだけが1〜2件残って一覧に表示されないこと。
- **システム設定以外のアプリで標準サイズの非表示裏方ウィンドウが生成される場合**: 特定アプリ1種だけでなく、同様の構造で生成されるアプリ横断の非表示補助ウィンドウが一貫して除外されること。
- **ウィンドウ一覧メニューに個別ウィンドウ項目を持たないアプリの場合**: メニュー項目からのタイトル照合が利用できないアプリであっても、未表示の裏方候補が「(タイトルなし)」として無制限に通過しないこと。
- **ユーザーが実際に開いたタイトル未設定（「無題」や空タイトル）の通常ウィンドウ**: ユーザーが視認・操作可能な実ウィンドウとして開いているものは誤って除外されないこと。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、通常スイッチャー（リスト型およびキャプチャ表示型）および検索ランチャーに表示するウィンドウ一覧を構築する際、ユーザーが実際に開いていない非表示の内部補助ウィンドウ（画面外に保持される既定サイズのバックキングウィンドウおよびアプリ内部の未表示パネル等）を除外しなければならない（MUST）。
- **FR-002**: システムは、Mac 標準の「メモ」アプリで1枚のみウィンドウを開いている場合（現在の操作スペース・別操作スペースのいずれにある場合でも）、スイッチャーおよびランチャーの双方において実ウィンドウ1件のみを表示し、追加の「(タイトルなし)」エントリを表示してはならない（MUST NOT）。
- **FR-003**: システムは、特定アプリの個別例外に過度に依存せず、システム全体で共通して発生する画面外の未表示バックキングウィンドウ（画面左端・既定サイズ500×500相当で実ウィンドウ属性を持たない候補等）をアプリ横断で除外しなければならない（MUST）。
- **FR-004**: システムは、ウィンドウ一覧メニューから開いている実ウィンドウ一覧を取得できないアプリ（メモアプリやシステム設定等）においても、実ウィンドウが捕捉済みである状態や実体のない画面外候補によって、実在しない「(タイトルなし)」ウィンドウが追加表示されないよう制御しなければならない（MUST）。
- **FR-005**: システムは、不要な補助ウィンドウの除外処理を行う際も、実際に別操作スペース上で開かれている他アプリの実ウィンドウ、複数ウィンドウを開いたメモアプリの各実ウィンドウ、および最小化中の実ウィンドウを誤って除外してはならない（MUST NOT）。
- **FR-006**: システムは、通常スイッチャーおよび検索ランチャーの双方で同一のウィンドウ候補フィルタリング結果を共有し、表示件数・タイトル・閉じる操作（単一ウィンドウ時のアプリ終了判定を含む）の整合性を一貫して維持しなければならない（MUST）。

### Key Entities

- **ウィンドウ候補（Window Candidate）**: 画面上の各アプリケーションから収集された、表示対象とするか判定される前のウィンドウ情報。実ウィンドウとしての属性有無、画面上の可視状態、位置・サイズ、所有アプリ情報、タイトル情報を持つ。
- **表示対象ウィンドウ項目（Displayed Window Entry）**: フィルタリングを通過し、通常スイッチャーおよび検索ランチャーの一覧に表示され、選択・切り替え・終了操作の対象となる実ウィンドウ項目。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Mac 標準のメモアプリでウィンドウを1枚のみ開いた状態（同スペース・別スペース両方）において、通常スイッチャーおよび検索ランチャーに表示されるメモアプリの項目数が 100% のケースで 1 件になる。
- **SC-002**: ウィンドウをすべて閉じて待機しているアプリ（Gemini、メモ、システム設定など）の「(タイトルなし)」ゴースト項目が、通常スイッチャーおよび検索ランチャーの一覧に 0 件となる。
- **SC-003**: メモアプリで複数ウィンドウを明示的に開いた場合および別操作スペースにウィンドウを持つ主要アプリ（Chrome、VS Code、Finder 等）が存在する場合において、表示件数の欠落や過剰重複が発生しない（実ウィンドウ数との一致率 100%）。
- **SC-004**: 本修正の追加後も、既存のウィンドウフィルタリング・検索・並び替え・閉じる操作に関する自動テストがすべて 100% 合格し、体感表示速度の劣化がない。

## Assumptions

- 画面収録権限を一切要求・使用しない基本動作（リスト型スイッチャーおよび検索ランチャー）の原則を維持し、アクセシビリティ情報・ウィンドウの可視および座標メタデータ・アプリメニュー情報のみを用いて判定を行う。
- プラットフォームの非公開機能は一切使用しない。
- スイッチャーとランチャーの双方で共通のウィンドウ収集・フィルタリング結果を利用しているため、対象判定ロジックの修正により両モードの重複表示が同時に解消される。
