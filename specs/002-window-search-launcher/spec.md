# 機能仕様書: ウィンドウ検索ランチャーモード

**Feature Branch**: `002-window-search-launcher`

**Created**: 2026-11-13

**Status**: Draft

**Input**: User description: "ランチャーのような検索入力ボックスを開き、現在開いているウィンドウを検索・絞り込みして切り替えられる機能を実装する。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ランチャー検索によるウィンドウの絞り込みと切り替え (Priority: P1)

ユーザーは、開いているウィンドウ数が多い場合でも、専用のショートカットで検索入力欄付きのランチャーパネルを開き、アプリケーション名やウィンドウタイトルの一部・略称を入力して目的のウィンドウを素早く絞り込み、キーボード操作のみでフォーカスを切り替えることができる。

**Why this priority**: 既存の順番送りスイッチャー（`Option + Tab`）ではウィンドウ数が増えると目的のウィンドウに到達するまでのキー押下回数が増える。検索入力による直接的な絞り込みこそが本機能の中核的な提供価値であるため。

**Independent Test**: 複数のアプリケーションおよび複数ウィンドウを開いた状態でランチャーショートカット（デフォルト `Option + Space`）を押し、修飾キーを離してもパネルが開いたまま検索欄にフォーカスされること、文字入力でファジー検索とハイライト表示が行われること、`Enter` で対象ウィンドウへ切り替えられること、および `Esc` またはショートカット再押下でキャンセルできることを確認できる。

**Acceptance Scenarios**:

1. **Given** 複数の通常ウィンドウが開かれており、直前にウィンドウA、その前にウィンドウBがアクティブだった状態, **When** ユーザーがランチャーショートカット（デフォルト `Option + Space`）を押してキーを離す, **Then** 画面に検索入力欄付きのランチャーパネルが開いたまま維持され、検索入力欄に自動フォーカスが当たり、全ウィンドウ一覧が直近アクティブ順（MRU）で表示され、2番目の項目（ウィンドウB）が初期選択される。
2. **Given** ランチャーパネルが開いており検索入力欄にフォーカスがある状態, **When** ユーザーが検索キーワード（例：`"vsc"` やスペース区切りの `"chr git"`）を入力する, **Then** アプリケーション名およびウィンドウタイトルを対象にスペース区切り AND のファジー検索で候補が絞り込まれ、一致スコア順（同スコア時は MRU 順）に並び替わり、選択カーソルが先頭項目（1番目）へ移動し、一致した文字が太字・ハイライト表示される。
3. **Given** ランチャーパネル上で検索結果または一覧が表示されている状態, **When** ユーザーが `↑` / `↓` または `Ctrl + N` / `Ctrl + P` を押す, **Then** 選択カーソルが上下に循環移動する。
4. **Given** ランチャーパネル上で目的のウィンドウが選択されている状態, **When** ユーザーが `Enter` キーを押す（または対象行をクリックする）, **Then** パネルが閉じ、選択されていたウィンドウ（別操作スペース・別ディスプレイ・最小化ウィンドウを含む）が最前面にアクティブ化される。
5. **Given** ランチャーパネルが開いている状態, **When** ユーザーが `Esc` キーを押す、ランチャーショートカットを再度押す、またはパネル外をクリックする, **Then** ウィンドウ切り替えは実行されず、元のアクティブウィンドウのまま即座にパネルが閉じる。
6. **Given** ランチャーパネルの検索入力欄で日本語 IME による変換入力（未確定文字列または変換候補表示中）を行っている状態, **When** ユーザーが `Enter`・`Esc`・`↑`・`↓` を押す, **Then** ウィンドウ確定やパネル終了・リスト移動ではなく IME の確定・キャンセル・候補選択操作が優先される。

### User Story 2 - 検索中のパネル位置安定性と 0 件時のフィードバック (Priority: P2)

ユーザーは、文字を入力して候補数がリアルタイムに増減する際も検索入力欄の位置が画面上で上下に動かず安定してタイピングを続けられ、一致するウィンドウがない場合も状態を把握して即座に入力を修正できる。

**Why this priority**: 検索中にパネルが上下へ跳ねると視線と入力体験が大きく損なわれ、0件時にパネルが閉じたり無反応になったりすると文字の打ち直しができなくなるため、実用的なランチャー体験に不可欠である。

**Independent Test**: 10件以上のウィンドウが開いた状態でランチャーを開き、一致件数が段階的に減って 0 件になり、バックスペースで再び増える一連の入力を行った際、パネルの上端位置と検索入力欄の位置が動かず下端のみが伸縮すること、および 0 件時に「一致するウィンドウがありません」と表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** ランチャーパネルが開いている状態, **When** ユーザーの検索入力によって一致するウィンドウの件数が減少または増加する, **Then** パネル起動時の上端位置を固定したままリスト領域の高さだけが下方向に伸縮し、検索入力欄の位置は移動しない。
2. **Given** ランチャーパネルが開いている状態, **When** どのウィンドウにも一致しない検索文字列が入力される, **Then** パネルと検索入力欄は開いたまま維持され、リスト領域に「一致するウィンドウがありません」というメッセージが表示される。
3. **Given** 0件メッセージが表示されている状態, **When** ユーザーが `Enter` キーを押す, **Then** 誤ってウィンドウ切り替えが発生せず、パネルはそのまま維持される。

### User Story 3 - ランチャーショートカットのカスタマイズと双方向競合防止 (Priority: P2)

ユーザーは既存の通常スイッチャー（`Option + Tab` / 逆順 `Option + Shift + Tab`）を従来通り維持したまま、設定画面のショートカットレコーダーを使ってランチャーの起動ショートカットを好みのキー組み合わせに変更でき、通常スイッチャーとの重複設定も確実に防止される。

**Why this priority**: 既存の `Option + Shift + Tab`（逆順移動）の操作体系を壊さずにランチャーを共存させ、他アプリや OS 標準ショートカットとの干渉をユーザー自身で回避できるようにするため。

**Independent Test**: 設定画面を開き、ランチャー用のショートカットレコーダーに有効なショートカット（例：`Control + Space`）を記録して変更後のキーでランチャーが起動すること、修飾キーなし入力が拒否されること、`Esc` で記録がキャンセルされること、および通常スイッチャー（順方向・逆方向）と重複する組み合わせが双方の設定 UI でブロックされエラー表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 設定画面が開かれている状態, **When** ユーザーがランチャーショートカットのレコーダーを選択して有効なキー組み合わせ（例：`Control + Space`）を入力する, **Then** 新しいショートカットが保存・反映され、以降は変更後のショートカットでランチャーを起動・トグル終了できる。
2. **Given** ランチャーショートカットのレコーダーが入力待機中の状態, **When** ユーザーが修飾キー（`Command` / `Option` / `Control`）を1つも含まないキー、または `Shift` のみとの組み合わせを入力する, **Then** 登録は受け付けられず、有効な修飾キーが必要である旨のエラーメッセージが表示される。
3. **Given** ランチャーショートカットのレコーダーが入力待機中の状態, **When** ユーザーが `Esc` キーを押す, **Then** 変更は適用されず元のショートカット設定のまま記録モードが終了する。
4. **Given** 通常スイッチャーが `Option + Tab`（逆順：`Option + Shift + Tab`）に設定されている状態, **When** ユーザーがランチャーレコーダーに `Option + Tab` または `Option + Shift + Tab` を入力する, **Then** 重複エラーが表示されて登録がブロックされ、元のランチャーショートカットが維持される。
5. **Given** ランチャーが `Option + Space` に設定されている状態, **When** ユーザーが通常スイッチャー側の設定を `Option + Space` へ変更しようとする, **Then** 重複エラーが表示されて変更がブロックされ、通常スイッチャーの既存設定が保存・維持される。

---

### Edge Cases

- **一方のモード表示中に他方のショートカットが押された場合**: 通常スイッチャー表示中にランチャーショートカットが押された場合、またはランチャー表示中に通常スイッチャーのショートカットが押された場合は、他方のショートカット入力を無視して現在のモードを維持する。
- **開いている通常ウィンドウが 0 件の状態でランチャーを起動しようとした場合**: 操作可能な通常ウィンドウが 1 件も存在しない状態では空のパネルを表示せず、エラーも起こさない。
- **開いている通常ウィンドウが 1 件のみの場合**: ランチャー起動時の初期選択状態は 1 番目（唯一のウィンドウ）となる。
- **ウィンドウタイトルが空のウィンドウ**: タイトルが空（表示上「(タイトルなし)」）のウィンドウであっても、アプリケーション名でのファジー検索によりヒットし、ハイライト表示および切り替え対象として選択できる。
- **通常の `Option + Shift + Tab` 操作の維持**: ランチャー機能の追加後も、通常スイッチャーの逆順起動・逆順選択移動（修飾キー + `Shift` + トリガーキー）は従来通り機能する。
- **アクセシビリティ権限未許可時の起動**: 権限が取り消された状態でランチャーショートカットが押された場合、クラッシュせず既存の権限誘導画面へ安全にフォールバックする。
- **最小権限の原則の維持**: ランチャーの検索対象・表示要素には引き続き画面収録権限を使用せず、ウィンドウのサムネイルプレビューも表示しない。

## Requirements *(mandatory)*

### Functional Requirements

#### 起動・ライフサイクルとモード共存
- **FR-001**: システムはランチャーモード（検索入力モード）のデフォルト起動ショートカットとして `Option + Space` を提供しなければならない（MUST）。
- **FR-002**: ランチャーショートカットが押されたとき、パネルはトグル方式で動作し、修飾キーを離した後も開いた状態を維持し、検索入力欄に自動的にキーボードフォーカスを与えなければならない（MUST）。
- **FR-003**: 既存の通常スイッチャーにおける逆順ショートカット（`修飾キー + Shift + トリガーキー`、デフォルト `Option + Shift + Tab`）の動作は変更せず維持しなければならない（MUST）。
- **FR-004**: 通常スイッチャーまたはランチャーのいずれか一方が表示中の間は、もう一方の起動ショートカットが押されても無視しなければならない（MUST）。
- **FR-005**: ランチャー表示中に `Esc` キー、ランチャーショートカットの再押下、またはパネル外クリックが行われた場合、ウィンドウを切り替えずに即座にパネルを閉じなければならない（MUST）。

#### 検索・絞り込み・ハイライト・操作
- **FR-006**: ランチャーの検索欄が未入力の状態では、開いている通常ウィンドウ全件（ノイズウィンドウ除外済み）を直近アクティブ順（MRU）で表示し、2件以上の場合は2番目の項目、1件のみの場合は1番目の項目を初期選択しなければならない（MUST）。
- **FR-007**: 検索欄に文字が入力された場合、システムは各ウィンドウの「アプリケーション名」および「ウィンドウタイトル」を対象として、スペース区切りの全キーワードに一致する（AND 条件）大文字小文字を区別しないファジー検索を実行しなければならない（MUST）。
- **FR-008**: 絞り込まれた結果は一致スコアの高い順に並び替え、同一スコアの場合は直近アクティブ順（MRU）を維持しなければならない（MUST）。
- **FR-009**: 検索文字列が入力されて候補が更新された際、一致する候補が 1 件以上あれば選択カーソルを先頭項目（1番目）へ自動移動しなければならない（MUST）。
- **FR-010**: 検索結果の各行において、検索キーワードと一致した文字箇所を視覚的に識別できるよう太字・ハイライト表示しなければならない（MUST）。
- **FR-011**: ランチャー表示中、ユーザーは `↑` / `↓` 矢印キーおよび `Ctrl + N` / `Ctrl + P` で選択カーソルを循環移動し、`Enter` キーまたは行クリックで選択中のウィンドウへフォーカスを切り替えてパネルを閉じることができなければならない（MUST）。
- **FR-012**: 検索入力欄で日本語 IME 等による変換中（未確定入力・候補選択中）に押された `Enter`、`Esc`、`↑`、`↓` は、ランチャーの確定・終了・選択移動よりも IME の入力処理を優先しなければならない（MUST）。

#### レイアウト安定性と空状態
- **FR-013**: ランチャーパネルは既存のフローティングウィンドウリストの上部に検索入力欄を統合した構成で表示し、候補件数の変化に応じてパネルの上端位置を固定したまま下方向のみに高さを伸縮させなければならない（MUST）。
- **FR-014**: 検索条件に一致するウィンドウが 0 件の場合、パネルを閉じずにリスト領域へ「一致するウィンドウがありません」という状態メッセージを表示しなければならない（MUST）。

#### 設定・ショートカットレコーダーと競合防止
- **FR-015**: 設定画面において、ユーザーはショートカットレコーダーを用いて実際のキー入力によりランチャーショートカットを変更・保存できなければならない（MUST）。
- **FR-016**: ランチャーショートカットとして登録できるキー組み合わせは、`Command` / `Option` / `Control` のうち最低1つの修飾キーを含む必要があり、修飾キーなしまたは `Shift` のみの組み合わせは拒否しなければならない（MUST）。また、記録中の `Esc` キー押下は記録のキャンセルとして扱わなければならない（MUST）。
- **FR-017**: システムは通常スイッチャーの起動ショートカット（順方向および `Shift` 併用の逆方向）とランチャーの起動ショートカットの重複を許可してはならない（MUST NOT）。レコーダー側で重複入力があった場合、および通常スイッチャー設定側でランチャーと重複する組み合わせを選択しようとした場合の双方において、変更をブロックしてエラーメッセージを表示し、既存設定を維持しなければならない（MUST）。

#### プライバシー・権限原則の継承
- **FR-018**: ランチャー機能においても画面収録権限を一切要求・使用してはならず（MUST NOT）、アクセシビリティ権限未許可時はクラッシュせずに既存の権限誘導画面へ安全に誘導しなければならない（MUST）。

### Key Entities

- **LauncherShortcutPreference（ランチャーショートカット設定）**: ランチャーモードを起動・トグル終了するためのキー組み合わせを表す概念。任意のキー識別子、必須修飾キー（`Command` / `Option` / `Control`）および併用修飾キー（`Shift`）の組み合わせ、画面表示用ラベルの属性を持ち、アプリ再起動後も永続化される。
- **WindowSearchResult（ウィンドウ検索結果）**: ファジー検索によって評価された個別のウィンドウ項目を表す概念。対象の `WindowEntry`、算出された一致スコア、およびアプリケーション名・ウィンドウタイトル内で一致した文字位置範囲（ハイライト描画用）の属性を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーがランチャーショートカットを押してから検索入力可能な状態でランチャーパネルが表示されるまでの体感遅延がなく、100ミリ秒以内に文字入力を受け付けられる。
- **SC-002**: 50個以上のウィンドウが開いている環境で1文字入力または削除するたびに、候補の絞り込み・スコア順ソート・一覧再描画が100ミリ秒以内に完了し、タイピングの引っかかりが発生しない。
- **SC-003**: 検索キーワードによる候補数の増減を通じて、検索入力欄の垂直座標（パネル上端）のズレが 0 ポイントのまま維持される。
- **SC-004**: 通常スイッチャー（順方向・逆方向）と重複するショートカットの組み合わせを設定画面から登録しようとした際、100%のケースで重複が検知・ブロックされ、意図しない動作競合が発生しない。
- **SC-005**: 日本語 IME を用いた検索入力において、変換確定の `Enter` や変換キャンセルの `Esc` で誤ってウィンドウ切り替えやパネル終了が発動する割合が 0% である。
- **SC-006**: 画面収録権限がオフ（未許可）の状態であっても、ランチャーの起動・検索・切り替えの全機能が制限なく 100% 動作する。

## Assumptions

- **ファジー検索のスコアリング基準**: 連続一致、単語境界（スペース・記号・大文字小文字境界）での一致、先頭一致、およびアプリ名一致に対して高いスコアを与え、同スコア時のタイブレークには既存の MRU 順位を用いることで直感的なランキングを実現する。
- **ハイライト表示の範囲**: 検索欄のキーワードがウィンドウタイトルまたはアプリケーション名に一致した場合に、該当文字を太字またはアクセント色で強調表示する（タイトルが空の場合は「(タイトルなし)」という補助表示テキスト自体は検索・ハイライト対象とせず、アプリケーション名のみを対象とする）。
- **重複ブロック時の初期設定変更**: 初期状態は通常スイッチャー `Option + Tab`（逆順 `Option + Shift + Tab`）、ランチャー `Option + Space` であり、初期状態で重複しない構成とする。
- **アクセシビリティ権限**: 既存の通常スイッチャーと同じく、ランチャーのグローバルショートカット監視およびウィンドウ一覧取得・切り替えには macOS のアクセシビリティ権限を使用する。
