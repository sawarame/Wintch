本ガイドは、Wintch MVP のビルド、ユニットテスト実行、および macOS 実機上でのエンドツーエンド動作検証手順を示します。

---

## 1. 前提条件

- **OS**: macOS 14.0 (Sonoma) 以降
- **ツールチェーン**: Swift 6 以降（Xcode または Apple Command Line Tools）
- **権限**: 画面収録権限は不要（オフのままで検証すること）。アクセシビリティ権限は実機動作確認時に許可・未許可の両パターンを検証する。

---

## 2. ビルドおよび自動テストの実行

リポジトリルートから Swift Package Manager を用いて、外部依存なしでビルドおよび純粋ドメインロジック・ViewModel のユニットテストを実行します。

```bash
# プロジェクトのビルド
swift build

# ユニットテストの実行（ノイズ除外、MRUソート、ショートカット判定、選択状態遷移）
swift test
```

**期待される結果**:
- 警告・エラーなくコンパイルが完了すること。
- すべてのユニットテストがパスすること（GUIやOSアクセシビリティ権限がなくても高速に完了すること）。

---

## 3. `.app` バンドルの組み立てと起動

メニューバー常駐（`LSUIElement`）、アクセシビリティ権限（TCC）、およびログイン時自動起動（`SMAppService`）を実機検証するため、ビルドした実行バイナリを `.app` バンドルとしてパッケージ化して起動します。

```bash
# .app バンドルを生成してビルド（ビルドスクリプト導入後に実行）
./scripts/build-app.sh

# アプリの起動
open .build/Wintch.app
```

---

## 4. エンドツーエンド動作検証シナリオ

### シナリオ A: 権限未許可時の安全なフォールバックと誘導（User Story 2）
1. 「システム設定 > プライバシーとセキュリティ > アクセシビリティ」で Wintch が未登録またはオフであることを確認する。
2. `Wintch.app` を起動する。
3. **期待結果**: アプリがクラッシュせず、権限誘導画面が表示される。「システム設定を開く」ボタンをクリックするとアクセシビリティ設定画面が直接開く。
4. 設定で Wintch をオンにする。
5. **期待結果**: 誘導画面が自動的に閉じ、切り替え機能が有効化される。

### シナリオ B: ウィンドウ単位・操作スペース横断切り替え（User Story 1）
1. 複数の操作スペース（仮想デスクトップ）を用意し、同じブラウザやエディタで複数ウィンドウを開いておく。
2. 画面収録権限が許可されていない状態であることを確認する。
3. `Option` キーを押したまま `Tab` キーを押す。
4. **期待結果**:
   - 画面収録権限を求めるダイアログは一切表示されない。
   - 画面中央にフローティングパネルが表示され、MRU順で2番目のウィンドウが選択状態になる。
   - メニューバー要素や非表示要素などのノイズが表示されない。
5. `Option` を押したまま `Tab`（次へ）および `Shift + Tab`（前へ）で選択を移動し、別の操作スペースにあるウィンドウを選択して `Option` キーを離す。
6. **期待結果**: パネルが閉じ、該当の操作スペースへ自動で移動して対象ウィンドウが最前面にアクティブ化される。
7. 再度パネルを開き、`Esc` キーを押す。
8. **期待結果**: 切り替えは実行されず、元のウィンドウのままパネルが閉じる。

### シナリオ C: メニューバー常駐と設定カスタマイズ（User Story 3）
1. Dock に Wintch のアイコンが表示されておらず、メニューバーにアイコンが表示されていることを確認する。
2. メニューバーアイコンから「設定を開く...」をクリックする。
3. 修飾キーを `Control`、トリガーキーを `Space` に変更する。
4. 「ログイン時に自動起動」をオンにする。
5. **期待結果**:
   - `Control + Space` でスイッチャーが起動し、`Option + Tab` は元のOS動作に戻る。
   - 「システム設定 > 一般 > ログイン項目」に Wintch が登録される。
6. メニューバーアイコンから「Wintch を終了」を選択し、アプリが安全に終了することを確認する。
