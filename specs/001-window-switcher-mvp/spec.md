# 機能仕様書: Wintch ウィンドウ単位スイッチャー (MVP)

**Feature Branch**: `001-window-switcher-mvp`

**Created**: 2026-11-13

**Status**: Draft

**Input**: User description: "macOS向けのシンプルで軽量なウィンドウ単位の切り替えアプリ「Wintch」のMVP（最小限の製品）を構築します。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - キーボード操作によるウィンドウ単位の高速切り替え (Priority: P1)

ユーザーは同じアプリケーションの複数ウィンドウや異なる操作スペース（仮想デスクトップ）にまたがるウィンドウを、キーボードショートカットのみで素早く一覧確認し、目的のウィンドウへ直接フォーカスを切り替えることができる。

**Why this priority**: アプリケーション単位ではなく「ウィンドウ単位」で、かつ画面収録権限を必要とせず軽量・高速に切り替えることこそが本製品の最大の存在意義であり、MVPの中核となる提供価値であるため。

**Independent Test**: 複数のアプリケーションおよび同一アプリケーションの複数ウィンドウ（別操作スペース上のウィンドウを含む）を開いた状態で、デフォルトショートカット（`Option + Tab`）を押してパネルを表示し、選択移動・確定・キャンセルの各操作が期待通りに動作することを確認できる。

**Acceptance Scenarios**:

1. **Given** 複数の通常ウィンドウが開かれており、直前にウィンドウA、その前にウィンドウBがアクティブだった状態, **When** ユーザーが `Option + Tab` を押す（`Option` キーは押したままにする）, **Then** 画面中央にフローティングパネルが表示され、ウィンドウ一覧が直近アクティブ順（MRU）に縦型リストで並び、デフォルトで2番目の項目（ウィンドウB）が選択状態になる。
2. **Given** フローティングパネルが表示されており、`Option` キーを押したままの状態, **When** ユーザーが `Tab` キーを押す, **Then** 選択カーソルが次のウィンドウへ移動する（末尾に達した場合は先頭に戻る）。
3. **Given** フローティングパネルが表示されており、`Option` キーを押したままの状態, **When** ユーザーが `Shift + Tab` を押す, **Then** 選択カーソルが前のウィンドウへ逆順に移動する（先頭にある場合は末尾に戻る）。
4. **Given** フローティングパネル上で目的のウィンドウが選択されている状態, **When** ユーザーが修飾キー（`Option`）を離す, **Then** パネルが即座に閉じ、選択されていたウィンドウが最前面にアクティブ化される。
5. **Given** 選択されたウィンドウが現在表示中の操作スペースとは別の操作スペースにある状態, **When** ユーザーが修飾キーを離して確定する, **Then** 該当の操作スペースへ自動的に移動し、対象ウィンドウが最前面にアクティブ化される。
6. **Given** フローティングパネルが表示されている状態, **When** ユーザーが `Esc` キーを押す, **Then** ウィンドウの切り替えは実行されず、元のアクティブウィンドウのままパネルが閉じる。
7. **Given** システムのメニューバー要素や非表示のバックグラウンド要素が存在する状態, **When** ユーザーがスイッチャーを起動する, **Then** それらのノイズとなる要素は除外され、ユーザーが操作対象とする通常ウィンドウのみが「アプリアイコン」「アプリケーション名」「ウィンドウタイトル」の形式で表示される。

### User Story 2 - アクセシビリティ権限の確認と安全な誘導 (Priority: P1)

初回起動時や権限取り消し時など、ウィンドウ一覧の取得とキーボード操作の監視に必要なアクセシビリティ権限が許可されていない状態でも、アプリはクラッシュすることなくユーザーに権限の必要性と許可手順をわかりやすく案内し、システム設定画面へ誘導する。

**Why this priority**: macOS環境でウィンドウ切り替えとグローバルショートカットを動作させるための前提条件であり、権限未許可時にアプリが動作不能・無反応になったり異常終了したりすることを防ぐ必須の安全機構であるため。

**Independent Test**: macOSのシステム設定で本アプリのアクセシビリティ権限をオフにした状態でアプリを起動し、エラーやクラッシュなしに権限誘導画面が表示され、案内ボタンから「システム設定 > プライバシーとセキュリティ > アクセシビリティ」画面を開けることを確認できる。権限をオンにした後、即座に（または最小限の操作で）ウィンドウ切り替え機能が利用可能になることを確認できる。

**Acceptance Scenarios**:

1. **Given** 本アプリにアクセシビリティ権限が付与されていない状態, **When** ユーザーがアプリを起動する（または権限が必要な操作を行う）, **Then** 権限が未許可であることを検知し、権限が必要な理由と許可手順を説明する誘導画面が表示される。
2. **Given** 権限誘導画面が表示されている状態, **When** ユーザーが「システム設定を開く」アクションを実行する, **Then** macOSの「システム設定 > プライバシーとセキュリティ > アクセシビリティ」画面が直接開かれる。
3. **Given** 権限誘導画面が表示されている状態, **When** ユーザーがシステム設定で本アプリのアクセシビリティ権限を許可する, **Then** アプリは権限付与を検知して誘導を完了し、ウィンドウ切り替え機能が有効化される。

### User Story 3 - メニューバー常駐と基本設定のカスタマイズ (Priority: P2)

ユーザーはDockやCmd+Tabの邪魔にならないメニューバー常駐アプリとして本製品をバックグラウンドで維持でき、メニューバーから設定画面を開いて起動ショートカットの組み合わせやログイン時の自動起動を好みに合わせて変更できる。

**Why this priority**: 普段の作業環境を邪魔せずに常駐させる使い勝手と、他のショートカットとの競合を避けるためのカスタマイズ性は日常利用の定着に不可欠であるが、まずはデフォルト設定（US1）と権限案内（US2）が動作した上で付加価値を提供する要素であるため。

**Independent Test**: アプリを起動してDockにアイコンが表示されずメニューバーにアイコンが表示されることを確認し、メニューから「設定画面を開く」を選択してショートカットを別の組み合わせ（例：`Control + Space`）および自動起動ONに変更した後、変更したショートカットでスイッチャーが起動すること、およびメニューから「アプリを終了する」で終了できることを確認できる。

**Acceptance Scenarios**:

1. **Given** アプリが起動している状態, **When** ユーザーがDockと画面上部のメニューバーを確認する, **Then** Dockにはアプリアイコンが表示されず、メニューバーに専用アイコンが表示されている。
2. **Given** メニューバーアイコンが表示されている状態, **When** ユーザーがメニューバーアイコンをクリックする, **Then** 「設定画面を開く」と「アプリを終了する」を含むメニューが表示される。
3. **Given** 設定画面が開かれている状態, **When** ユーザーが修飾キー（`Option` / `Control` / `Command`）とトリガーキー（`Tab` / `Space` / バッククォート等）の組み合わせを変更する, **Then** 設定が保存され、以降は新しく設定したショートカットでスイッチャーの起動と選択移動が行える。
4. **Given** 設定画面が開かれている状態, **When** ユーザーが「ログイン時に自動起動」のON/OFFを切り替える, **Then** OSのログイン項目設定に反映され、設定状態が保持される。
5. **Given** メニューバーメニューが開かれている状態, **When** ユーザーが「アプリを終了する」を選択する, **Then** アプリが安全に終了する。

---

### Edge Cases

- **開いているウィンドウが0個の場合**: 操作可能な通常ウィンドウが1つも存在しない状態で起動ショートカットが押された場合、空のパネルは表示せず（または操作不要として無視し）、エラーを起こさない。
- **開いているウィンドウが1個のみの場合**: 操作可能な通常ウィンドウが1つだけ存在する場合、起動時は1番目（唯一のウィンドウ）が選択状態になり、修飾キーを離すとそのウィンドウにフォーカスが維持されたままパネルが閉じる。
- **ウィンドウタイトルが空のウィンドウ**: ウィンドウタイトルを持たない通常ウィンドウが存在する場合でも、アプリケーション名とアプリアイコンが表示され、クラッシュせずに切り替え対象として選択できる。
- **システム標準ショートカットとの競合**: ユーザーが設定画面で変更できるショートカットには、単体キーや修飾キーなしの組み合わせを許可せず、必ず指定の修飾キーとトリガーキーのペアで構成されるようにする（例：`Command + Tab` 等を設定した場合はOS標準の挙動と競合しないようショートカット入力を適切に制御する、または競合への注意を案内する）。
- **マルチディスプレイ環境・フルスクリーンウィンドウ**: 別ディスプレイやフルスクリーン用の独立した操作スペースにあるウィンドウを選択して確定した場合も、対象の操作スペース・ウィンドウへ適切にフォーカスが移動する。
- **起動中の権限剥奪**: アプリ常駐中にユーザーがシステム設定からアクセシビリティ権限をオフにした場合、次回ショートカット押下時または状態検知時にクラッシュせず、権限未許可の誘導画面へ安全にフォールバックする。
- **パネル表示中のフォーカス喪失（マウスクリック等）**: パネル表示中にユーザーがパネル外をクリックしたり他のシステムイベントでフォーカスが外れたりした場合、意図しないウィンドウ切り替えを実行せず安全にパネルを閉じる。

## Requirements *(mandatory)*

### Functional Requirements

#### 常駐とライフサイクル
- **FR-001**: システムはDockにアプリアイコンを表示せず、macOSのメニューバー常駐アプリとして動作しなければならない（MUST）。
- **FR-002**: メニューバーアイコンのクリックにより、「設定画面を開く」および「アプリを終了する」のメニュー項目を提供しなければならない（MUST）。
- **FR-003**: システムは設定画面から「ログイン時に自動起動（Launch at Login）」のON/OFFを切り替えられる機能を提供し、設定状態を永続化しなければならない（MUST）。

#### 権限管理とプライバシー
- **FR-004**: システムは画面収録権限（Screen Recording）を一切要求または使用してはならない（MUST NOT）。ウィンドウのサムネイル画像プレビューは取得・表示しない。
- **FR-005**: システムはアクセシビリティ権限の許可状態を起動時および実行時に検知しなければならない（MUST）。
- **FR-006**: アクセシビリティ権限が未許可の場合、システムはクラッシュやサイレント失敗をせず、権限許可の手順案内と「システム設定 > プライバシーとセキュリティ > アクセシビリティ」画面を開くための誘導UIを表示しなければならない（MUST）。

#### ウィンドウ一覧の取得・整理と表示
- **FR-007**: システムは現在表示中の操作スペースだけでなく、すべての仮想デスクトップ（操作スペース）に存在する操作可能な通常ウィンドウを一覧取得しなければならない（MUST）。
- **FR-008**: システムはメニューバーのシステムUI、非表示のバックグラウンド要素、透明な補助レイヤーなど、ユーザーが切り替え対象としないノイズウィンドウを一覧から除外しなければならない（MUST）。
- **FR-009**: スイッチャーUIは画面中央のフローティングパネルとして表示し、各ウィンドウにつき「アプリアイコン」「アプリケーション名」「ウィンドウタイトル」のみで構成される縦型リストを表示しなければならない（MUST）。
- **FR-010**: ウィンドウ一覧は「直近でアクティブだった順（MRU: Most Recently Used）」にソートして表示しなければならない（MUST）。
- **FR-011**: ウィンドウが2つ以上存在する場合、スイッチャー起動時の初期選択状態はリストの2番目（直前まで使用していたウィンドウ）としなければならない（MUST）。ウィンドウが1つのみの場合は1番目を選択する。

#### キーボード操作とショートカット制御
- **FR-012**: システムはデフォルトの起動ショートカットとして `Option + Tab` を提供しなければならない（MUST）。
- **FR-013**: 修飾キーを押したままトリガーキーを押すことで次のウィンドウへ選択を移動し、`Shift` キーを併用することで逆順（前のウィンドウ）へ選択を移動できなければならない（MUST）。
- **FR-014**: 修飾キーを離した瞬間にフローティングパネルを閉じ、選択中のウィンドウを最前面にアクティブ化しなければならない（MUST）。選択ウィンドウが別の操作スペースにある場合は、自動的に該当の操作スペースへ移動しなければならない（MUST）。
- **FR-015**: パネル表示中に `Esc` キーが押された場合、ウィンドウ切り替えをキャンセルしてパネルを閉じなければならない（MUST）。
- **FR-016**: 設定画面において、ユーザーは起動ショートカットの「修飾キー（`Option` / `Control` / `Command`）」および「トリガーキー（`Tab` / `Space` / バッククォート等）」の組み合わせを変更・保存できなければならない（MUST）。

#### スコープ境界（MVPで実装しない項目）
- **FR-017**: MVPにおいては、ウィンドウのサムネイルプレビュー表示、スイッチャー上からのウィンドウを閉じる・最小化・アプリ終了操作、テキスト入力によるインクリメンタルサーチ、特定アプリの除外設定（ブラックリスト）、仮想デスクトップ番号のバッジ表示、テーマやフォントの外観カスタマイズ機能は提供しない。

### Key Entities

- **WindowEntry（ウィンドウ項目）**: 切り替え対象となる1つのウィンドウを表す概念。識別子、ウィンドウタイトル、所属アプリケーション名、アプリアイコン、直近アクティブ順位、所属する操作スペースとの関連性などの属性を持つ。
- **ShortcutPreference（ショートカット設定）**: ユーザーが選択したスイッチャー起動・操作用キーの組み合わせを表す概念。修飾キー（`Option` / `Control` / `Command`）とトリガーキー（`Tab` / `Space` / バッククォート等）の属性を持ち、アプリ再起動後も永続化される。
- **AppPreferences（アプリ基本設定）**: ログイン時自動起動の有効・無効など、アプリ全体の設定状態を保持する概念。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーが起動ショートカットを押してからフローティングパネルが画面中央に表示されるまでの体感遅延がなく、操作から100ミリ秒以内に一覧が視認可能な状態で提示される。
- **SC-002**: ユーザーが修飾キーを離してから選択されたウィンドウ（同一スペースおよび別スペースを含む）へフォーカスが切り替わり始めるまでの反応が、200ミリ秒以内に開始される。
- **SC-003**: 常駐待機状態（スイッチャー非表示時）のCPU使用率は実質0%（1%未満）を維持し、日常的なバックグラウンド常駐でバッテリー消費やシステム負荷に影響を与えない。
- **SC-004**: 画面収録権限がオフ（未許可）の状態であっても、すべてのMVP機能が制限なく100%動作し、OSから画面収録権限を求めるダイアログが一切表示されない。
- **SC-005**: アクセシビリティ権限が未許可の状態でアプリを起動した場合、100%のケースでクラッシュせずに誘導画面が表示され、ユーザーは迷うことなく3ステップ以内でシステム設定の該当箇所へ到達できる。
- **SC-006**: ノイズウィンドウ除外ロジックにより、通常のデスクトップ作業環境において一覧に表示される項目のうち、ユーザーが意図しないシステムUIやバックグラウンド要素の混入率が0%である。

## Assumptions

- **対象ユーザーとOS環境**: ユーザーは macOS 14.0 (Sonoma) 以降の環境を使用しており、macOS標準のアクセシビリティ権限付与操作を行えることを前提とする。
- **ショートカット操作の基本動作**: パネル表示中は、設定したショートカットの組み合わせ（トリガーキーおよび `Shift` + トリガーキー）のほかに、直感的な補助操作としてキーボードの上下矢印キーでの選択移動やマウスクリックでの確定をサポートしてもよいが、主たる体験は「修飾キーを押しながらトリガーキーで選択し、離して確定する」操作フローとする。
- **トリガーキーの選択肢**: 「Tab / Space / バッククォート等」については、誤操作やシステム干渉が少なくウィンドウ切り替えに適した代表的なキー（例：`Tab`、`Space`、`` ` ``（バッククォート）、`\` 等）を選択肢として設定画面に用意する。
- **MRU（直近アクティブ順）の記録範囲**: アプリが常駐を開始してから検知したウィンドウのアクティブ履歴をもとにMRU順序を構築する。アプリ起動直後（履歴蓄積前）に存在するウィンドウについては、システムの現在のウィンドウ重なり順（フロントからバックへの順序）を初期MRU順として扱う。
- **ノイズウィンドウの定義**: タイトルバーや通常ウィンドウ属性を持たないメニューバーアイテム、通知センター、壁紙、ドック、および実体のないバックグラウンドプロセスの補助ウィンドウなどを「ノイズウィンドウ」とみなして除外対象とする。
