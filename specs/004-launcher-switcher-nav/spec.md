# 機能仕様書: 検索ランチャー表示中の通常スイッチャーショートカットによる候補移動

**Feature Branch**: `004-launcher-switcher-nav`

**Created**: 2026-11-14

**Status**: Draft

**Input**: User description: "検索ランチャーを起動した状態で通常スイッチャーのショートカットが入力された時はウィンドウリストの「次へ」「前へ」と動作するように修正してもらえますか。これについて過去の仕様の修正の必要があれば修正をお願いします。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 検索ランチャー表示中に通常スイッチャーショートカットで候補を次へ・前へ移動する (Priority: P1)

ユーザーは、検索ランチャーを開いてウィンドウ一覧の確認やキーワードによる絞り込みを行っている最中に、矢印キーへ手を移動させることなく、普段から使い慣れている通常スイッチャーのショートカット（順方向および `Shift` 併用の逆方向、デフォルトは `Option + Tab` / `Option + Shift + Tab`）を入力して候補リストの選択カーソルを「次へ」「前へ」と移動し、そのまま目的のウィンドウを選択・確定できる。

**Why this priority**: ユーザーが最も頻繁に操作する通常スイッチャーのショートカット（`Option + Tab` / `Option + Shift + Tab` 等）の操作習慣をそのまま検索ランチャー内の候補移動に適用できることが、本変更の中核的な利便性向上であるため。

**Independent Test**: 複数のウィンドウを開いた状態で検索ランチャーを起動し、通常スイッチャーの順方向・逆方向ショートカットを単発および連続で入力した際に選択カーソルが「次へ」「前へ」と循環移動すること、修飾キーを離してもランチャーが閉じないこと、検索入力欄に不要な文字が入力されないこと、および `Enter` で選択中のウィンドウへ切り替えられることを確認できる。

**Acceptance Scenarios**:

1. **Given** 3件以上の通常ウィンドウが開いており、検索ランチャーが起動している状態（初期選択は2番目の項目）, **When** ユーザーが通常スイッチャーの順方向ショートカット（デフォルト `Option + Tab`）を押す, **Then** 検索ランチャーが開いたまま維持され、ウィンドウリストの選択カーソルが次の項目（3番目）へ移動し、検索入力欄には文字やタブが入力されない。
2. **Given** 検索ランチャーが起動し、表示中リストの最後の項目が選択されている状態, **When** ユーザーが通常スイッチャーの順方向ショートカットを押す, **Then** 選択カーソルはリストの先頭項目（1番目）へ循環移動する。
3. **Given** 検索ランチャーが起動し、任意の項目が選択されている状態, **When** ユーザーが通常スイッチャーの逆方向ショートカット（`Shift` 併用、デフォルト `Option + Shift + Tab`）を押す, **Then** 選択カーソルが前の項目へ移動する（先頭項目が選択されていた場合は末尾項目へ循環移動する）。
4. **Given** 検索ランチャー上で通常スイッチャーのショートカットを押して選択カーソルを移動した状態, **When** ユーザーがその操作に使用した修飾キー（例：`Option`）を離す, **Then** ウィンドウ切り替えは自動確定されず、検索ランチャーは開いたまま維持される。
5. **Given** 検索ランチャーで検索キーワードを入力して候補が複数件に絞り込まれている状態, **When** ユーザーが通常スイッチャーの順方向または逆方向ショートカットを押す, **Then** 現在の検索キーワードと絞り込み結果を保持したまま、絞り込み後のリスト内で選択カーソルが「次へ」または「前へ」に移動する。

### User Story 2 - カスタマイズ済みショートカットへの追従と通常モード共存の維持 (Priority: P2)

ユーザーは、設定画面で通常スイッチャーのショートカットをデフォルト以外の組み合わせに変更している場合でも、検索ランチャー起動中は変更後のショートカットで候補移動を行える。また、通常スイッチャー起動中に検索ランチャーのショートカットが押された場合は従来通り無視され、既存の通常スイッチャー体験が損なわれない。

**Why this priority**: ユーザーごとのショートカット設定差分で挙動が破綻しないこと、および既存の通常スイッチャーモード側の安全性（意図しないモード遷移の防止）を維持することが、安定した日常利用に不可欠であるため。

**Independent Test**: 設定画面で通常スイッチャーのショートカットを変更した後に検索ランチャーを起動し、変更後の順方向・逆方向ショートカットで候補を「次へ」「前へ」に移動できること、および通常スイッチャーを表示している最中に検索ランチャーのショートカットを押しても無視されて通常スイッチャーが維持されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 設定画面で通常スイッチャーのショートカットが別の有効な組み合わせ（例：`Control + ` `）に変更されている状態, **When** 検索ランチャーを起動して変更後の順方向または `Shift` 併用の逆方向ショートカットを押す, **Then** 設定変更に追従して検索ランチャー内の選択カーソルが「次へ」または「前へ」に移動する。
2. **Given** 通常スイッチャー（ホールド式）が起動して表示されている状態, **When** ユーザーが検索ランチャーの起動ショートカット（デフォルト `Option + Space`）を押す, **Then** 検索ランチャーへは切り替わらず、ランチャーショートカットは無視されて通常スイッチャーの表示と選択状態がそのまま維持される。

---

### Edge Cases

- **検索結果が 0 件の状態で通常スイッチャーショートカットが押された場合**: 「一致するウィンドウがありません」と表示された空状態を維持し、ショートカット入力を安全に消費して検索欄や背面アプリへ漏らさず、エラーや誤確定を起こさない。
- **候補が 1 件のみ表示されている状態で通常スイッチャーショートカットが押された場合**: 順方向・逆方向いずれを入力しても先頭項目（1番目）を選択した状態を維持し、検索ランチャーは開いたまま保たれる。
- **日本語 IME で未確定文字列を入力中に通常スイッチャーショートカットが押された場合**: 検索欄の未確定文字列を確定・消去したり余分な文字を挿入したりすることなく、表示中の候補リストの選択移動を行い、IME 入力状態と検索ランチャーを維持する（`Enter`・`Esc`・`↑`・`↓` に対する IME 優先ルールは従来通り維持する）。
- **トリガーキーを押し続けてキーリピートが発生した場合**: 連続した「次へ」または「前へ」の選択移動として処理され、検索欄や背面アプリへキー入力が漏れない。
- **過去の仕様書における相互無視ルールとの整合性**: `002-window-search-launcher` の仕様書等に定義されていた「ランチャー表示中に通常スイッチャーショートカットを無視する」記述は、本仕様に合わせて改定・整合化される。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 検索ランチャー表示中に、現在設定されている通常スイッチャーの順方向ショートカット（デフォルト `Option + Tab`）が入力された場合、システムは検索ランチャーモードを維持したまま、表示中のウィンドウリストの選択カーソルを次の項目へ移動しなければならない（MUST）。末尾項目が選択中の場合は先頭項目へ循環移動しなければならない（MUST）。
- **FR-002**: 検索ランチャー表示中に、現在設定されている通常スイッチャーの逆方向ショートカット（`必須修飾キー + Shift + トリガーキー`、デフォルト `Option + Shift + Tab`）が入力された場合、システムは検索ランチャーモードを維持したまま、表示中のウィンドウリストの選択カーソルを前の項目へ移動しなければならない（MUST）。先頭項目が選択中の場合は末尾項目へ循環移動しなければならない（MUST）。
- **FR-003**: 検索ランチャー表示中に通常スイッチャーの順方向または逆方向ショートカットが入力された場合、システムはそのキー入力を選択移動操作として消費し、検索入力欄への文字・制御文字の入力や背面アプリケーションへのキーイベント伝播を行ってはならない（MUST NOT）。
- **FR-004**: 検索ランチャー表示中に通常スイッチャーのショートカットを入力したあと、その操作に用いた修飾キーを離しても、システムはウィンドウの切り替え確定や検索ランチャーの終了を行ってはならない（MUST NOT）。検索ランチャーの確定および終了は既存の操作（`Enter`・行クリック・`Esc`・ランチャーショートカット再押下・パネル外クリック）のみで実行されなければならない（MUST）。
- **FR-005**: 検索キーワードによる絞り込みが行われている状態で通常スイッチャーのショートカットが入力された場合、システムは検索キーワードおよび絞り込み結果を維持したまま、絞り込み後の候補リスト内で選択カーソルを「次へ」または「前へ」に移動しなければならない（MUST）。
- **FR-006**: 表示中の候補リストが 0 件の状態で通常スイッチャーのショートカットが入力された場合、システムはエラーや誤確定を起こさず、選択インデックスを変更しないまま入力を消費し、検索ランチャーと 0 件案内表示を維持しなければならない（MUST）。
- **FR-007**: 検索ランチャー表示中に反応する通常スイッチャーの順方向・逆方向ショートカット判定は、設定画面でユーザーが保存した最新の通常スイッチャーショートカット設定に常に追従しなければならない（MUST）。
- **FR-008**: 通常スイッチャー表示中に検索ランチャーの起動ショートカットが入力された場合は、従来仕様通り検索ランチャーへの切り替えを行わず、ランチャーショートカットを無視して通常スイッチャーモードを維持しなければならない（MUST）。
- **FR-009**: 過去の仕様書（`002-window-search-launcher`）におけるランチャー表示中の通常スイッチャーショートカットの扱いを本仕様の内容へ改定し、仕様ドキュメント間の整合性を確保しなければならない（MUST）。

### Key Entities

- **通常スイッチャーショートカット設定**: 通常スイッチャーの起動および候補移動に用いられる順方向（必須修飾キー + トリガーキー）と逆方向（必須修飾キー + `Shift` + トリガーキー）のキー組み合わせ設定。検索ランチャー表示中の「次へ」「前へ」移動でも共通の基準として参照される。
- **ランチャー表示中候補リストと選択カーソル**: 検索ランチャー上に現在表示されているウィンドウ候補の一覧（未入力時は直近アクティブ順の全件、入力時は一致スコア順の絞り込み結果）および現在選択中の位置。通常スイッチャーショートカットの入力に応じて一覧件数の範囲内で循環移動する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 検索ランチャー表示中に通常スイッチャーの順方向または逆方向ショートカットを入力してから選択カーソルが「次へ」「前へ」へ移動して視覚的に反映されるまで、100%のケースで 100ミリ秒以内の即時応答で完了する。
- **SC-002**: 検索ランチャー表示中に通常スイッチャーショートカットを単発または連続で使用した際、検索入力欄への不要な文字混入および修飾キー解放による誤確定の発生率が 0% である。
- **SC-003**: 候補が 0 件・1 件・複数件、および通常スイッチャーショートカットをカスタマイズした状態を含むすべての利用条件において、既存の矢印キー・`Ctrl + N` / `Ctrl + P` による移動および通常スイッチャー側の起動・切り替え機能が 100% 維持される。
- **SC-004**: 既存の機能仕様書（`002-window-search-launcher`）および関連契約・設計文書において、本仕様と矛盾する「ランチャー中の通常ショートカット無視」の記述が 0 件である。

## Assumptions

- 通常スイッチャーと検索ランチャーのショートカットは設定画面の双方向競合防止機構により互いに重複しない前提とする。万一外部変更等で両設定が重複した状態になっていた場合でも、検索ランチャー表示中はランチャー自身のトグル終了操作が優先される。
- 検索ランチャー表示中の既存の候補移動手段（`↑` / `↓` 矢印キー、`Ctrl + N` / `Ctrl + P`）および確定・キャンセル手段（`Enter`、行クリック、`Esc`、ランチャーショートカット再押下、パネル外クリック）は本変更後もすべてそのまま維持される。
- 日本語 IME の変換候補操作等で用いられる `Enter`・`Esc`・`↑`・`↓` キーの IME 優先挙動は従来仕様通り維持され、グローバルショートカットとして横取りする通常スイッチャーショートカットとは干渉しない。
