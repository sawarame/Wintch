# 機能仕様書: セキュア入力（パスワード入力欄等）フォーカス中のショートカット起動と安定復帰

**Feature Branch**: `013-fix-secure-input-hotkey`

**Created**: 2026-11-17

**Status**: Draft

**Input**: User description: "Issue #15 対応: ブラウザ（Chrome / Edge 等）のパスワード入力フォーム等のセキュア入力フォーカス中でも、ショートカット（既定 Option+Tab / Option+Space）でウィンドウ切り替え・検索ランチャーを起動・全操作できるようにし（セキュア入力中は一時アクティブ化）、フォーカス解除後の入力不能状態も防ぐ。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - パスワード入力欄にフォーカス中でも通常スイッチャーを起動して全操作・切り替えできる (Priority: P1)

ユーザーは、Web ブラウザ（Chrome、Microsoft Edge 等）やパスワード管理画面などでパスワード入力フォームにフォーカスを置いている最中であっても、通常スイッチャーのショートカット（既定 `Option + Tab`、逆順 `Option + Shift + Tab`）を押したときに他の画面にいるときと同じようにスイッチャーが開き、候補の移動・キャンセル・ウィンドウ終了・確定切り替えまで一貫して行えることを期待する。

**Why this priority**: Issue #15 で報告された中核症状であり、パスワード入力中にウィンドウ切り替え（パスワード確認のために別アプリへ移る操作など）が一切できなくなるのは実用上の大きな障害となるため。

**Independent Test**: ブラウザでパスワード入力欄にフォーカスを置いた状態から通常スイッチャーのショートカットを押し、パネル表示、順方向・逆方向移動、矢印キー移動、`Esc` キャンセル（元アプリへのフォーカス復帰）、修飾キー + `Q` でのウィンドウ終了、および修飾キー解放による確定切り替えがすべて期待通りに動作することで検証できる。

**Acceptance Scenarios**:

1. **Given** ブラウザのパスワード入力フォームにフォーカスがあり、OS のセキュア入力保護が有効になっている状態, **When** ユーザーが通常スイッチャーのショートカット（例：`Option + Tab`）を押す, **Then** スイッチャーパネルが一時的に最前面のアクティブ状態で表示され、最初の切り替え候補が選択される。
2. **Given** セキュア入力中に通常スイッチャーが起動された状態, **When** 修飾キーを保持したままトリガーキー追加押下（`Shift` 併用での逆順を含む）、上下左右矢印キー移動、または修飾キー + `Q` による選択ウィンドウ終了を行う, **Then** すべての操作が通常時と同様に反応し、背面ブラウザへキー操作が漏れない。
3. **Given** セキュア入力中に通常スイッチャーが起動された状態, **When** ユーザーが保持していた修飾キーを離す, **Then** 選択中のウィンドウが最前面にアクティブ化されて切り替わり、パネルが閉じる。
4. **Given** セキュア入力中に通常スイッチャーが起動された状態, **When** ユーザーが `Esc` キーを押す（またはパネル外をクリックする）, **Then** ウィンドウ切り替えは行われずパネルが閉じ、直前にフォーカスしていた元のアプリケーションへフォーカスが戻る。

### User Story 2 - パスワード入力欄にフォーカス中でも検索ランチャーを起動・検索・切り替えできる (Priority: P1)

ユーザーは、パスワード入力フォームにフォーカスしている状態からでも検索ランチャーのショートカット（既定 `Option + Space`）で検索ランチャーを開き、検索文字列の入力、候補選択、ウィンドウ切り替え、およびキャンセルを行えることを期待する。

**Why this priority**: 通常スイッチャーと同じ原因で検索ランチャーも起動できなくなるため、両方のショートカット経路を同等に救済する必要がある。

**Independent Test**: ブラウザのパスワード入力欄にフォーカスした状態で検索ランチャーショートカットを押し、検索入力欄へ文字入力してウィンドウを切り替えられること、および `Esc` または再押下でキャンセルした際に直前アプリへフォーカスが戻ることで検証できる。

**Acceptance Scenarios**:

1. **Given** ブラウザのパスワード入力フォームにフォーカスがある状態, **When** ユーザーが検索ランチャーのショートカット（例：`Option + Space`）を押す, **Then** 検索ランチャーが表示されて検索入力欄にフォーカスが当たり、続けて日本語 IME を含む検索入力や候補移動、確定切り替えができる。
2. **Given** セキュア入力中に検索ランチャーを起動した状態, **When** ユーザーが `Esc` キーまたは検索ランチャーショートカットを再押下してキャンセルする, **Then** パネルが閉じ、直前にフォーカスしていた元のアプリケーションへフォーカスが戻る。

### User Story 3 - フォーカス解除後にセキュア入力状態が残留する場合や監視状態が揺らいだ場合でも使い続けられる (Priority: P1)

ユーザーは、ブラウザのパスワード入力欄からフォーカスを外した後（あるいはタブ切替・自動入力ポップアップ操作の後）にブラウザ側でセキュア入力保護の解除が遅れたり残ったりした場合でも、しばらく一切操作不能になることなく引き続きショートカットでスイッチャーを起動できることを期待する。また、実際に権限が剥奪されたわけではない一時的な状態変化によって誤って権限エラー画面が出たり監視が永久停止したりしないことを期待する。

**Why this priority**: Issue #15 の「フォーカスを外しても稀にしばらく使えなくなってしまう」という現象を解消し、長時間常用しても安定して動作する信頼性を確保するため。

**Independent Test**: セキュア入力状態がフォーカス移動後も残存するケースを再現した状態で通常スイッチャー／検索ランチャーのショートカットを繰り返し操作し、無反応期間や誤った権限停止に陥らず起動・切り替えできることで検証できる。

**Acceptance Scenarios**:

1. **Given** パスワード入力欄からフォーカスを外した直後であっても、ブラウザ側の事情でセキュア入力保護状態がシステム上に一時的に残存している状態, **When** ユーザーが通常スイッチャーまたは検索ランチャーのショートカットを押す, **Then** セキュア入力中と同様に代替起動経路が機能し、待ち時間なくスイッチャーまたはランチャーが起動する。
2. **Given** セキュア入力保護の有効／無効が短時間に連続して切り替わる状態（パスワード表示切替や自動入力ポップアップの開閉など）, **When** 保護状態が切り替わった後にショートカットを押す, **Then** 監視状態が永久停止したり権限未許可と誤判定されたりすることなく、通常通りの操作へ自動復帰する。

### User Story 4 - 通常時の操作感維持・ショートカット設定変更との整合・二重発火防止 (Priority: P2)

ユーザーは、パスワード入力欄以外の通常作業時にはこれまで通り裏アプリのフォーカスを不必要に奪わず軽快に動作し、1 回のキー押下で候補が 2 つ進むような二重反応も起きないことを期待する。また、設定画面でショートカットを変更・記録している最中に誤起動しないことを期待する。

**Why this priority**: セキュア入力対策の副次機能追加によって、99% を占める通常利用時の体感やショートカット変更機能が劣化・誤動作しないことを保証するため。

**Independent Test**: 通常アプリ作業中にスイッチャーを連続操作して二重移動や不要なフォーカス変更が起きないこと、および設定画面で通常ショートカット・ランチャーショートカットを変更・記録した直後から通常時・セキュア入力時ともに新しいショートカットのみが有効になることで検証できる。

**Acceptance Scenarios**:

1. **Given** セキュア入力保護が有効ではない通常のアプリケーションを使用している状態, **When** ユーザーが通常スイッチャー（例：`Option + Tab`）を押す, **Then** 1 回の押下につき候補が 1 つだけ進み（二重発火せず）、通常スイッチャー確定前まで裏アプリのアクティブ状態は従来通り維持される。
2. **Given** ユーザーが設定画面で通常スイッチャーまたは検索ランチャーのショートカットを別のキー組み合わせへ変更した状態, **When** 通常時およびセキュア入力保護中の双方で新しいショートカットを押す, **Then** 新しいショートカットが即座に有効化されて動作し、古いショートカットには反応しない。
3. **Given** ユーザーが設定画面で新しいショートカットを記録待機している状態, **When** 登録したいキー組み合わせを押す, **Then** スイッチャーやランチャーが裏で誤起動することなく、新しいショートカットとして正しく記録される。

---

### Edge Cases

- **ショートカット押下直後の極めて素早い修飾キー解放**: セキュア入力中にショートカット（例：`Option + Tab`）を押し、パネル表示や一時アクティブ化が完了するより前のごく短時間に修飾キーを離した場合でも、解放を取りこぼしてパネルが開きっぱなしにならず、次のウィンドウへ確定切り替えされること。
- **セキュア入力解除タイミングとの競合**: ショートカット押下とほぼ同時にセキュア入力が解除された場合でも、通常経路と代替経路の両方が重複発火して候補が 2 つ進んだり、逆にどちらも無視して無反応になったりしないこと。
- **同じショートカットを連続押下した場合**: セキュア入力中に起動したあと、同じセッション中に続けてトリガーキー（順方向・`Shift` 逆順）を連打しても、滑らかに候補が移動すること。
- **`Command + Tab` 等、OS 標準機能が最優先で予約しているショートカットが設定されている場合**: セキュア入力保護下では OS 標準機能（アプリスイッチャーやシステム検索等）がシステム側で最優先処理されるため、代替経路で上書きできないキー組み合わせが存在する。そのようなショートカットを設定している場合でもアプリが異常終了したり通常時の動作が壊れたりしないこと。
- **アクセシビリティ権限が実際に取り消された場合**: セキュア入力による一時的なイベント遮断と、システム設定での実際の権限取り消しを混同せず、実際に権限が失われた場合のみ安全に監視を停止して権限誘導画面を表示すること。
- **設定画面で `Shift` を含む通常ショートカット以外の任意の修飾キー組み合わせに変更した場合**: `Control`・`Option`・`Command` の複数修飾キーの組み合わせや任意トリガーキーを設定しても、通常時・セキュア入力時ともに整合した判定が行われること。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、パスワード入力フォーム等によって OS のセキュア入力保護が有効化されている状態であっても、通常スイッチャー（順方向および `Shift` 併用の逆順）および検索ランチャーの起動ショートカットを検知し、それぞれのパネルを起動できなければならない（MUST）。
- **FR-002**: システムは、セキュア入力保護が有効な状態で通常スイッチャーが起動された場合、表示中の一連の操作（追加のトリガーキー押下による順／逆移動、上下左右矢印キー移動、`Esc` キャンセル、修飾キー + `Q` による選択ウィンドウ終了、および修飾キー解放による確定）をすべて利用可能にするため、一時的に自アプリをアクティブ化して入力制御を受け取れるようにしなければならない（MUST）。
- **FR-003**: システムは、セキュア入力保護下での一時アクティブ化によって起動した通常スイッチャーまたは検索ランチャーが、ウィンドウ切り替え以外の理由（`Esc` キーやパネル外クリック等）でキャンセルされた場合、直前にフォーカスしていた元のアプリケーションへフォーカスを復元しなければならない（MUST）。
- **FR-004**: システムは、セキュア入力保護が有効でない通常のアプリケーション操作中には、通常スイッチャー起動時に不要な自アプリ前面化（アクティブ化）を行わず、従来の軽快なフォーカス非奪取動作を維持しなければならない（MUST）。
- **FR-005**: システムは、通常時の監視経路とセキュア入力時向けの代替起動経路を併用するにあたり、1 回のショートカット押下で 2 重に起動・候補移動イベントが発生しないよう重複発火を防止しなければならない（MUST）。
- **FR-006**: システムは、セキュア入力保護が有効な状態で起動ショートカットが押され、その直後に極めて短時間で修飾キーが離された場合でも、修飾キー解放の取りこぼしによる「確定されないままパネルが残る」状態を防ぎ、確実に切り替え確定または終了を行わなければならない（MUST）。
- **FR-007**: システムは、設定画面におけるショートカット変更（通常スイッチャー・検索ランチャーの双方）を代替起動経路にも即時反映し、変更前のショートカットを無効化するとともに、ショートカット記録待機中はすべての起動経路を一時停止して誤起動を防止しなければならない（MUST）。
- **FR-008**: システムは、ブラウザ等によるセキュア入力保護の解除遅延・一時的残留や監視イベントの揺らぎが発生しても、実際の権限剥奪が起きていない限り監視を永久停止させず、通常状態への自動復旧または代替経路での継続動作を維持しなければならない（MUST）。
- **FR-009**: システムは、OS 標準機能がセキュア入力下で最優先予約しているショートカット（例：`Command + Tab` 等）への代替登録が OS 側で制限される場合であっても、クラッシュや設定不整合を起こさず安全に通常時の監視を継続しなければならない（MUST）。
- **FR-010**: システムは、本機能追加にあたり画面収録権限を一切追加要求せず、かつ外部サードパーティ製ライブラリや非公開 OS 機能を使用しないものとする（MUST）。

### Key Entities

- **セキュア入力状態（Secure Input State）**: パスワード入力欄等へのフォーカスに伴い OS 全体で通常のキーボード監視が制限されているか否かの状態。ブラウザ等のフォーカス遷移遅延によりフォーカス解除後も一時的に維持されることがある。
- **ショートカット起動経路（Shortcut Trigger Channel）**: 通常時の全キー監視経路と、セキュア入力保護下でも利用可能な代替ホットキー受付経路の 2 系統。重複排除された単一のユーザー操作として統合される。
- **直前アクティブアプリ参照（Previous Frontmost Application）**: セキュア入力中の一時アクティブ化を伴ってスイッチャー／ランチャーを開いた際、キャンセル時にフォーカスを戻す対象となる元のアプリケーション情報。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ブラウザ（Chrome / Microsoft Edge 等）のパスワード入力フォームにフォーカスした状態で通常スイッチャーの既定ショートカット（`Option + Tab`）を押した場合、パネルが体感遅延なく（0.2 秒以内）表示され、候補移動・`Esc` キャンセル・ウィンドウ終了・修飾キー解放による切り替え確定のすべての操作が 100% 期待通り完了する。
- **SC-002**: パスワード入力フォームにフォーカスした状態で検索ランチャーの既定ショートカット（`Option + Space`）を押した場合も、100% ランチャーが起動し検索・切り替え・キャンセル後の元アプリ復帰が完了する。
- **SC-003**: パスワード入力欄からのフォーカス解除直後や複数回のフォーカス往復を行った後でも、ショートカットが無反応状態のまま固着する発生件数が 0 件になる。
- **SC-004**: 通常アプリ使用時の連続ショートカット操作において、二重反応（1 回の押下で 2 候補進む等）の発生率が 0% であり、ショートカット記録中の誤起動も 0 件である。
- **SC-005**: 既存の自動テストおよび本仕様で追加する判定ロジック・状態遷移のテストがすべて 100% 合格する。

## Assumptions

- 既定のショートカット（`Option + Tab` / `Option + Space`）や一般的な任意ショートカット（`Control` / `Option` 等と通常キーの組み合わせ）は OS の標準機能に奪われず代替経路で捕捉可能である一方、`Command + Tab` のように macOS 自体が最優先予約しているキー組み合わせは、セキュア入力保護下において OS の仕様上システム標準のスイッチャー等が優先される（通常時のみ Wintch が上書き動作する）。
- セキュア入力保護中に通常スイッチャーを一時アクティブ化方式で起動した場合、`Esc` 等でキャンセルした際に元のブラウザに戻った直後は、ブラウザの仕様上パスワード自動入力ポップアップ等が一旦閉じている場合があるが、元のアプリケーションへのフォーカス復元をもって正常動作とみなす。
- 検索ランチャーは従来仕様から起動時に一時アクティブ化を行って直前アプリへフォーカスを戻す設計であるため、セキュア入力保護中も同じフォーカス復元フローと整合させて扱う。
