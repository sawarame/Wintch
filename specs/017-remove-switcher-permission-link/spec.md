# 機能仕様書: 画面収録権限未許可時のスイッチャー内設定リンク削除

**Feature Branch**: `017-remove-switcher-permission-link`

**Created**: 2026-11-17

**Status**: Draft

**Related Issue**: [#23](https://github.com/sawarame/Wintch/issues/23)

**Input**: User description: "画面収録権限がないときにスイッチャーに権限へのリンクが表示されているが、このリンクをクリックすることは不可能なので（Option+tabで両手が塞がっている）、リンクをなくす"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 画面収録権限未許可のキャプチャ表示型スイッチャーからクリック不能な設定リンクをなくす (Priority: P1)

ユーザーは、通常スイッチャー（修飾キー保持式）の表示形式を「キャプチャ表示型」に設定し、かつ画面収録権限が未許可の状態で `Option + Tab` 等のショートカットを押下した際、キーボード操作で両手が塞がっている状況ではクリックできない権限設定リンクがスイッチャーパネル上に表示されないことを期待する。同時に、なぜウィンドウサムネイルではなくアイコンプレースホルダーが表示されているのかを把握できる案内テキストは維持され、通常通りウィンドウ切り替えを完結できることを期待する。

**Why this priority**: Issue #23 で指摘されている通り、ホールド式の通常スイッチャー表示中は修飾キーを押し続ける必要があり、パネル上のリンクをクリックしようとして手を離したりクリック操作を試みたりしても実用上クリック不可能なため、操作できない UI 要素を取り除くことが最優先となる。

**Independent Test**: 画面収録権限が未許可の状態で「キャプチャ表示型」の通常スイッチャーを起動したとき、パネル上部に「画面収録権限が未許可のためプレースホルダーを表示しています」といった案内表示のみが非インタラクティブに表示され、「設定を開く」等の設定リンクが表示されないこと、ならびにウィンドウ選択・切り替え・キャンセル操作が従来通り完了できることで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** 通常スイッチャーの表示形式が「キャプチャ表示型」に設定されており、画面収録権限が未許可である状態, **When** ユーザーが通常スイッチャーのショートカット（修飾キー保持＋トリガーキー）を押下してスイッチャーパネルを表示する, **Then** パネル上部には画面収録権限が未許可である旨の案内文のみが表示され、クリック可能な権限設定へのリンク（「設定を開く」等）は一切表示されない。
2. **Given** 画面収録権限が未許可の状態でキャプチャ表示型スイッチャーが表示されている状態, **When** ユーザーがそのままトリガーキーや矢印キーでカードを選択し修飾キーを解放する（または `Esc` を押す）, **Then** プレースホルダーカードを用いて通常通り対象ウィンドウへの切り替え（またはキャンセル）が完結する。
3. **Given** 画面収録権限が利用中に取り消された・失効した状態, **When** キャプチャ表示型スイッチャーが非許可状態へフォールバックする, **Then** 設定リンクを含まない案内文のみが表示され、各ウィンドウはアイコンプレースホルダーで表示される。

---

### User Story 2 - 設定画面からの画面収録権限設定導線は維持する (Priority: P2)

ユーザーは、スイッチャーパネル上のクリック不能なリンクが削除された後でも、メニューバーから開ける設定画面上では従来通りマウスクリック可能な状態で画面収録権限の確認・リクエスト・システム設定を開く操作を行えることを期待する。

**Why this priority**: スイッチャー中のホールド操作とは異なり、設定画面は通常の独立ウィンドウとして表示されるため、そこからシステム設定へ遷移できる導線を維持することが権限付与フローの完結に不可欠であるため。

**Independent Test**: メニューバーから設定画面を開き、「キャプチャ表示型」を選択した際に画面収録権限が未許可であれば、「権限をリクエスト」「システム設定を開く」「再確認」の各操作導線が設定画面上に表示され正常に機能することで検証できる。

**Acceptance Scenarios**:

1. **Given** 通常スイッチャーの表示形式が「キャプチャ表示型」で画面収録権限が未許可の状態, **When** ユーザーがメニューバーから設定画面を開く, **Then** 設定画面内の権限案内およびシステム権限欄からシステム設定の画面収録ペインを開く操作が引き続き利用できる。

---

### Edge Cases

- **ウィンドウ件数が少ない場合（1 件など）のパネル幅**: リンク削除後も案内バナーのテキストが途切れたり不自然に圧縮されたりしないよう、バナー表示時のパネル最小幅および 1 行／折り返し余白が適切に保たれること。
- **リスト型スイッチャーおよび検索ランチャーへの影響**: リスト型および検索ランチャーでは従来通り画面収録権限の確認・案内自体を行わないため、本変更による影響を受けないこと。
- **画面収録権限が許可済みの場合**: 許可済み時は案内バナー自体が表示されない従来の挙動を維持すること。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、画面収録権限が未許可の状態で「キャプチャ表示型」通常スイッチャーを表示する際、パネル上にクリック可能な設定リンク（システム設定の画面収録ペインを開くリンクボタン等）を表示してはならない（MUST NOT）。
- **FR-002**: システムは、画面収録権限が未許可の状態で「キャプチャ表示型」通常スイッチャーを表示する際、プレースホルダー表示になっている理由を伝える非インタラクティブな案内表示（警告アイコンと説明テキスト）を維持しなければならない（MUST）。
- **FR-003**: システムは、案内表示から設定リンクを削除した状態でも、案内テキストの見切れやパネルレイアウトの崩れを起こしてはならず、各ウィンドウのプレースホルダーカード表示および選択・切り替え・キャンセル・ウィンドウ終了操作を従来通り維持しなければならない（MUST）。
- **FR-004**: システムは、通常の設定画面における画面収録権限の案内・リクエスト・システム設定を開く操作導線には一切の影響を与えず、従来通り維持しなければならない（MUST）。
- **FR-005**: システムは、スイッチャーパネル上の設定リンク廃止に伴い不要となるスイッチャー経由の設定画面起動処理を整理し、コードベースに不要な導線や死んだコードを残さないようにしなければならない（SHOULD）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 画面収録権限が未許可の状態で「キャプチャ表示型」通常スイッチャーを起動した際、スイッチャーパネル上に表示される画面収録権限設定へのクリック可能なリンク数は 0 個である。
- **SC-002**: 画面収録権限が未許可の状態で「キャプチャ表示型」通常スイッチャーを起動した際、権限未許可の案内テキストおよびプレースホルダーカードが表示され、100% のケースでキーボード操作によるウィンドウ切り替え・キャンセルが正常に完了する。
- **SC-003**: 設定画面における画面収録権限の状態表示および「システム設定を開く」操作は変更前と変わらず 100% 機能する。
- **SC-004**: 変更後、既存の自動テスト全件がパスし、プロジェクトのビルドがエラーなく成功する。

## Assumptions

- 通常スイッチャーは修飾キーを押し続ける操作モデル（ホールド式）であるため、スイッチャー表示中にマウスでパネル内リンクをクリックする導線は設けない。画面収録権限の付与やシステム設定の開放は、メニューバーから開く設定画面から行う運用とする。
- スイッチャー上部の案内バナー自体は「なぜキャプチャではなくアイコンのプレースホルダーが表示されているのか」をユーザーに知らせる上で有益であるため、リンクのみを削除して非インタラクティブな案内表示を残す（既存仕様 `007-window-capture-switcher` の FR-008 における「スイッチャーパネル上にシステム設定を開く導線を表示する」部分を本仕様で廃止・上書きする）。
