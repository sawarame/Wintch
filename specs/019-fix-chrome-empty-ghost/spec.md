# 機能仕様書: Chrome等のタブ全閉によるウィンドウ閉鎖後に空の表示が残る問題の修正

**Feature Branch**: `019-fix-chrome-empty-ghost`

**Created**: 2026-11-18

**Status**: Draft

**Related Issue**: [#27](https://github.com/sawarame/Wintch/issues/27)

**Input**: User description: "chromeのタブをすべて閉じてウィンドウを閉じると（アプリは終了してない）、スイッチャーに空の表示が残ったままになり、選択しても何も起こらない状態になってしまう。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - タブをすべて閉じてウィンドウを閉じた待機中ブラウザの空表示を残さない (Priority: P1)

ユーザーは、Google Chrome などのブラウザで開いているタブをすべて閉じてウィンドウが閉じられた（ただしアプリケーション自体は終了せず常駐待機している）状態で通常スイッチャーまたは検索ランチャーを起動したとき、実体のない空のウィンドウ表示（真っ白なプレビューや「(タイトルなし)」項目）が残らず、現在実際に開かれているウィンドウのみが一覧に表示されることを期待する。

**Why this priority**: すでに閉じたはずのウィンドウが空の表示としてスイッチャーに残り続け、選択しても何も起こらない状態になることは、ウィンドウ切り替えの信頼性を大きく損なう最優先の不具合であるため。

**Independent Test**: Google Chrome で開いているすべてのタブおよびウィンドウを閉じた状態（アプリは未終了）で通常スイッチャー（リスト型・キャプチャ表示型）および検索ランチャーを起動し、Chrome の空ウィンドウ項目が 1 件も表示されないことで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** Google Chrome のすべてのタブを閉じて開いているウィンドウが 0 枚になった状態（アプリ自体は終了していない）, **When** ユーザーが通常スイッチャー（リスト型またはキャプチャ表示型）を起動する, **Then** Chrome の空表示（真っ白なプレビューや「Google Chrome (タイトルなし)」）は一覧に一切表示されない。
2. **Given** Google Chrome のすべてのタブを閉じて開いているウィンドウが 0 枚になった状態（アプリ自体は終了していない）, **When** ユーザーが検索ランチャーを起動する, **Then** ウィンドウ一覧には Chrome の空ウィンドウは表示されず、検索時にはアプリ起動候補として適切に扱われる。
3. **Given** Google Chrome の最後のタブを閉じてウィンドウが閉じた直後（2 秒以内を含む即時操作時）, **When** ユーザーが即座に通常スイッチャーまたは検索ランチャーを起動する, **Then** 閉じる前の古いウィンドウ名や空の表示が残留することなく、即座に一覧から除外される。

---

### User Story 2 - 複数ウィンドウのうち1枚のタブをすべて閉じた際に閉じた側の空表示を残さない (Priority: P1)

ユーザーは、Google Chrome で複数のウィンドウを開いている状態から、そのうち 1 枚のウィンドウのタブをすべて閉じてウィンドウを閉じたとき、閉じたウィンドウが「(タイトルなし)」や真っ白な空表示に化けて残ることなく、残っている実ウィンドウのみが一覧に表示され、正しく切り替えられることを期待する。

**Why this priority**: 複数ウィンドウ併用時に閉じたはずのウィンドウが空のゴースト項目として残り続けると、残存する本物のウィンドウとの区別や選択操作を妨げるため。

**Independent Test**: Google Chrome で 2 枚のウィンドウを開き、片方のウィンドウのタブをすべて閉じて閉じた後に通常スイッチャーおよび検索ランチャーを起動し、残っている 1 枚の実ウィンドウのみが表示され、閉じたウィンドウの空表示が残らないことで検証できる。

**Acceptance Scenarios**:

1. **Given** Google Chrome で複数のウィンドウが開かれている状態, **When** そのうち 1 枚のウィンドウのタブをすべて閉じてウィンドウを閉じた後にスイッチャーまたはランチャーを起動する, **Then** 閉じたウィンドウは一覧から消え、現在も開いている実ウィンドウのみが正確な枚数分だけ表示される。
2. **Given** 複数ウィンドウのうち 1 枚を閉じて実ウィンドウが 1 枚だけ残っている状態, **When** スイッチャーまたはランチャー上でその残っているウィンドウに対して閉じる操作を実行する, **Then** ゴースト項目に阻害されることなく同アプリの最後の 1 枚と正しく判定され、アプリ終了操作が機能する。

---

### User Story 3 - 別スペースや「新しいタブ」を含む実在ウィンドウの正確なタイトル表示と切り替えを維持する (Priority: P2)

ユーザーは、不要な空表示や閉鎖済みゴーストが除外される一方で、別の操作スペースやフルスクリーンで実際に開いている Chrome ウィンドウ（「新しいタブ」のみを開いているウィンドウや Web アプリウィンドウを含む）については、誤って除外されたり「(タイトルなし)」になったりせず、正しいウィンドウタイトルで一覧に表示され、選択時に確実に切り替えられることを期待する。

**Why this priority**: 閉鎖済みウィンドウの除外に伴って、実際に開かれている別スペースのウィンドウや「新しいタブ」ウィンドウが消えたりタイトルを失ったりする退行を防ぐ必要があるため。

**Independent Test**: 別の操作スペース（フルスクリーンを含む）に「新しいタブ」や通常の Web ページを開いた Chrome ウィンドウを配置した状態で通常スイッチャーおよび検索ランチャーを起動し、タイトルが「(タイトルなし)」にならず正しく表示され、選択してそのウィンドウへ遷移できることで検証できる。

**Acceptance Scenarios**:

1. **Given** 別の操作スペース（フルスクリーンを含む）で「新しいタブ」または通常のページを開いている Chrome ウィンドウが存在する状態, **When** ユーザーが通常スイッチャーまたは検索ランチャーを起動する, **Then** そのウィンドウは除外されることなく、「(タイトルなし)」ではなく実際のウィンドウタイトルで一覧に表示される。
2. **Given** 別の操作スペースに実在する Chrome ウィンドウが一覧に表示されている状態, **When** ユーザーがその項目を選択して確定する, **Then** 対象の操作スペースおよびウィンドウへ確実に切り替わる。

---

### Edge Cases

- **最後のタブを閉じてから即座（数ミリ秒〜2秒以内）にスイッチャーを起動した場合**: ウィンドウ一覧やメニュー情報の古い一時記憶が残っていても、閉じられたウィンドウや裏方の空ウィンドウに古いタイトルが結びついて延命されないこと。
- **フルスクリーン空間でタブをすべて閉じてウィンドウが閉じた場合**: フルスクリーン遷移や終了に伴ってアプリ内部に残存する大画面サイズの真っ白な裏方ウィンドウや閉鎖済みウィンドウ参照が、実ウィンドウとして誤表示されないこと。
- **過去に捕捉されたウィンドウ参照が閉鎖後にシステム上のウィンドウ実体を失った場合**: すでに実体が消滅した古いウィンドウ参照が、同じアプリの裏方補助ウィンドウへ乗り換えて「(タイトルなし)」として生き残らないこと。
- **別スペースのウィンドウで一時的に標準タイトル情報が空を返す場合**: ウィンドウ一覧メニューやウィンドウ名メタデータに有効なタイトルが存在する実ウィンドウであれば、適切にタイトルが補完されて「(タイトルなし)」にならないこと。
- **ユーザーが実際に開いたタイトル未設定の他アプリの通常ウィンドウ**: テキストエディタ等で実際に開かれている無題ウィンドウは誤って除外されないこと。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、Google Chrome のすべてのタブおよびウィンドウが閉じられ、アプリケーション自体は終了していない待機状態において、アプリ内部で画面外に保持される無名の補助・空き殻ウィンドウをスイッチャーおよび検索ランチャーの一覧から除外しなければならない（MUST）。
- **FR-002**: システムは、過去に捕捉・記憶していたウィンドウが閉じられてシステム上の対応ウィンドウ実体が消滅した場合、その古いウィンドウ参照を確実に破棄し、同アプリの別補助ウィンドウへ付け替えて残留させてはならない（MUST NOT）。
- **FR-003**: システムは、ウィンドウが破棄・閉鎖された際、該当アプリケーションのウィンドウ一覧メニューに関する一時記憶を即座に無効化し、閉じる前の古いウィンドウタイトルが閉鎖後の裏方ウィンドウへ割り当てられないようにしなければならない（MUST）。
- **FR-004**: システムは、別操作スペースの未捕捉ウィンドウを補完する対象アプリだけでなく、捕捉済みウィンドウの中にタイトルが空の候補が存在するアプリに対しても、利用可能なウィンドウメニュー情報やウィンドウ名メタデータからのタイトル補完を実行しなければならない（MUST）。
- **FR-005**: システムは、別の操作スペースに存在するウィンドウ（メイン／フォーカス対象として認識されているが現在の操作スペース上には表示されていないウィンドウを含む）が選択された際、現在の操作スペース上にあると誤認せず、対象ウィンドウへの遷移処理を確実に実行しなければならない（MUST）。
- **FR-006**: システムは、通常スイッチャー（リスト型・キャプチャ表示型）および検索ランチャーの双方で同一のウィンドウ除外・補完結果を共有し、開いているウィンドウ数と表示項目数の整合性を維持しなければならない（MUST）。

### Key Entities

- **画面外補助ウィンドウ（Offscreen Auxiliary / Shell Window）**: ブラウザ等がウィンドウ閉鎖後やバックグラウンド動作中に画面外で保持する描画実体のない内部ウィンドウ。ユーザーの切り替え対象ではないため除外される。
- **記憶済みウィンドウ参照（Cached Window Reference）**: 操作スペースを跨いでウィンドウを追跡するための管理情報。対応するウィンドウ実体が消滅した時点で破棄される。
- **ウィンドウメニュー項目（Window Menu Entry）**: アプリケーションの「ウィンドウ」メニューに表示される現在開かれている実ウィンドウの一覧情報。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Google Chrome のすべてのタブを閉じてウィンドウを閉じた状態（アプリ未終了）において、通常スイッチャー（リスト型・キャプチャ表示型）および検索ランチャーに表示される Chrome の空ウィンドウ項目数が 100% のケースで 0 件になる（閉鎖直後の即時起動時を含む）。
- **SC-002**: Google Chrome で複数ウィンドウを開き、一部のウィンドウのタブをすべて閉じて閉じた場合において、一覧に表示される Chrome のウィンドウ数が現在開いている実ウィンドウ数と 100% 一致する。
- **SC-003**: 別操作スペースやフルスクリーンで開かれている実在の Chrome ウィンドウ（「新しいタブ」を含む）が 100% 正しいタイトルで一覧に表示され、選択時に目的のウィンドウへ切り替えられる。
- **SC-004**: 既存の全自動テストおよび本仕様の再現条件を検証する新規テストがすべて 100% 合格し、スイッチャー表示の体感遅延が発生しない。

## Assumptions

- リスト型スイッチャーおよび検索ランチャーにおいて画面収録権限を一切要求・使用しない原則、および非公開機能を使用しない原則を完全に維持する。
- Google Chrome のようにアプリケーション終了を伴わずに全ウィンドウを閉じることができ、かつ「ウィンドウ」メニューに開いている実ウィンドウ一覧を持つブラウザ・アプリの特性を既存の宣言的プロファイルおよびメニュー照合の仕組みに沿って扱う。
- ユーザーが実際に開いている他アプリの正当な無題ウィンドウ（実体を持つウィンドウ）は引き続き表示対象として維持する。
