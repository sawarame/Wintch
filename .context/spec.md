# Wintch 仕様書

## 1. 基本コンセプトと動作環境

**Wintch**（Window + Switch）は、macOS 14.0 (Sonoma) 以降向けに設計された、軽量・最小権限の**ウィンドウ単位スイッチャー＆ランチャー**アプリケーションである。

macOS 標準の `Command + Tab` がアプリケーション単位の切り替えであるのに対し、Wintch は同一アプリケーションの複数ウィンドウを含めて操作スペース（仮想デスクトップ）やマルチディスプレイを横断しながら、キーボード操作中心で目的のウィンドウへ素早く切り替える体験を提供する。また、検索ランチャーを通じてインストール済みアプリケーションの検索・起動にも対応する。

- **対象 OS**: macOS 14.0 (Sonoma) 以降
- **対応言語**: 日本語（`ja`）、英語（`en`）、中国語（簡体字、`zh-Hans`）、中国語（繁体字、`zh-Hant`）、韓国語（`ko`）の 5 言語（デフォルトはシステム設定追従・非対応システム言語時は英語へフォールバック）
- **必須権限**: macOS「アクセシビリティ」権限
- **任意権限（オプトイン）**: macOS「画面収録」権限（通常スイッチャーまたは検索ランチャーで「キャプチャ表示型」を選択した場合のみ使用）
- **常駐形態**: Dock アイコンを表示しないメニューバー常駐アプリ（`LSUIElement = true` / `NSApplication.ActivationPolicy.accessory`）

---

## 2. 主要機能

### A. 通常ウィンドウスイッチャー（ホールド式・デフォルト `Option + Tab`）

修飾キーを押し続けている間だけフローティングパネルを表示し、離した瞬間に選択中のウィンドウへ切り替えるモード。一覧視認性を高めるため、通常はアクティブディスプレイ有効領域の上端から 14%（最小 `32pt`）の位置にパネル上端を固定する上寄せ配置とし、**グルーピング OFF のキャプチャ表示型のみ**従来通りディスプレイ中央に配置する。

- **起動と候補一覧**:
  - 操作可能な通常ウィンドウが 1 件以上存在する場合に起動する（有効ウィンドウが 0 件の場合は空パネルを表示せず無視する）。
  - 現在の操作スペースだけでなく、別の操作スペース・別ディスプレイ・フルスクリーン空間・最小化ウィンドウを含む有効な通常ウィンドウを収集する。
  - 並び順は**直近アクティブ順（MRU: Most Recently Used）**を最優先とし、未履歴の初期起動時および同順位時はシステムの Z オーダー順に従う。
  - **アプリごとのグルーピング（デフォルト ON）**: 設定画面またはメニューバーから ON/OFF を切り替え可能。ON 時は同一アプリ（非空の `bundleIdentifier` 優先、未取得時は `pid`）のウィンドウを初出順（各アプリ内最上位ウィンドウの MRU 順、同順位時は Z オーダー順）でまとめて視覚的にセクション表示し、各グループ内は元の MRU 順を維持する。OFF 時は従来どおり全ウィンドウをフラットに表示する。
  - 初期選択カーソルは、候補が 2 件以上ある場合は**直前まで使っていたウィンドウ（MRU 2 番目）**（グルーピング OFF 時はインデックス `1`、グルーピング ON 時は MRU 2 番目ウィンドウが配置された表示インデックス）、1 件のみの場合は **1 番目（インデックス `0`）** とする。
- **操作方法**:
  - 修飾キー（デフォルト `Option`）を保持したまま、トリガーキー（デフォルト `Tab`）で「次へ」、`Shift + トリガーキー` で「前へ」と循環移動する（グルーピング ON 時もアプリ見出しをスキップして全ウィンドウを連続循環移動する）。
  - 表示中は補助操作として上下矢印キー（グルーピング OFF のアイコン型・キャプチャ表示型グリッドでは上下左右すべての矢印キー、リスト表示およびグルーピング ON 時の縦型リストでは前後循環移動）、および行／タイル／カードクリックによる選択・確定もサポートする。
  - 保持していた修飾キーを離した瞬間にパネルを閉じ、選択中のウィンドウ（別操作スペースを含む）を最前面にアクティブ化する。
  - `Esc` キー押下またはパネル外クリックによるフォーカス喪失時は、切り替えを実行せず元のアクティブウィンドウのままパネルを閉じる。
- **3 つの表示形式（`SwitcherDisplayStyle`）**:
  - **リスト型（デフォルト）**: 横幅 `520pt` の半透明角丸パネルの縦型リストを上寄せ配置で表示する。グルーピング OFF 時は「アプリアイコン」「アプリケーション名」「ウィンドウタイトル」のフラット行、グルーピング ON 時は全アプリに非選択のアプリ見出し行（アプリアイコン＋アプリ名太字、2 グループ目以降は区切り線）とインデントされたウィンドウタイトル行を表示する。画面収録権限は一切使用しない。最大スクロール高さはアクティブディスプレイの有効高さから上端オフセット（14%、最小 `32pt`）と下端余白（10%、最小 `24pt`）を除いた動的高さ（最小 `220pt`）とし、これを超える場合は縦スクロール可能となりキーボードによる選択移動および初期表示時に合わせて自動スクロール追従する。
  - **アイコン型**: グルーピング OFF 時は macOS 標準の `Command + Tab` 風の角丸フローティングパネルを上寄せ配置で表示し、「1 ウィンドウ = 1 タイル（`112 × 120pt`）」として上部中央の大きなアプリアイコン（`56 × 56pt`）と下部のアプリ名（太字）・ウィンドウタイトル（補足色）を単一グリッドで並べて表示する（アクティブディスプレイ幅の `85%`、最大列数 `8` 列、タイル間隔 `10pt`、外側余白 `14pt`、最大スクロール高さは上寄せ配置時のパネル最大高さに連動）。グルーピング ON 時は横幅 `520pt`・ディスプレイ有効高さ連動の最大高さをもつ縦型リスト形式とし、アプリ見出し行の下にインデントされた背景・枠線なしの大きなアプリアイコン（`46 × 46pt`、領域 `50 × 50pt`）＋右ウィンドウタイトル（最大 2 行）を並べる。グルーピング ON/OFF いずれでも画面収録権限は一切使用しない。
  - **キャプチャ表示型（オプトイン）**: 設定画面またはメニューバーで明示的に選択した場合のみ有効。グルーピング OFF 時は従来通りディスプレイ中央に配置し、Windows の `Alt + Tab` のように各ウィンドウのサムネイルプレビュー・アプリアイコン・アプリ名・ウィンドウタイトルを並べたカードグリッドを表示する。グルーピング ON 時は検索ランチャーのキャプチャ表示型（グルーピング ON）と同一の上寄せ縦型リスト形式（横幅 `520pt`・ディスプレイ有効高さ連動の最大高さ、アプリ見出し行＋インデントされた左 `80 × 50pt` サムネイル枠＋右ウィンドウタイトル、画面収録権限未許可時はパネル上部に非インタラクティブな警告バナーを表示）で表示する（詳細は「[D. キャプチャ表示型スイッチャーとオプトイン画面収録権限](#d-キャプチャ表示型スイッチャーとオプトイン画面収録権限)」を参照）。
- **モード優先順位**: 通常スイッチャー表示中に検索ランチャーの起動ショートカットが押されても無視し、通常スイッチャーモードを維持する。

### B. 検索ランチャーモード（トグル式・デフォルト `Option + Space`）

検索入力欄付きパネルをトグル表示し、開いているウィンドウのファジー検索および未起動・未一致アプリケーションの新規起動を行うモード。

- **起動と初期状態**:
  - 起動ショートカット押下によりトグル式で開き、修飾キーを離してもパネルが開いたまま維持され、検索入力欄に自動的にフォーカスが当たる。
  - **ウィンドウ 0 件時の起動対応**: 有効な通常ウィンドウが 0 件の環境であってもアプリ起動ランチャーとして起動でき、未入力時は案内メッセージ「開いているウィンドウがありません（アプリ名を入力して起動）」を表示する。
  - 有効な通常ウィンドウが 1 件以上ある場合、未入力状態では通常ウィンドウ全件を直近アクティブ順（MRU）で表示し、常に **1 番目（先頭）** を初期選択する。未入力状態ではアプリ起動候補は表示しない。
  - **2 つの表示形式（`LauncherDisplayStyle`）とアプリグルーピング（デフォルト ON）**:
    - 通常スイッチャーの表示形式（`normalDisplayStyle`）およびグルーピング設定とは独立して設定画面またはメニューバーから選択可能。いずれの形式でもディスプレイ有効領域の上端から 14%（最小 `32pt`）の上寄せ配置と縦型リスト構造（横幅 `520pt`、上端固定リサイズ、ディスプレイ有効高さから上端オフセット・下端余白 10% および上部ヘッダ分を差し引いた動的スクロール最大高さ）を維持する。
    - **リスト型（デフォルト）**: グルーピング OFF 時は「アプリアイコン」「アプリケーション名」「ウィンドウタイトル」のフラット縦型リスト、グルーピング ON 時は全アプリにアプリ見出し行（アプリアイコン＋アプリ名太字、検索時は一致ハイライト付き）とインデントされたウィンドウタイトル行を表示する。画面収録権限は一切使用しない。
    - **キャプチャ表示型（オプトイン）**: 各ウィンドウ候補行の左側に小型キャプチャサムネイル（固定枠 `80 × 50pt`、角丸・枠線付き、`aspectRatio(.fit)`、未取得・権限未許可・最小化時等はアプリアイコンまたは `macwindow` のプレースホルダー）を配置し、グルーピング OFF 時は右側にアプリアイコン・アプリ名（太字）・ウィンドウタイトル、グルーピング ON 時はアプリ見出し行の下にインデントして右側ウィンドウタイトル（一致文字ハイライト維持）を表示する。下部のアプリ起動候補行（`AppLaunchRowView`）は従来どおりのデザインを維持する。画面収録権限が未許可（または取得中失効）の場合は、検索入力ヘッダ直下に非インタラクティブな警告バナー（「画面収録権限が未許可のためプレースホルダーを表示しています」）を表示し、プレースホルダーのまま検索・切り替え・アプリ起動を継続する。
- **ファジー検索・ハイライト・アプリ起動候補併用**:
  - 1 文字以上の有効キーワード（空白のみを除く）が入力されると、ウィンドウ候補および起動可能なインストール済みアプリケーションの双方に対してスペース区切り AND 条件・大文字小文字非区別（アプリ名は発音区別符号・文字幅も非区別）のファジー検索を実行する。
  - 一致した文字範囲は各行（グルーピング ON 時は見出しのアプリ名および各行のウィンドウタイトル）で太字・ハイライト表示される（タイトルが空のウィンドウの表示補助テキスト `"(タイトルなし)"` 自体は検索・ハイライト対象外）。
  - **2 セクション統合表示と重複除外**:
    - 上部に一致スコア順（同点時は MRU 順。グルーピング ON 時は各アプリ内の最高スコア降順・同点 MRU 順でアプリごとにグルーピング）のウィンドウ候補を表示する。
    - 下部に区切りとセクション見出し（ウィンドウ候補あり時は「アプリを起動」、ウィンドウ 1 件以上環境でウィンドウ候補のみ 0 件のときは「一致するウィンドウがないため、アプリを起動」）を設け、アプリ起動候補を表示する。
    - 上部のウィンドウ検索結果にすでに出現しているアプリケーション（バンドル ID / バンドル URL / 大文字小文字非区別のアプリ名で照合）は、重複表示を防ぐため下のアプリ起動候補から除外する。
    - アプリ起動候補は表示名および英語等の別名（表示名と異なる場合のみ併記・ハイライト）を検索対象とし、一致スコア降順・同点時は表示名の自然昇順で並べる。
  - 候補更新時は選択カーソルを全体先頭（インデックス `0`）へ自動リセットする。
- **空状態（`LauncherEmptyState`）**:
  - ウィンドウ 0 件＋未入力: 「開いているウィンドウがありません（アプリ名を入力して起動）」
  - ウィンドウ 0 件＋検索不一致: 「一致するアプリがありません」
  - ウィンドウ 1 件以上＋検索不一致: 「一致するウィンドウやアプリがありません」
  - いずれの空状態でもパネルを閉じずに維持し、`Enter` キーや上下移動を安全に無視する。
- **インストール済みアプリ収集（`InstalledAppService`）**:
  - `/Applications`、`/System/Applications`、`~/Applications`、`/System/Library/CoreServices/Applications`（最大階層深さ `3`）および `/System/Library/CoreServices/Finder.app` から起動可能な `.app` を非同期バックグラウンド走査し、メモリにキャッシュする。
  - シンボリックリンクの実体解決による重複排除、非対話バックグラウンドヘルパーアプリや起動不能バンドル・本アプリ自身（`Bundle.main.bundleIdentifier`）の除外を行う。
- **キーボード操作・IME 保護・レイアウト安定性**:
  - `↑` / `↓` 矢印キー、`Ctrl + N` / `Ctrl + P`、および**通常スイッチャーの順方向・逆方向ショートカット**で、ウィンドウ候補セクションとアプリ起動候補セクションを単一の連続リストとして貫通・循環移動できる（通常スイッチャーショートカット使用時に修飾キーを離してもランチャーは確定・閉鎖しない）。
  - 選択移動、検索クエリ変更による先頭復帰、および再表示時に、選択行が可視領域に収まるよう自動スクロール追従する。
  - 日本語 IME による未確定入力（`hasMarkedText`）または変換候補選択中の `Enter`・`Esc`・`↑`・`↓` は、ランチャー操作よりも IME の確定・キャンセル・候補選択を優先する。
  - `Enter` または行クリックで確定し、ウィンドウ候補なら対象ウィンドウのアクティブ化、アプリ起動候補なら `NSWorkspace` による起動・前面化を行ってパネルを閉じる。
  - `Esc`、ランチャーショートカットの再押下、またはパネル外クリックで実行せずキャンセル終了する。
  - 候補件数の増減に際しては、パネル上端座標（検索入力欄の位置）を固定したままリスト領域の下端のみを伸縮させる。

### C. 選択中ウィンドウ／アプリ終了操作（スイッチャー修飾キー + `Q`）

通常スイッチャー（リスト型・アイコン型・キャプチャ表示型）および検索ランチャーの双方において、現在設定されている通常スイッチャーの必須修飾キー + `Q`（デフォルト `Option + Q`）で選択中のウィンドウを閉じる機能。

- **単一ウィンドウクローズ vs アプリケーション通常終了**:
  - 選択中ウィンドウの所属アプリケーションについて、**絞り込み前の有効ウィンドウ一覧全体**における有効ウィンドウ数を判定する。
  - **2 枚以上**ある場合: 選択中のウィンドウ 1 枚のみを閉じる（AX クローズ操作）。他ウィンドウおよびアプリ本体は終了しない。
  - **1 枚のみ**の場合: アプリケーション全体を通常終了（Quit 相当、強制終了ではない）し、閉じ残りの空プロセスが候補へ再出現するのを防ぐ。
- **別スペースの未捕捉ウィンドウ対応**:
  - 複数ウィンドウを持つアプリの選択中ウィンドウが別操作スペースにあり直接 AX 参照が未捕捉の場合、対象スペースへ一時的に切り替えてウィンドウを特定・クローズする。この際の一時的なフォーカス移動でパネルをキャンセル終了せず、処理完了後にパネル表示と操作状態を回復する。
- **安全配慮とイベント消費**:
  - 未保存変更の確認ダイアログ等を強制スキップ・強制終了せず、対象アプリの標準確認手順を尊重する（キャンセルされウィンドウが残存した場合は一覧から除外しない）。
  - 通常スイッチャーの修飾キーに `Command` を設定している場合でも、パネル表示中の `Command + Q` は本アプリ自身の誤終了を起こさず選択対象への終了操作として優先処理・消費する。
  - 検索ランチャーで修飾キーなしの単体 `Q`（および `Shift + Q`）を入力した場合は、検索文字 `"q"` / `"Q"` として検索欄へ通す。修飾キー + `Q` の場合は検索欄への文字・特殊文字（`œ` 等）の入力を遮断する。
  - 検索ランチャーでアプリ起動候補を選択中、または候補 0 件状態の場合は、誤操作を起こさずキー入力を消費して安全に無視する。
- **終了処理中のインジケーター表示**:
  - ウィンドウクローズまたはアプリケーション通常終了の実行を開始してから実際に完了（または確認ダイアログ等による残存判定・パネル閉鎖）するまでの間、対象ウィンドウ項目上に処理中アニメーション（円形スピナーインジケーター）を表示する。
  - 縦型リスト系表示（リスト型、グルーピング ON 時のアイコン型・キャプチャ表示型、検索ランチャー）では対象行の右端に小型スピナーを表示し、アイコングリッド（グルーピング OFF）ではアイコン領域中央に、キャプチャグリッド（グルーピング OFF）ではプレビュー領域中央に半透明の暗色オーバーレイとともにスピナーを表示する（行高さやタイル／カード寸法は変化させない）。
  - 処理中状態は選択インデックスではなく対象ウィンドウ項目 ID（`WindowEntry.id`）で追跡し、完了・失敗・パネル閉鎖時に速やかに解除する。
- **終了後のパネル維持と状態更新**:
  - クローズ／終了完了後も有効ウィンドウが 1 件以上残っている場合、パネルを閉じずに対象を除外し、同じインデックス（末尾削除時は新しい末尾）を選択状態にする。検索ランチャーでは検索キーワードを維持したままウィンドウ候補とアプリ起動候補を再評価する。
  - 最後の 1 件が閉じられて有効ウィンドウが 0 件になった場合、**通常スイッチャー**は自動的にパネルを閉じ、**検索ランチャー**はパネルを閉じずに維持してウィンドウ 0 件状態（未入力時は案内表示、検索語あり時はアプリ起動候補再評価結果）へ遷移する。

### D. キャプチャ表示型（通常スイッチャー／検索ランチャー）とオプトイン画面収録権限

通常スイッチャーまたは検索ランチャーの表示形式として「キャプチャ表示型」を選択した場合のビジュアル表示・キャッシュ仕様。

- **通常スイッチャーのグリッドレイアウト（`SwitcherGridLayout`）**:
  - カードサイズ固定 `216 × 164pt`、カード間隔 `10pt`、外側余白 `14pt`。
  - アクティブディスプレイ幅の `85%`（最大列数 `5` 列）に収まる列数で自動折り返しし、最大スクロール高さ（画面高さの 72% を基準に `220pt`〜`560pt` の範囲）を超える場合は縦スクロールと選択カードへの自動追従を行う。
  - 上下左右の矢印キーでグリッド内を循環移動する（最終行の列数が不足する場合はその行の末尾に丸める）。
- **検索ランチャーのキャプチャ付きリストレイアウト（`SwitcherListView`）**:
  - 上寄せ配置・パネル横幅 `520pt`・縦型スクロールリスト（ディスプレイ有効高さおよび検索ヘッダ・権限バナー有無に応じた動的スクロール最大高さ）を維持し、各ウィンドウ候補行の左側に `80 × 50pt` のサムネイル枠、右側にアプリアイコン・アプリ名・ウィンドウタイトルを配置する。
- **ゼロレイテンシ表示と非同期キャッシュ管理（`WindowCaptureService`）**:
  - 通常スイッチャー・検索ランチャーいずれのキャプチャ表示型でも、パネル表示時は同期キャッシュ済みサムネイルまたはアプリアイコンのプレースホルダーで即座に表示を開始し、`ScreenCaptureKit` でバックグラウンド非同期取得して順次差し替える。
  - 画面表示中（`isOnScreen`）ウィンドウを優先し、最大同時実行数 `4`、1 ウィンドウあたりタイムアウト `1.5` 秒で取得する。
  - **メモリ限定 LRU キャッシュ**: 最大保持件数は `100` 件（メモリ内限定、ディスク保存・ログ出力・外部送信は厳禁）。通常スイッチャーと検索ランチャーで共有し、表示セッション評価時にすでに閉じられたウィンドウ分を自動整理し、MRU 上位ウィンドウが追い出されないよう順序を維持する。再取得が一時失敗しても既存の有効プレビューは消去しない。
  - 非同期取得完了時にパネル閉鎖・セッション変更・モード変更・ウィンドウ無効化が起きていた場合は結果を安全に破棄する。
  - 設定変更により通常スイッチャーと検索ランチャーの**双方とも非キャプチャ（「リスト型」／「アイコン型」）になった時点**で即座にキャッシュを全破棄し、以降は画面収録権限確認やキャプチャ処理を一切行わない（どちらか一方が引き続き「キャプチャ表示型」である間は共有キャッシュを維持する）。
- **権限未許可・取得不能時のフォールバック**:
  - 画面収録権限が未許可（または利用中に失効）の場合でもクラッシュせず、パネル上部（検索ランチャーでは検索入力ヘッダ直下）に非インタラクティブな警告バナー（「画面収録権限が未許可のためプレースホルダーを表示しています」、通常グリッド時の最小パネル幅 `360pt`）を表示し、各カード／行をアプリアイコンプレースホルダーで描画して通常通りウィンドウ切り替え・検索・アプリ起動を継続する。
  - パネル上に設定画面へのリンクボタンは配置せず、権限リクエスト・システム設定を開く操作は設定画面から行う。

### E. ウィンドウ収集・ノイズ除外・アプリ別ウィンドウプロファイル

「通常ウィンドウのみを過不足なく収集し、ゴーストや補助ウィンドウを除外し、別スペースの同名・複数ウィンドウも正確に切り替える」ための収集・フィルタリング・アクティブ化機構。

- **2 系統収集と照合（`WindowService` + `WindowMenuPairing`）**:
  - `CGWindowListCopyWindowInfo`（全操作スペース対象）とアクセシビリティ API（`AXUIElement` による現在スペース上のウィンドウ一覧）を組み合わせ、さらにアプリケーションの「ウィンドウ」メニュー項目（`WindowMenuPairing`：`Window` / `ウィンドウ` / `ウインドウ` / `窗口` / `視窗` / `윈도우` を認識）を用いて別スペースの未捕捉ウィンドウや空タイトルのタイトル補完・遷移を行う。
- **ノイズ・バックキングウィンドウ除外（`WindowFilter` + `AppWindowProfileRegistry`）**:
  - 許可ロール: `AXWindow`、サブロール: `AXStandardWindow` / `AXDialog`（および実質サイズ要件を満たす `AXFloatingWindow` / `AXSystemFloatingWindow`）、レイヤー: `0` または `3`。最小サイズ `50×50pt` 未満や透明・非実体ウィンドウ、横長ツールバーストリップ（アスペクト比 `> 6.0` かつ高さ `<= 300pt`）を除外する。
  - AX 未捕捉の画面外 `CGWindow` 補完候補に対しては、通常レイヤー（`layer == 0`）限定・最小サイズ `200×165pt` 要件を課し、未表示のフローティング補助窓およびアプリ横断の共通未表示バックキングウィンドウ（`x=0`, `500×500pt`）を除外する。
  - 同一矩形の重複候補・タブ統合時に、他スペースに存在するフルスクリーン／画面最大化級ウィンドウや通常サイズ別ウィンドウを誤って消去しない（`screenBounds` を用いた画面占有級判定および別スペース実体保持）。
  - ウィンドウ閉鎖時に古いキャッシュ参照を即座に破棄し、アプリのウィンドウメニューキャッシュも無効化して裏方ウィンドウへのタイトル誤割り当てを防止する。また、最新 AX スキャンに存在せず WindowServer 上に対応する生存 CGWindow も存在しないキャッシュ済みウィンドウ（`cgWindowID` 未照合のまま閉鎖されたウィンドウ等）は即座に破棄し、非フローティング AX ウィンドウがオフスクリーン補助レイヤー窓（`layer != 0`）へ誤照合されないよう制御する。
- **アプリ別プロファイル（`AppWindowProfileRegistry`）**:
  - `com.apple.systempreferences`（システム設定）: `singleRepresentativeOnly`（単一メインウィンドウ構成のため代表 1 件に制限）。
  - `com.apple.Notes`（メモ）: `requireAXOrMenuTitle` + 内部補助パネル `475×600pt` シグネチャ除外（AX またはメニュー確定タイトルを持つ実ウィンドウのみ表示し、非表示の「(タイトルなし)」ゴーストを防ぐ）。
  - `com.google.Chrome`（Google Chrome）: `requireAXOrMenuTitle`（全タブ・全ウィンドウ閉鎖後も画面外に残る無名空き殻ウィンドウや予測変換ポップアップ等を除外しつつ、「新しいタブ」等の実ウィンドウタイトルは補完して維持する）。
  - `com.figma.Desktop`（Figma）: `requireAXOrMenuTitle` + 内部補助パネル `400×600pt` シグネチャ除外（全ウィンドウ閉鎖後も画面外に残る未表示の `400×600pt` 補助ウィンドウや無名空き殻ウィンドウを除外しつつ、AX またはメニュー確定タイトルを持つ実ウィンドウを保持する）。
  - `com.google.GeminiMacOS`（Gemini）: `requireAXOrMenuTitle` + オフスクリーンキャッシュ生存再検証（ウィンドウ閉鎖後も `orderOut` 等で元サイズの無名 `CGWindow` を画面外に保持する挙動に対応し、AX 未捕捉の画面外無名 `CGWindow` および未確認オフスクリーンキャッシュを除外しつつ、開いている実ウィンドウや別スペースのメニュー確定ウィンドウを保持する）。
- **ウィンドウ切り替えとタイトル照合**:
  - タイトル自体に省略記号（`…` / `...`）が含まれる場合や長文が中央・末尾省略される場合でも、正規化・プレフィックス／サフィックス照合によりメニュー項目と正確に対応付ける。
  - 別スペースウィンドウの切り替え時は最新のメニュー項目参照を再取得して実行し、直後のアプリ前面化によって個別ウィンドウ選択を上書きしない順序でフォーカス確定する。

### F. セキュア入力対応とグローバルショートカット監視

- **通常監視（`CGEventTap`）**:
  - バックグラウンドの専用監視スレッドで `CGEventTap` を稼働させ、修飾キー・キー押下・解放を低遅延で検知・消費する。
  - タップのタイムアウト無効化に対してはバースト／長期ウィンドウ付きサーキットブレーカー（`TapTimeoutRecoveryTracker`）で自動再有効化を試行し、実際の権限剥奪時のみ監視を停止して権限誘導へフォールバックする。
- **セキュア入力保護中の代替起動経路（Carbon `RegisterEventHotKey`）**:
  - ブラウザのパスワード入力欄等にフォーカス中（OS のセキュア入力保護有効中、およびフォーカス解除後の残留中）は `CGEventTap` へイベントが届かないため、Carbon `RegisterEventHotKey` による代替ホットキー登録を併用する。
  - 重複発火防止トラッカーにより、`CGEventTap` と Carbon 代替経路の二重反応（1 回の押下で 2 候補進む等）を防止する。
  - セキュア入力保護下で通常スイッチャーまたは検索ランチャーが起動された場合は一時的に自アプリをアクティブ化して操作を受け付け、選択中に素早く修飾キーが離された場合でも解放ウォッチドッグにより取りこぼさず確定する。`Esc` 等でキャンセル終了した際は直前にフォーカスしていた元のアプリケーションへフォーカスを復元する。
  - 設定画面でショートカットを記録待機中（`isRecording`）は、すべての起動経路を一時サスペンドし誤起動を防ぐ。
  - 注記: `Command + Tab` 等 macOS 標準機能がセキュア入力下で最優先予約しているキーについては、OS 仕様上システム側が優先されるが、アプリはクラッシュせず通常時のみ上書き動作する。

### H. ビルド識別分離と SemVer 自動リリース

- **開発版と配布版の識別分離（`AppIdentity` + `build-app.sh`）**:
  - **リリースビルド（配布版）**: アプリ名・表示名 `Wintch`、Bundle Identifier `dev.wintch.Wintch`。
  - **デバッグビルド（ローカル開発版）**: アプリ名・表示名 `Wintch_dev`、Bundle Identifier `dev.wintch.Wintch.dev`。
  - 識別子を分離することで、同じ Mac 上で配布版とローカル開発版を共存させても macOS のアクセシビリティ権限登録や設定（`UserDefaults`）が干渉しない。
- **SemVer 一元管理と自動リリース（`VERSION` + `.github/workflows/release.yml`）**:
  - ルートの `VERSION` ファイル（現在 `0.2.6`）を唯一のバージョン情報源とし、`MAJOR.MINOR.PATCH` および任意プレリリース識別子（`-<id>`）を許容する。
  - ビルド時に `VERSION` の値と Git コミット数（取得不能時は `1`）がバンドル内 `Info.plist` へ反映される。
  - `main` への `VERSION` 更新プッシュまたは `v*` タグプッシュ・リリース公開時に、CI（`macos-15`）で `swift test` 実行後、Universal Binary（`arm64` + `x86_64`）ビルド、Developer ID 署名・Apple 公証・Staple、`ditto` による `Wintch-v<VERSION>.zip` 生成、および `scripts/build-dmg.sh`（`hdiutil`）による `Wintch.app` と `/Applications` シンボリックリンクを含む `Wintch-v<VERSION>.dmg` 生成・署名・Apple 公証・Staple を実施し、ZIP／DMG 双方を添付して GitHub Release を公開する。さらに安定版時のみ、`Wintch-v<VERSION>.zip` の SHA256 を用いて `sawarame/homebrew-tap` の Cask 自動更新を実行する。

### I. 自動バージョンアップ確認とアプリ内アップデート

外部ライブラリを使用せず、Apple 標準フレームワーク（`URLSession`, `CryptoKit`, `Security` 等）のみで GitHub Releases の最新安定版を確認し、ユーザー許可に基づき安全にアプリ内更新を行う機能。

- **バージョン確認（`AppUpdateService` + `SemanticVersion` + `UpdateCheckPolicy`）**:
  - `https://api.github.com/repos/sawarame/Wintch/releases/latest` から `draft == false` かつ `prerelease == false` の安定版リリースを取得し、`Wintch-v<VERSION>.zip` アセット URL・任意 `digest`（`sha256:...`）・`html_url`・リリースノートを抽出する。ダウンロード URL およびリダイレクト先は HTTPS かつ GitHub 許可ホストのみ許容する。
  - 起動時自動チェックは設定「バージョンアップを自動チェック」が ON（デフォルト OFF）かつ配布版（非開発版・有効 SemVer）の場合のみ `AppCoordinator.start()` で非同期実行する。OFF 時や開発版（`Wintch_dev` / `shortVersion == "dev"`）ではネットワーク通信を一切行わない。エラー時はサイレント終了（ログ出力のみ）とし、アクセシビリティ権限誘導画面の表示中は更新ダイアログ表示を保留して権限許可後に提示する。
  - スキップ済みバージョン（`skippedUpdateVersion`）と一致する場合は起動時自動チェックでは通知せず、さらに新しいバージョン公開時または設定画面「システム」＞「アプリ情報」の「アップデートを確認」からの手動確認時に提示する。
- **更新確認ダイアログ（`UpdatePromptView` + `UpdateViewModel`）**:
  - `WindowFrontPresenter` で最前面表示し、バージョン遷移・スクロール可能なリリースノート・「GitHub で変更内容を見る」リンク・進捗表示・エラー案内を表示する。
  - 「今すぐアップデート」「後で」「このバージョンをスキップ」を提供する。
- **検証・安全な差し替え・フォールバック**:
  - 一時ディレクトリへ ZIP をダウンロードし、アセットに `sha256:` ダイジェストがあれば `CryptoKit.SHA256` で検証、`ditto -x -k` で展開して `Wintch.app/Contents/Info.plist`（`CFBundleIdentifier == "dev.wintch.Wintch"` およびバージョン一致）、コード署名検証（Security フレームワークおよび `codesign --verify --deep --strict`）、および現在実行中アプリと同一の Developer ID Team ID 一致を検証する（失敗時は差し替えを中止しエラー表示）。
  - 差し替えは一時ディレクトリの分離ヘルパープロセスで「現アプリ終了待機 → 既存 `.app` を同一ボリューム上へ退避リネーム → 新 `.app` 配置（失敗時は自動ロールバック） → `open -n` で再起動 → 退避ファイル・一時作業ディレクトリ削除」の順に実行する。
  - 開発版（`Wintch_dev`）・App Translocation・未バンドル実行・読み取り専用ボリュームまたは書き込み権限不足環境では自動差し替えを行わず、理由説明と「GitHub Releases を開く」ボタンへ安全にフォールバックする。

## 3. 永続化データ仕様（`UserDefaults`）

`PreferencesStore` により以下のキーでアプリ設定を永続化する（開発版は Bundle ID が `dev.wintch.Wintch.dev` となるため保存領域が独立する）。

| キー名 | 型（保存形式） | デフォルト値 | 用途 |
| :--- | :--- | :--- | :--- |
| `dev.wintch.shortcutPreference` | JSON (`ShortcutPreference`) | `Option + Tab` (`keyCode: 48`, `.option`) | 通常スイッチャー起動ショートカット（旧 `{modifier, trigger}` 形式からのマイグレーションデコード対応） |
| `dev.wintch.launcherShortcutPreference` | JSON (`LauncherShortcutPreference`) | `Option + Space` (`keyCode: 49`, `.option`) | 検索ランチャー起動ショートカット |
| `dev.wintch.normalDisplayStyle` | `String` (`SwitcherDisplayStyle.rawValue`) | `"list"`（リスト型） | 通常スイッチャー表示形式（`"list"` / `"icon"` / `"capture"`） |
| `dev.wintch.launcherDisplayStyle` | `String` (`LauncherDisplayStyle.rawValue`) | `"list"`（リスト型） | 検索ランチャー表示形式（`"list"` / `"capture"`、不正値時は `.list` へフォールバック） |
| `dev.wintch.groupNormalSwitcherByApp` | `Bool` | `true`（ON） | 通常スイッチャーでウィンドウをアプリごとにグルーピングするかどうか（キー未保存時は `true`） |
| `dev.wintch.groupLauncherByApp` | `Bool` | `true`（ON） | 検索ランチャーでウィンドウをアプリごとにグルーピングするかどうか（キー未保存時は `true`） |
| `dev.wintch.appLanguage` | `String` (`AppLanguage.rawValue`) | `"system"`（システム設定に従う） | アプリの表示言語設定（`"system"` / `"ja"` / `"en"` / `"zh-Hans"` / `"zh-Hant"` / `"ko"`、未保存または不正値時は `"system"` へフォールバック） |
| `dev.wintch.autoCheckForUpdates` | `Bool` | `false`（OFF） | 起動時のバージョンアップ自動チェック有効／無効（オプトイン） |
| `dev.wintch.skippedUpdateVersion` | `String?` | `nil` | 「このバージョンをスキップ」で保存されたバージョン文字列（未設定・解除時はキー削除） |

※ ログイン時自動起動状態は `SMAppService.mainApp.status` により OS 側で管理される。  
※ キャプチャサムネイル画像およびアプリ一覧キャッシュはメモリ内のみに保持し、永続保存は一切行わない。
